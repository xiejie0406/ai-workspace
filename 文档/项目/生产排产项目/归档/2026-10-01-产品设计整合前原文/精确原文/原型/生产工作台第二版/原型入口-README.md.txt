## 1. 可以操作的业务闭环

| 页面 | 当前可操作内容 |
| --- | --- |
| 排程工作台 | 订单交期、设备 / 人员 / 车间工序三甘特、日期范围及搜索、工序详情、人工调整、时间 / 资源 / 全锁、撤销、候选重排、审查发布 |
| 生产订单 | 多产品订单、从已有正常工艺模板展开、数量及工时重算、工序追踪、产品及订单合格进度 |
| 工艺路线 | 工序图、先后 / 数量门槛 / 连续转移批依赖、工时及阶段参数、循环和缺项校验 |
| 工作中心与设备 | 设备能力、可选资源、班次及维修例外；历史已执行时段受保护 |
| 人员与班次 | 具名员工、技能等级、出勤及请假、可用工时和分配；多技能员工不重复累计 |
| 加工批次 | 兼容与容量校验、共享炉批、成员及共同时间、合批 / 拆批 |
| 约束与异常 | 未排任务、依赖、技能、资源日历、锁定冲突及任务定位 |
| 现场执行 | 正式计划任务、开工 / 暂停 / 恢复、合格与不良报工、数量放行、不良返工或报废补产 |
| 车间每日生产表 | 日计划基线、工序及末道产出、按实际阶段的人时 / 机时、跨日归属、CSV、打印媒体 |
| 人力累计产能 | 员工去重容量、日 / 半日累计、已排与剩余、时段冲突、未排需求、明细与 CSV |
| 计划版本 | 草稿与正式版本差异、工序及交期影响、恢复旧版为新草稿、发布说明及复验 |
| 操作记录 | 本地操作时间线、关联任务、筛选和 CSV |

页面共享一份状态。修改工艺、数量或日历会使旧候选过期；生成候选不等于发布，现场使用正式版本。正式计划与当前批次或工艺不一致时，开工 / 恢复会要求重新排程发布。

## 2. 代表场景

初始包含 4 张订单、17 道任务、9 名员工和 4 台设备，时间窗口为 2026-09-14 至 9 月 18 日。人员默认班次 08:00–12:00、13:00–17:00；这些是演示参数，不读取当前工厂。

**订单 O-100：** A、B 各 100 件。A10 合格 50 件后才释放 B10，随后两产品进入共享炉批 H1。炉占用 3 机时，王工只在装卸参与，共 1 人时；赵工先检 A，次日检 B，预计整单 9/15 09:00 完成，比 9/14 17:00 承诺晚 16 个自然小时。

**订单 O-400：** 上序 20 件 / 小时，每 20 件转序，下序 40 件 / 小时。下序形成三段 30 分钟加工，中间等待后续释放，不能一次性提前消耗整单数量。

现场页可设置模拟生产时间并实际操作开停与报工。时间经过不会自动形成合格放行；暂停、午休和晚到的上游释放都会参与实际产能检查。不良品可以形成返工或完整路线补产任务，经重排发布后执行；回记原产品时不重复计算交付量。

## 3. 数据与恢复

- 使用当前浏览器 `localStorage`，键为 `business-prototype-v1:production-workbench-v2.0`。这是示例业务数据，没有真实账号、客户、设备采集或生产写入。
- 刷新保留本地修改。浏览器不允许存储时会提示，数据只留在当前页面；不同浏览器或不同文件位置的存储互通不作保证。
- 多标签页检测到旧副本时阻止覆盖，提供导出当前编辑副本和载入最新计划入口。它只保护同浏览器本地编辑，不是生产级并发控制。
- 草稿调整可撤销；旧版本恢复只形成新草稿，已发生报工和正式版本不被回退。历史日历不能通过资源表单修改已经发生的作业时段。
- CSV 导出用于查看和复核，不宣称是完整数据库备份。恢复初始示例可使用隔离浏览器上下文；勿为体验原型清除浏览器的全部网站数据。

## 4. 设计与实现

沿用已有原型的紧凑侧栏、筛选条、表格、抽屉、绿色主操作与多种语义状态。主屏直接显示调度工作台。甘特时间条保持真实相对长度，短条可通过提示和详情查看全称；长表格与时间轴局部滚动，窄屏导航折叠。

当前甘特由原生 HTML / CSS / JavaScript 绘制，未接入第三方甘特组件。生产实现已接受 [DHTMLX Community v10+ 与 `vis-timeline` 进入 PoC](../../文档/项目/生产排产项目/决策/甘特图组件选型决策.md)：前者用于订单 / 工艺路线任务甘特，后者用于人员 / 设备 / 车间资源时间轴。该决定不改变本原型的验证事实，也不表示组件、许可证文件或生产适配层已经落地。

`engine.js` 集中处理约束、数量和执行；`app.js` 维护工作台与保存；`catalog.js` 负责订单工艺资源；`operations.js` 负责现场和报表。模块通过 [实现契约](contract.md) 共享状态。

排程使用本地 `javascript-lp-solver 1.0.3` 对有限候选进行二进制选择，外围按就绪任务逐次排入。这样可以运行真实约束示例，但不保证全局最优。第三方库来自官方 npm 包，见 [来源与许可](vendor/solver-SOURCES.md)。共享 Lucide 图标沿用 [原资产许可](../business-suite-v1/shared/lucide-LICENSE.txt)。

## 5. 面向生产系统的明确边界

本轮交付完整工作流的本地交互原型及产品需求基线，**没有达到生产系统上线就绪状态**。以下内容由 PRD 保留为产品要求，原型未完成的部分不以按钮或样例代替：

- 真实 ERP / MES / HR / WMS / QMS、服务端身份权限、持久数据库、报工事务与来源幂等、外发重试、监控和备份恢复。
- 全局最优、倒排、任意规模数据与求解超时保证。当前是 5 日有限窗口和小样例，不能外推至 PRD 性能目标。
- 多人员协作席位、任意同起同止同步组、跨班换人、恢复准备及设备保留策略的全组合。
- 连续消耗转移批限单按件来源、manual / machine、固定速率、零装卸和整数换算；复杂转序与返工组合显式阻断。
- 任意部分数量装炉、完整工艺主版本发布及迁移、独立待检 / 隔离放行、历史报工更正审批。
- 多浏览器与辅助技术完整矩阵、真实负载与安全测试、工厂现场用户验收。

生产实现顺序为：固化 PRD 对象与数量账 → 服务端共同约束与计划版本 → 真实人员 / 设备日历和执行接口 → 用同一 AC 场景验证复杂组合 → 容量、安全与恢复验证 → 现场验收。具体未验证项在 [验证记录](verification.md) 逐条关联 AC。
