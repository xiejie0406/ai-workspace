## 1. 当前结论

本 Feature 的目标是把已有生产排程需求、29 表数据库业务雏形和本地交互原型，转化为可部署的单站点生产排程 P0 产品。IMP-01～IMP-09 已完成。IMP-10 的技术项已收口：日冻结基线、每日生产表、人员去重累计产能/多席位峰值与技能有效期、订单/产品行 ETA、CSV/打印、权限审计与 OpenAPI 已形成纵切片；Worker 遗留求解回收、优雅停机、发布故障原子回滚/重试和 29 表恢复已有本地证据。PRD AC-01～24 与 21 项 P0 APS-AC 的技术回归均已通过。本机固定容量基准的 1k/5k/20k 独立单阶段形态均在 30 秒求解上限内得到经独立校验的可行候选，当前为有限 Go；结果不证明复杂业务形态的目标质量或未经验证的生产硬件 SLA。用户已明确 Windows 为目标运行环境，当前 Windows 11 x64、Microsoft JDK 17.0.18、OR-Tools JNI、API/Worker 启动和前后端制品均已通过隔离复验。真实角色/数据联调和业务 UAT 尚未完成，因此 IMP-10 仍为 `InProgress`，不能评为 `ReleaseReady`。

用户已批准[十阶段实施计划](任务清单.md)及其开工基线。计划使用 `IMP-01`～`IMP-10` 表示十个**实施里程碑**，与协作规范中的 Stage 1～10 **治理阶段**分开。Feature 处于 Stage 7 / InProgress：IMP-01～IMP-09 已完成，IMP-10 技术项已完成而 UAT 待执行。目标环境就是当前 Windows 本地环境，API 与 Worker 使用两个独立 Java 进程；Docker、WSL 和 Linux 仅可作为未来可移植性验证，不属于本 Feature 当前完成条件。

## 2. P0 最终闭环

2026-10-01 已按用户批准范围修复本机主流程衔接：按车间/订单名称发起排程，选择候选或正式计划，从正式作业进入派工并选择报工成员。六项合成样本页面检查通过，原失败与修复后证据均保留，详见[本轮定向复验报告](evidence/20261001主流程复验/verification-report.html)和[任务第25节](任务清单.md#25-本轮主流程衔接修复)。本轮实际API/Worker运行环境为JDK21，与上文历史JDK17基线分别记录；真实角色UAT、用户接受和上线就绪结论未因此改变。

```text
资源与工艺维护
  → 多产品订单与路线版本展开
  → 数据就绪和硬约束校验
  → 单 Worker 有限产能排程
  → 数量释放、转移批、拆批与共享加工批
  → 三类甘特、人工计划、锁定、版本比较与系统内发布
  → 开停工、实际占用、部分报工、质量处置、返工与数量账
  → 车间日报、人力产能、订单预计完成与原因解释
  → 安全、恢复、容量验证和用户验收
```

首版采用一套 APS 业务数据库服务对应一个生产站点，车间是组织、权限与报表根。首版不恢复 `aps_factory` 或 `factory_id`，技能只使用 `aps_resource_skill` 一张表。

## 5. 已批准开工基线

下列选择已经随十阶段计划获得用户批准，是当前开发基线：

1. P0 的 API 与 Worker 统一编译到 Java 17，沿用共享父工程，不把全仓升级 Java 21 作为 APS 开工前置；同步修订当前 APS 设计中的 Java 21 表述。
2. `admin-web` 只为新增 APS 文件增量接入 TypeScript、`vue-tsc`、Vitest 和 Playwright，不迁移既有 JavaScript 页面。
3. 使用 29 表、单 Worker、受控失败恢复和系统内发布；不把 `row_version` 冒充分布式租约。用户已批准把多 Worker 接管、Solver Attempt、Inbox/Outbox 和外部 MES 可靠回执转为 P1，PRD 与引擎设计已同步。
4. P0 日历事实为 M05 中的绝对可用/不可用时间窗，由人工、导入或受控 API 物化；循环班制模板和 HR 实时同步不在 29 表首版中暗建。
5. 单站点信息和 IANA 时区由部署配置承担；数据权限按 RuoYi 角色加车间/工作中心范围实现，不恢复工厂表。
6. MySQL 是 APS 唯一业务事实源；RuoYi 用户、部门只以稳定 ID 逻辑关联，不建立跨库外键、跨库 `JOIN` 或跨库事务。
7. OR-Tools CP-SAT 是 P0 求解 PoC 首选；任何候选必须再经过不依赖 OR-Tools 的独立硬约束校验器才能发布。
8. DHTMLX Gantt Community 与 `vis-timeline` 仅位于前端适配层；数据库、REST 契约和领域对象不保存组件原生对象。

## 6. 审核门与授权限制

用户批准十阶段计划后，已批准路径内的本地代码、文档、隔离数据库和自动化验证可连续实施；每个 IMP 完成后按真实证据汇报，不机械重复申请相同授权。以下事项不由路线批准自动授权：

- 在真实生产数据库执行 migration 或写入真实业务数据；
- 连接真实 ERP、MES、HR、WMS、QMS 账号或向外部系统写入；
- 安装或启用会产生费用的服务、正式发布或上线；
- Git 暂存、提交、建分支、推送、PR、标签和发布；
- 将 P1/P2 能力并入 P0，或新增多 Worker、消息中间件、Inbox/Outbox 等基础设施。

四个关键复核点是：IMP-01 技术与业务基线、IMP-06 OR-Tools PoC Go/No-Go、IMP-08 系统内发布语义、IMP-09 数量与执行账口径。IMP-10 的 UAT 决定只能由用户或业务负责人给出，且 `ReleaseReady` 不等于已发布。

当前按[任务清单](任务清单.md)完成至 IMP-09；IMP-10 的报表与 ETA、Worker 恢复、发布故障回滚/重试、完整 P0 技术 AC、固定独立单阶段容量形态及 Windows 目标运行时均已形成证据。复杂业务形态、真实试点与 UAT 前置仍未收口。真实生产迁移、外部账号、正式部署与 Git 写操作保持关闭。
