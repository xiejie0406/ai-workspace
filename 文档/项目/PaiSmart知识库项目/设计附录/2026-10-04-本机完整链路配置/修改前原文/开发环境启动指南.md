# PaiSmart 开发环境启动指南

> 文档类型：Windows 开发环境操作说明；版本：1.2  
> 负责人：当前项目执行者；创建：2026-10-03；更新：2026-10-04  
> 用户依据：本轮要求核对已有软件，软件下载和安装目录使用 `D:\javaSoft`，以后再要求启动项目；每次开发前必须先准备好运行环境。  
> 适用范围：当前 Windows 电脑的 PaiSmart 项目；共享基础服务规则继承[多项目并行开发启动指南](../../若依框架/多项目并行开发启动指南.md)。  
> 本文唯一维护本项目的软件需求、路径、启动顺序与就绪判定；实际实施结果仍在[完整迁移设计第6节](完整迁移设计.md#6-实施记录)，本次只读核查原始事实见[环境核查](设计附录/2026-10-03-启动环境核查/环境核查.json)。

**当前软件准备已覆盖主要基础服务，但还不足以直接运行完整知识库。** MySQL、Redis 已运行；MinIO 可执行文件已有；Kafka 4.2.0、Elasticsearch 9.3.1 只有压缩包。2026-10-03 软件核查未启动项目；2026-10-04 接续的查看通道、实际结果及缺项以第8节和[唯一实施记录第6.7节](完整迁移设计.md#67-本机查看通道启动与只读完成度核对)为准。

以后可以直接说：**“按 PaiSmart 开发环境启动指南，先准备好环境，再启动项目。”** 执行者按本文核实当前状态，复用已运行服务，再补齐真正缺少的项，不能直接运行原参考工程的 Docker 全套配置。

## 1. 每次开发前必须先准备环境

1. 执行者在修改 PaiSmart 业务代码之前，先阅读本文和唯一实施记录，核实当前配置、固定包、进程、端口及所需功能范围。
2. 已有正确实例先做只读健康检查并复用；未运行的必要服务按下述顺序启动。完成后核对项目后台、前端、任务消费、解析入口、存储/检索和模型配置，保存当时版本、PID、地址、日志及结果。
3. 默认开发环境必须支持文档上传、解析、索引、检索和问答。缺必要配置、服务或身份时明确说明缺项，先处理环境问题，不把接口有响应、前端能打开或构建成功称为环境就绪，再进入功能开发。
4. 如果用户本次明确只要求文档、只读核查或离线编译，不为此启动业务；如果用户明确限定纯界面等范围，只核实该范围，但不能称完整环境就绪。本次就是用户指定的检查和文档任务，项目启动留待后续请求。
5. 重建包后让当前开发通道使用新固定版本，再核对进程和前端代理。已有共享实例地址/版本正确时不重复启动；项目停止不得停止共享 MySQL、Redis、对象存储、Kafka或ES，也不得终止其他项目进程。
6. 环境准备不自动授权建表、菜单/账号/角色写入、导入旧数据、提交文档样本、付费模型/OCR测试、微信支付或Git操作。开启消费者前先检查既有排队任务和副作用，避免启动时意外重放收费或运维任务。

| 软件或服务 | 在项目中的用途 | 当前核查结果 | 下一步 |
|---|---|---|---|
| Java / Maven | 若依中心及独立解析 Worker、源码构建 | Java Temurin 21.0.10、Maven 3.9.15已有；项目编译目标17，上轮私有构建成功 | 复用；不额外安装JDK或Maven。启动前核实实际Java与包版本 |
| Node.js / npm | Vue/Element Plus管理端开发与构建 | Node 24.15.0、npm及管理端node_modules已有，上轮类型/构建成功 | 复用；不运行无依据的全局安装或重装共享node_modules |
| MySQL | 若依账户/权限及知识库正式业务、账务、任务 | MySQL 8.0.46；现有`localhost:3306/ry-vue`可只读查询；54表、history1—5回读完整 | 复用原库/账号，禁止再次建库、初始化或重复DDL |
| Redis | 共享登录会话与知识库原子限流 | 现有服务`127.0.0.1:6379`，Redis 5.0.14.1，PING返回PONG | 复用同一连接/database与原认证；不再起项目专属Redis。PING不证明所有业务键/脚本已验证 |

| Kafka | outbox通知与中心任务消费 | 2.6已有原配置；后续找到`D:\tmp\kafka-logs`及`D:\tmp\zookeeper`原集群数据，4.2仍只有压缩包 | 优先恢复同版原集群，见第9节；不格式化、不以4.2空集群替代。当前JDK21不在2.6官方支持范围内，实际恢复与长期支持结论分开 |
| Elasticsearch | BM25/KNN混合检索及版本化向量索引 | 2026-10-04后续已核对9.3.1包官方SHA512并解压至`D:\javaSoft\elasticsearch-9.3.1`；没有原集群data/证书 | 首次准备loopback、TLS、身份/ApiKey和Java信任配置；项目9.3.1检索兼容仍未验证 |
| LLM模型服务 | 四工具问答、摘要；增强、核验、Judge等可选调用 | `ps_provider`为空，本项目托管密钥元数据为空；本轮未访问模型 | 配置至少一个受支持接口的LLM模型、用途与预算，属于服务接入，不是安装桌面软件 |
| Embedding模型服务 | 文档向量化与语义检索 | 同上，无激活Embedding配置及活动索引 | 配置模型/维度/托管用途，并通过正式索引流程建立匹配版本；不能用LLM模型顶替 |
| 独立解析 Worker | Tika/PDFBox/现代Apple正文解析 | 上轮私有`logic-worker`主JAR与240个依赖已打包 | 配置固定classpath即可，不需另装Tika服务器；只核对入口，不提交业务文件作启动探测 |

当前机器32GiB物理内存，核查时约9.2GiB空闲；D盘约810GiB空闲。首次本地启动可先限制ES堆1GiB、Kafka堆约1GiB、中心堆768MiB，再观察实际占用；这是开发初始建议，不是容量测试或生产配置。不要让ES默认自动分配大量内存影响其他项目。

### 2.3 不需要为本项目单独安装的东西

- `D:\javaSoft`中的Nacos 1.1.3/2.4.3：当前PaiSmart没有Nacos注册/配置中心接入，不是启动前提。
- Postman 8.3.1安装器：可选接口调试工具，不是运行依赖；安装器存在也不表示已安装。
- Docker/WSL：本轮未发现Docker命令，WSL报告未配置；ES Windows ZIP、Kafka Windows脚本及MinIO exe已经提供本机准备路径，不因原项目compose存在就安装Docker或启用WSL。
- ZooKeeper：旧Kafka2.6配置需要它；选Kafka4.2 KRaft时不需为其另起ZooKeeper。[Kafka4.2官方启动说明](https://kafka.apache.org/42/getting-started/quickstart/)
- Tika、PDFBox、MinIO/Kafka客户端、BouncyCastle、阿里OCR/微信SDK、ZXing，以及Vue、Element Plus、PDF.js、Markdown-it、KaTeX、DOMPurify：它们是已随Java/前端工程依赖安装或打包的库，不是需要单独启动的Windows应用。

| 项目 | 正确准备方法 | 当前缺项 |
|---|---|---|
| 数据库/Redis | 复用原`.env`托管的DB连接及原共享Redis，秘密只在进程内传入；不得写进本文、日志或命令参数 | 连接只读可用，实际后端配置注入未启动核对 |
| MinIO | `object-store.endpoint/bucket`、`platform.paismart.minio.access-key/secret-key`项目托管用途；恢复原存储身份，不取参考文件明文示例 | 端点/桶/项目用途未配，已有原存储身份尚未确认 |


## 5. 第一次准备与每日启动顺序

### 5.1 第一次准备

1. 复核`D:\javaSoft`文件、版本、来源摘要和现有数据，保留安装包及旧配置。只准备真正缺的项，不重装共享MySQL/Redis。
2. 解压现有ES/Kafka包；ES使用其内置JDK、独立数据/日志与开发堆限制，设置单节点和loopback监听；保留默认认证/TLS。Kafka4.2使用新空数据目录，例如`D:\javaSoft\kafka-data\kraft-4.2`，替换默认`/tmp`路径并限制loopback监听。
3. Kafka第一次格式化仅用于已核实的全新空KRaft目录，保存cluster ID和配置；存在`meta.properties`时直接恢复而不重格式化。Windows入口为4.2目录`bin\windows\kafka-storage.bat`的`random-uuid`及`format --standalone -t <既定clusterId> -c <已审核配置>`，实际配置及数据路径核对后才执行。[官方KRaft启动流程](https://kafka.apache.org/42/getting-started/quickstart/)
4. 恢复MinIO原目录/身份，配置必要桶、主题、ES项目用途及模型用途。创建这些服务资源或平台用途是明确的配置写入，须纳入当次启动范围；本轮没有执行，不能假称已存在。
5. 需要扫描件时补LiteParse和语言资源，不启动额外PaddleOCR/EasyOCR/LibreOffice全套服务。云OCR/充值支付按当次明确范围准备，不默认发真实测试请求。
6. 生成本项目通道私有配置/日志定位，先核对秘密用途及原库表，再进入每日流程。缺前提时停止相关启动并报告，不用空桶、空库或假模型代替原数据。

### 5.2 每日启动

1. **共享数据库、Redis**：先检查原服务及只读查询/PING，已健康就复用。不能因为要启动PaiSmart停止或重建别的项目基础服务。
2. **MinIO、ES、Kafka**：查地址/PID后复用；确未运行时使用已核实安装目录和配置。启动命令入口分别是`minio.exe server <原数据目录>`、ES的`bin\elasticsearch.bat`、Kafka4.2的`bin\windows\kafka-server-start.bat <已审核配置>`。MinIO/API/console及Kafka broker/controller监听loopback。后台启动一律隐藏窗口并保存PID、日志；凭据不放命令参数。
3. **后台**：使用当前PaiSmart固定admin包，开启`paismart.enabled`并显式关闭interview/fashion/aden/aps/aipicture/aippt/paiflow/paicli及必要独立子开关；共享数据源和Redis保持原值。先检查密钥解密主配置、对象/ES/模型出口白名单、解析classpath与WS Origin，再启用必要子功能。不能直接启动参考项目的独立账户/数据库服务。
4. **任务消费**：核对待处理作业数量和类型、模型预算/对象副作用及主题权限后开启。上传索引处理需要Kafka、解析、对象写入和外部ES/模型调用；12项默认关闭开关不能原样用于完整开发。只开启实际所需，不能以关闭问答/解析后能打开页面称完整环境已准备好。
5. **前端**：工作区根目录使用下述已有入口，代理必须指向当次后台；同一管理端其他项目使用自己的Vite缓存，不能覆盖它们的配置。

```powershell

$env:ADMIN_DEV_BACKEND_URL = 'http://127.0.0.1:18096'
```
