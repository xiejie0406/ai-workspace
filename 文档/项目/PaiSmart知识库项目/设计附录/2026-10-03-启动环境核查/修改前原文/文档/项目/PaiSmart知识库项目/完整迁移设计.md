## 1. 需求与业务逻辑

### 1.1 用户目标与完整范围

用户登录共享若依后，按已有角色菜单进入“知识库”：上传并管理文档，按个人、公开或组织空间检索，进行有引用的流式问答与摘要，查看历史和额度。知识库管理人员处理文档冲突、模型配置、向量索引、评测及人工复核，维护业务组织、邀请码、用量策略和充值套餐。平台账户、角色、部门和权限仍由若依维护。

迁移包括原项目所有实际业务能力，以及使这些能力在若依中完整可用所需的管理页面、数据映射、可靠性修补和运行交付。实施可分批验证，但不得将后续批次变为可选范围或把“问答可运行”当作完整迁移。原模板空页面、规划中算法不冒充已实现功能；本设计明确要补齐的差距仍属于交付范围。

原项目 README、代码和测试的证据边界不同：下表“已实现”仅表示找到具体执行链路，未运行原项目或测试，不表示功能已验证。原 `pom.xml` 是 Java 17 / Spring Boot 3.4.2，持久化采用 JPA；原前端是 Vue 3.5.13 / TypeScript 5.8.3 / Naive UI 2.41.0 / Vite 6.3.5。目标以共享父 POM 的 Java 17 / Boot 4.0.6 / RuoYi 3.9.2，以及管理端 Vue 3.5.26 / Element Plus 2.13.1 / Pinia 3.0.4 / Vite 6.4.3 为基线；TypeScript 5.9.3用于本业务岛，共享设施仍有 JavaScript。声明版本不证明本机服务或安装依赖正在运行。

### 1.2 用户流程与业务规则

1. **获得业务资格。** 使用若依登录、注册、验证码、退出、个人资料及密码管理。已有用户通过映射保留原文档、组织、余额和会话。知识库邀请资格、初始额度和业务组织在业务模块完成；邀请码不可赋予平台管理员角色。开放注册与邀请注册在既有注册链路上扩展，平台注册开关关闭时不得绕过。
2. **选择知识范围并上传。** 个人空间只允许本人及获授权管理人员访问；组织空间要求有效成员资格和上传权限；公开意味着共享平台中已登录且有知识库访问资格的用户可读。组织成员默认可读其直接组织及祖先组织的共享文档，不能自动读兄弟组织或子组织。原 `OrgTagCacheService` 收集祖先标签，原 `default` 标签还有宽放行逻辑；目标统一范围规则，默认空间不隐式等于公开。这项收敛及历史分类需用户审核。
3. **分片、续传与处理。** 用户选择文件、范围和公开标记，系统预估 Embedding 用量，检查组织非管理员上传上限和余额，进行分片校验、断点续传、合并、解析、上下文说明生成、向量化及索引。每阶段显示实际状态；合并成功不是索引就绪。失败后重试复用有效片段，避免重复收费。相同内容跨范围可复用存储字节，不能复用授权元数据或泄露其他人的文件是否存在。
4. **检索、问答与摘要。** 检索首先限制资源范围，再执行关键词和向量两路召回、RRF 融合、重排与阈值过滤。模型按需调用知识检索、主题摘要、用户反馈、知识库统计四个工具；闲聊及明确不查知识库的请求不强行检索。检索事实、模型推断、引用可疑分别显示。工具与父块扩展始终继承提问者权限。
5. **使用与管理会话。** 新建、切换、归档及恢复会话；个人只读自己的历史，授权审计人员按业务范围查询用户历史。断线后按生成编号恢复现有结果，不自动重发提问；停止生成保留已经生成的内容和真实用量。历史保存原文引用映射，点击引用可定位 PDF 单页及锚点，其他格式显示片段或受控下载。
6. **治理知识质量。** 新文档索引后检测可能冲突；管理人员比较新旧证据，再选择保留新文档、保留旧文档或忽略。保留一方会使另一份整篇文档退出检索，界面必须明确影响范围。索引升级保存目标供应商、模型版本和维度，异步重建、追平变更、校验后切换，旧索引可回滚。离线评测使用授权样本、模型和配置快照，并由人工检查抽样结论，不能只凭模型评分发布。
7. **管理消耗与充值。** 用户查看 LLM、Embedding 余额、日用量、请求次数和逐笔流水；管理员设置限流、日额度/余额策略和追加额度，提供理由。充值包含套餐、自定义金额、扫码订单、订单查询和支付回调；金额以整数分计算，额度以整数 Token 计算。真实支付是否启用不影响功能实施范围，上线启用需要审核商户、价格、凭证和费用范围。

### 1.4 审核需决定的内容

| 决定 | 建议方案及理由 | 不确定范围与影响 |
|---|---|---|
| 业务组织与公开范围 | 保留原组织标签树作为业务知识空间；可绑定若依部门但不强制一对一；公开限于平台已授权用户；默认空间须显式授权 | 原“多租户”实际是标签共享，非完整独立租户。若要求跨企业绝对租户隔离，需增加企业owner及租户键，调整所有唯一约束/检索过滤/数据映射后再实施 |

## 3. 后台处理设计

### 3.1 模块、运行进程与正式事实

新增 `ruoyi-backend/ruoyi-paismart`，包 `com.ruoyi.paismart`，由 `ruoyi-admin` 装配。Java/MySQL拥有文档元数据、业务组织/成员、任务、会话、引用、评测/复核、冲突、模型配置引用、额度/账本、订单及操作审计。ES是可重建检索投影，MinIO是文件/报告/临时分片对象，Redis是可丢弃缓存/限流/短期流式数据，Kafka是作业投递通道，均不作为第二正式业务控制面。

解析保留独立 `lit`/OCR进程，可用原Java Tika算法在独立解析Worker中执行以避免阻塞中心和影响其他业务。Worker只获取中心签发的具体任务和短期对象读取授权，返回页/块/错误结果，不直接连接业务库、不维护账户、不决定权限、收费或任务终态。初始建议将原Java算法适配到Boot4模块并通过受限外部进程调用LiteParse；如果Tika依赖隔离实测需要独立Java17解析应用，使用同一任务契约拆出执行器，而非复制原SmartPAI后端。

Kafka保留是为了维持文件处理、积压/背压和重放能力；不能未经等效性验证换成中心线程池。启动关闭模块时不能连ES/MinIO/Kafka、初始化索引或导入文档。模块开关 `paismart.enabled=false` 默认关闭；解析消费、迁移、内置导入、支付、外部OCR和模型调用均有独立显式开关。

### 3.2 数据与权限

建议在批准的现有MySQL实例/业务schema内使用 `ps_` 前缀表和 `paismart_schema_history`，新业务落库位置需实施前确认，不新建或克隆数据库。平台 `sys_user/sys_role/sys_dept/sys_menu` 仍是唯一账户/平台权限源。业务用户以 `sys_user.user_id` 关联，迁移映射保留旧ID和旧username；不把名称作为稳定主键。

### 3.3 文件、解析与异步处理

上传创建时服务端核对类型、真实大小上限、范围、组织上限和配额，冻结Embedding估算额度。客户端建议4MiB分片、最多3并发，分片请求限16MiB；逻辑文件建议初始最大200MiB、PDF最大1000页，这些是拟定上限需按样本和资源核定，不从原multipart 50MB推断原逻辑文件上限。状态请求回源MySQL分片manifest，Redis位图可重建；服务端校验连续编号、总字节数、每片摘要和合并SHA-256，原MD5兼容只用于数据映射。

流程为“上传中→合并中→待解析→解析中→待向量化→向量化中→可检索”；任一步可以进入“失败/待重试/取消”，拒绝状态逆跳。MySQL事务提交文档和outbox后再投递Kafka；对象上传先写临时key，业务记录引用成功后才发布，残留对象通过补偿清理。解析输出带documentId、contentVersion、jobId与checkpoint；过期租约或内容版本不符的结果不入正式索引。

Kafka拟主题 `paismart.file-processing.v1`、`paismart.file-processing.retry.v1`、`paismart.file-processing.dlq.v1`；按documentId分区保持同文档版本顺序，消费者以事件ID/作业版本去重。失败最多3次，建议30秒/2分钟/10分钟退避；无权限、格式不支持、永久无额度错误直接人工处理，毒文件隔离。内存水位达到0.8暂停新解析，下降到0.7恢复，暂停超过300秒告警，不暂停其他项目消费者。文件解析默认最多2任务并行，LLM增强最多2并行，上限由显式配置控制。

Tika处理非PDF，LiteParse按页处理PDF并按原chi_sim+eng配置OCR。有文本PDF、扫描PDF、混合PDF、表格/换行、无标点、空白、损坏及超页数均有样本；白名单每种扩展名必须有可解析样例，Apple格式解析资料不足时在实施中补适配或明确修订支持契约，不能只因扩展名允许就宣称支持。XML禁止外部实体/网络解析，HTML不执行资源，压缩炸弹/路径穿越/超时有隔离。OCR健康检查和真调用分开；调用费用记作业，凭证通过现有托管密钥按用途读取。

向量化按块checkpoint，失败仅重试未完成部分；批次结果包含provider/model/dimension/usage与请求ID。Embedding维度必须匹配ES索引，错维度失败不可索引。上下文增强保留原邻居窗口、最多200字符说明、分组8块、退化原文的算法和开关，但生成说明不能替代原证据。原独立Parent-Child实体模型尚未实现，目标先使用当前相邻块扩展及文字合并，不无依据升级算法。

### 3.4 检索、流式问答、工具与历史

普通查询先解析中心用户范围，再生成ES过滤。BM25/KNN每路窗口为TopK×30、最多300候选，RRF默认k=60；原默认rerank最多50候选、阈值0.2、10秒超时保留为配置候选。TopK是上限，阈值过滤后可以少于TopK。rerank失败降为RRF并标记scoreType，不能对RRF分数套用rerank阈值；Embedding不可用时可降为带权限的关键词检索，ES不可用明确失败。展示引用、扩展邻居和工具统计都以Java二次权限核对后的文档为准。

四工具保留名称与schema：`search_knowledge(query,topK)`、`generate_summary(topic,maxDocs)`、`submit_feedback(rating,reason)`、`knowledge_stats()`。工具白名单、参数范围、超时和ReAct 4轮/8调用在Java确定性执行；未知工具拒绝，模型不能读任意对象路径、扩大组织范围、删除文档或调整账务。统计原实现使用全库计数，迁入后普通用户只看到授权范围；运维全库统计需专门权限。反馈仅在用户明确评价意图或点击按钮时记录，绑定已有message/generation，不让模型推断点赞。

REST通过共享request取得一次性WS ticket，ticket绑定若依用户、登录会话和Origin，建议60秒有效、单次消费；不在URL中传长期Bearer。握手只允许业务WS路径使用专用ticket验证，不开放全域匿名路由。WS只是已有认证下的传输适配，不建立独立JWT/刷新token。新增共享安全扩展时只配置具体路径且记录兼容范围。使用现有平台token撤销信号关闭连接；若暂无通用扩展点，应在原TokenService校验基础上添加最小适配。

事件包含type、conversationId、generationId、sequence、timestamp和payload，涵盖开始、文本增量、工具状态、引用、核验、完成、错误、停止；客户端以sequence去重。发送请求具有clientRequestId，重发返回同generation；当前用户同会话只允许一任务，其余返回占用状态。断线重连从已确认序号继续；回放窗口过期返回持久消息快照，不重算/重扣。运行lease与checkpoint在MySQL，Redis流/缓存仅用于回放；中心进程崩溃将失去供应商流连接，恢复为明确“中断”并保存内容/结算，不声称能从任意Token无损继续上游生成。

长期历史与引用正式落MySQL；Redis仅缓存最近上下文。新建/切换/归档/恢复验证会话owner，管理员历史另经audit权限和空间范围；会话“归档”不等于删除。原跨轮引用编号规则、fileMd5/chunkId/page/anchor映射迁为documentId/contentVersion并保留legacy映射。文件权限撤销、删除或索引回滚后仍保留历史引用文字/版本，但正文预览重新授权；无法访问显示原因。引用核验默认关闭、可按政策启用，可疑结论是质量提示，不能改变访问权限或自动删除答案。

### 3.5 冲突、索引与评测

冲突检测沿用相似候选阈值、键值分析和可选LLM确认；检测只是建议，不能自动裁决。冲突pairKey带两份文档及内容版本，防重复；双方均可访问才提供证据。Resolve带rowVersion，事务冻结裁决和删除计划，随后异步使被舍弃文档退出索引；关联冲突变为失效保留原因。用户看见整个文档范围、引用影响和软删恢复期，恢复需重新向量化/索引并不会把旧裁决改写为未处理。

索引重建任务持久保存目标供应商配置快照、向量维度、原索引、目标索引、文档高水位和checkpoint；用数据库租约保证同知识命名空间一个切换任务，不能仅synchronized。拟索引别名 `paismart_knowledge_current`，物理索引 `paismart_knowledge_<modelVersion>_<revision>`，防与原knowledge索引及其他项目重名。重建按原全量→增量追平→暂停相关消费→校验→切换→恢复消费流程实施，目标从已有块生成新向量。切换时阻止本命名空间文档写投影，记录已开始作业并排空/重定向，删除tombstone与权限变更也须追平，不能只追上传文件。

ES别名与MySQL激活模型不可跨系统事务：使用持久切换日志及阶段状态，先校验，短暂阻断本业务查询，切别名、CAS激活配置，回读双方一致再开放；失败补偿回旧别名/配置，无法补偿保持受阻并告警。普通查询携带indexRevision及模型快照，不在切换窗口混用。回滚验证旧索引存在、模型/维度及凭证引用可用、权限投影已追平；旧版本保留周期审核后删除，不把fresh重建权限扩展成任意ES删除。

评测保留JSONL内联/上传/受控资源三入口、样本最多500、TopK最多20、检索指标、生成与裁判、错误诊断、JSON报告及人工抽样；不允许客户端传任意主机绝对路径。数据集、指标算法、搜索/上下文/模型/提示词配置和随机种子冻结版本，searchUserId从中心指定的受授权评测身份获得。评测成本按发起者或批准的部门预算计费，不能沿用system-eval/system-contextual字符串绕过额度。

报告保存对象及hash，运行/逐例正式状态落MySQL，人工review保存原始判断、修改版本、操作者和理由，不覆盖旧证据。人工与裁判一致率/kappa、最小可比样本数保留原逻辑；默认阈值0.8、最小5例仅是原配置起点，正式质量阈值需业务样本审核。评测不读他人私有文档，不能通过裁判供应商外发未经允许的内容；失败样本、空检索、Judge输出无法解析都单列，不能从总数删除后声称通过。

### 3.6 配额、充值、供应商与运维

LLM和Embedding在执行前MySQL原子冻结估算额度，(userId,operationId,scope)唯一；并发余额不足时拒绝，不采用原reserve仅余额检查方式。供应商实际usage优先结算；缺usage按固定版本估算并标注。结算/释放幂等，失败仍计已发生费用，超估算需有预授权上限并记录债务/拒绝下一请求，不能产生无来源负余额。每日额度策略与余额策略保持独立，Asia/Shanghai为拟业务日界，服务不可用时拒绝有费用调用，缓存可回源账本。

后台追加额度在同事务内写账户和流水，保存理由/操作者/前后余额/幂等键；限流Redis原子计数有namespace，登录注册策略扩展既有平台防滥用，不复刻原登录限流链路。用量统计从账本及请求记录聚合，可重算；图表不从内存临时值推断正式余额。

充值创建时保存订单金额、币种、套餐版本、LLM/Embedding权益、价格规则和过期时间，调用微信前交易号落库；失败状态可对账，不重复创建。回调属于外部支付认证边界，只精确放行callback路径，执行官方SDK签名校验/解密、商户/app/币种/金额/交易号匹配，校验后原子写支付事件、订单条件状态迁移和两类Token流水。主动查询与回调必须使用同一结算方法和唯一键，重复/乱序成功不重复增加余额；浏览器轮询不能直接驱动入账。禁止迁入原WxPay配置默认示例凭证；未启用时明确“支付未配置”，不能生成假支付成功。

退款不是已核实原能力；目标保留订单状态和异常对账，是否提供退款需另定业务规则，不能以原充值代码存在推断退款已经实现。套餐删除改为停止售卖或软删，历史订单快照可复算。自定义金额原逻辑按内部1分基准套餐乘Token，应改为审核后的版本化整数换算规则，处理最小/最大金额和溢出。

供应商配置复用平台托管密钥/Provider注册设施可用部分，业务provider只存用途、允许地址、模型、维度和secretRef。原LLM/Embedding范围保留，rerank、OCR与裁判配置关联同用途管理；改Embedding模型触发重建，不能直接切换。测试调用需权限、超时、额度和审计；地址校验允许批准的外部服务/内部推理服务，阻止任意内网探测、重定向SSRF及凭证跨域发送。

系统状态分开显示数据库、ES、对象存储、队列、Redis、解析执行器和供应商“可达/凭证错误/未配置”，不从进程存在推断全部正常。用户活动复用平台在线用户/登录/操作日志，业务任务/账务/治理另存业务审计。文本添加作为 `documents/text`走同解析/索引流程；内置文档导入改为显式受控作业而非默认启动副作用。对象搬迁先形成源/目的范围、对象manifest、hash、双读验证与停止/回退计划；清空先预览仅本业务对象范围，账务审计不清除，不保留原跨库一键清空入口。

### 3.7 接口与跨进程契约

2026-10-03 实施复查校正：原 `UserTokenService` 的当前余额在 Redis `user:token:llm:{userId}` 与 `user:token:embedding:{userId}`，MySQL `user_token_record` 为聚合/赠送记录，不能替代当前余额。迁移必须取得经批准的只读 Redis 余额及请求次数快照，与原数据库、对象和订单在同一停写时点核对；缺快照或账实不符阻止相关账号资产导入，不推算余额或重新赠送。目标迁入后由本模块 MySQL 正式账本持有余额，Redis只作为缓存与限流。
