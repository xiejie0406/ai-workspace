## 1 执行范围与选择

本地原型放在 `prototype/fashion-workbench-v2/`，采用现有工作区可用浏览器与脚本能力，形成独立静态页面及可维护的业务模块。原有 `prototype/business-suite-v1/`、其他产品原型、用户原始 Word 和 AI Interview Coach 业务工程均保持其既有责任边界。本次不借服装原型改动面试训练生产模块。

采用这一方案是因为完整原型需要真实上传解析、状态保存、图片采用、报价和文件生成，可直接以浏览器操作验证；单张静态设计图无法验证这些动作。后续生产实现采用“Vue 3/TypeScript 前端 + Spring Boot/RuoYi 业务控制面 + 独立 Python AI Runtime”的边界：Java 继续承担权限、业务事实、事务和正式副作用，Python 承担模型编排、结构化 AI 输出与评测。完整边界见[统一设计·Python运行时](../架构/技术架构设计.md#runtime)，不得把可修改的浏览器状态或模型输出当生产账本。

| 设计决定 | 本地原型 | 生产目标与迁移要求 |
| --- | --- | --- |
| 商品、批次、方案 | 本原型专属持久化；保存失败保持上一可读取版本 | 数据库事务、导入批次与当前行版本的服务端并发检查 |

| 权限 | 角色切换展示允许/拒绝场景 | 真实身份、字段权限、客户归属、下载鉴权，不能复用角色切换作为认证 |
| 恢复 | 本地工作区备份、结构校验后恢复、限定范围重置 | 定时数据库/媒体备份和隔离恢复演练，按 PRD 的 RPO/RTO 验证 |

## 3 数据设计与不变量

本节维护模块级数据意图；后续数据库表、字段、关系、索引和事务取舍的唯一详细正文为[统一设计·数据模型](../架构/技术架构设计.md#data)。首期按六个模块共 16 张 `fq_*` 业务表实施：10 张核心业务表覆盖商品/库存、客户、报价交付和导入，6 张 AI 表覆盖 Agent 主数据与版本、对话与消息、运行与步骤。固定导入模板随版本化代码/配置发布，不建模板表；采用/拒绝写运行状态、图片审核写方案图片记录，首期不建通用 AI 反馈表。确认后锁定 `fq_quote + fq_quote_combo + fq_quote_detail` 自身留档，修订复制新报价版本，不另建快照表；AI 运行输出经人工采用和业务重验后才写业务表。该文档不代表生产数据库已经建立或迁移完成。

### 3 1 对象与键

外部导入的字段、缺省值和校验以 PRD 第6节为唯一正文。以下说明持久化关系与并发信息，字段名可由正式代码契约映射。

| 对象 | 主键/关键约束 | 关系、版本与写入者 |
| --- | --- | --- |
| 商品资料（SKU） | source + sku 唯一；source + style + color + size 唯一 | 一张商品表保存款号、颜色、尺码、单位、图片与当前销售价；页面可按款号和颜色分组，下架保留历史引用 |
| 商品当前价格 | 与商品SKU一对一，不是独立业务表 | salePrice、币种、税口径和asOf直接更新商品行并立即生效；完整价格批次在导入明细保留前后值，首期不支持预约调价 |
| 当前库存 | product + warehouse 唯一 | availableQty、asOf和核实来源；库存批次与价格批次独立，历史变化由导入明细追溯 |
| 商品图片 | 当前图片随商品资料维护，文件按内容摘要识别 | 源链接、用途许可和imageVersion；确认报价明细冻结实际图片键、摘要和版本 |
| 导入批次 | batchId + 文件摘要 + 范围 + 业务时间 | 原文件、列映射、冻结SKU清单、校验结果、逐行前后值和操作者 |
| 客户与报价 | customerId、quoteId、quoteRowVersion；owner及授权成员 | 客户、brief、versionNo、状态；当前售价从商品读取，内部备注不进入对客投影 |
| 组合及配比 | comboId + quoteId + visualHash；`fq_quote_detail` 引用真实SKU | 1–4互异 `slot_code`，明细 `qty` 守恒，锁定商品、顺序、采购套数、图像采用记录 |
| 方案图片记录 | quoteImageId + requestKey | comboVisualHash、输入图版本、来源模式、供应商ID、1–4个结果、复核、费用状态 |
| 确认报价留档 | quoteNo + versionNo，不可覆盖已确认内容 | 方案、组合和明细三层冻结白名单对客字段、完整金额数量、取价批次、素材与模板版本 |
| 导出记录与文件 | quoteFileId + confirmedQuoteId + rendererVersion + fileType | 只读确认报价；记录状态、文件摘要/大小和生成时间，下载前重新检查访问权和素材禁用 |
| 操作审计 | 复用 RuoYi 操作日志能力和业务关联ID，不新增 `fq_audit_log` | 操作者、动作、对象、时间、前后版本、原因；实施时核实现有平台落点，不保存秘密或完整凭据 |

### 3 2 必须在实现中保持的约束

金额在原型内使用安全范围内的整数分和明确舍入；生产数据库统一使用 `DECIMAL(16,2)` 元，百分率使用 `DECIMAL(5,2)` 的百分数值，服务端采用十进制定点运算并按分币舍入，禁止二进制浮点累计。UI 输入先校验允许精度再转换，不能先四舍五入后接受非法输入。平均每套价格仅用于展示。

每个组合的品类数等于互异槽位数，SKU尺码行数不会增加品类数；每个槽位的 `fq_quote_detail.qty` 之和等于采购套数。备选按候选分别检查；合并先逐组合检查配比，再跨组合汇总 SKU，报价优惠/费用只计算一次。候选生成、人工替换、报价预检应调用同一业务校验，避免三个页面各自计算出不同结果。

确认时把当前明确对客数据写入并锁定 `fq_quote + fq_quote_combo + fq_quote_detail` 三层稳定记录，不保留可变商品对象引用，也不另建快照表。导出只读该已确认报价版本，不能再次取最新价格。素材本体版本稳定，后续禁用产生新的禁止使用事实，既不悄悄换历史图片，也不允许绕开禁用再次外发。

浏览器存储有容量与事务限制。原型须在克隆状态上完成校验，持久化成功后再替换当前状态；写入失败不提示成功。大图缩略图和实际下载素材需要保持明确关联，不能仅保存临时 `blob:` 地址导致刷新失图。生产把大文件放受控对象存储，数据库记录引用、版本、摘要和权限；存储 URL 不是业务主键。

### 3 3 版本迁移与恢复

工作区备份含 schemaVersion、导出时间、数据版本和全部必要集合及素材引用，恢复先校验 JSON/文件结构、已知schema、金额/数量范围、对象引用和文件限制。恢复动作在确认范围后一次替换本原型状态，保留现有数据的可导出恢复途径；未知未来schema拒绝写入。

生产数据库迁移先备份并记录行数/校验摘要，采取兼容新增字段 → 回填 → 校验 → 切换读写的顺序；移除旧字段或不可逆数据转换须形成实际迁移与恢复执行包。原型本地备份不是生产数据库迁移工具，不自动把示例客户、示例供应商账单或角色状态导入生产。

## 4 服务契约意图

本节定义未来业务接口职责与失败语义，正式开发时由单一 OpenAPI/类型 schema 维护字段，不另把 Markdown 维护为第二套机器契约。原型的浏览器函数不是外部公共 API。Java 与 Python 的 Agent Run、事件、Tool Gateway、鉴权、幂等和暂停恢复职责由[统一设计·Python运行时](../架构/技术架构设计.md#runtime)维护，实施时同样收敛为生成双端类型的机器契约。

| 接口职责（候选路径） | 输入/输出边界 | 权限与一致性 |
| --- | --- | --- |
| `POST /imports/validate` | 原文件标识、类型、范围、映射、业务时间；返回batchId、差异、行错误、覆盖数和baseDataHash | 运营所属范围；冻结商品范围与当前行版本；错误批次不能发布 |
| `POST /imports/{id}/publish` | batchId、expectedScopeHash、baseDataHash、确认差异摘要；返回成功批次与更新行数 | 运营范围；幂等键；范围或当前数据变化返回冲突，在一个事务中更新当前商品价格或库存行 |
| `POST /imports/{id}/restore` | 历史batchId、选择before/after、当前baseDataHash、恢复原因 | 运营/管理员；创建新的restore批次，保留目标值原asOf和完整前后值 |
| `POST /products/{id}/images`、`POST /products/{id}/images/{imageId}:confirm` | 文件、商品映射、来源/使用范围；返回商品图片版本 | 运营范围；内容与格式检查；主图变更发出受影响引用提示 |
| `POST /quotes`、`PATCH /quotes/{id}` | 客户需求、expectedRowVersion；返回 quoteId 和新 rowVersion | 本人或分配范围；字段白名单；旧行版本写入返回409；已确认版本不得覆盖 |
| `POST /quotes/{id}/combos:generate` | 明确确认条件、档位、数量、模式与锁定项 | 返回库内SKU候选和约束原因；异步结果带 quoteRowVersion |
| `POST /quote-images` | quoteId、comboId、comboVisualHash、输入商品/图版本、画幅、模式、张数和费用上限 | 权限和额度先检查；重复 requestKey 复用记录；后台密钥调用供应商 |
| `GET /quote-images/{id}`、取消/复核动作 | 返回当前状态、1–4个结果和账单状态；复核写输入版本与原因 | 报价访问权；终态规则与晚到结果隔离；取消不承诺退款 |
| `POST /quotes/{id}:validate`、`POST /quotes/{id}:confirm` | expectedRowVersion 及商务参数；返回阻断清单或已确认 quoteId/versionNo | 服务端重算金额/配比/库存/权限；确认后锁定三层记录，不建快照表 |
| `POST /quote-files`、`GET /quote-files/{id}` | confirmedQuoteId、quoteHash、rendererVersion 与 fileType；返回记录及受控下载 | 输出对客白名单；同确认报价幂等；下载再次鉴权与检查禁用素材 |
| 配置/额度/备份接口 | 管理设置、版本及操作原因 | 管理/运维权限；不把完整内部备份暴露给普通销售 |

变更请求携带 `expectedRowVersion` 和稳定幂等键；请求身份来自服务端认证，不接受 body 中伪造的 role。接口读取也按客户归属及字段过滤。耗时动作先返回受理状态和记录ID，任务受理不是图片或PPT成功。

| 错误类别 | 面向用户的结果 | 可重试规则 |
| --- | --- | --- |
| 输入/格式错误（400/422） | 行/字段错误及修正入口 | 修正后新校验；不对同样非法输入自动重试 |
| 无权限/身份失效（403/401） | 拒绝访问，保留允许恢复的草稿 | 重新登录或实际授权后重试，不自动换管理员身份 |
| 版本冲突（409） | 展示已有新版本、差异和本地副本 | 重新载入/合并/复制后新请求；不能覆盖旧baseVersion |
| 素材禁用/版本作废（410或业务拒绝） | 明确不可再次对客交付，指向修订流程 | 先换素材或新确认，不重试原禁止对象 |
| 额度或频率限制（429/业务拒绝） | 显示剩余额度/配额及已有排队任务 | 等待有效配额；禁止前端循环重试绕开上限 |
| 依赖或网络故障（503/超时） | 保留任务ID与“待查结果”或明确失败 | 先回查；确定未受理才有限重提，真实费用状态保持 |

## 5 状态、并发和外部任务

### 5 1 状态转换

导入正常路径为“待校验 → 待确认 → 发布中 → 成功”；校验错误转“校验失败”，发布前可“取消”，数据冲突回到需重新校验。成功后的修正通过新批次或显式历史恢复完成，不把原成功批次改写为另一份文件。发布事务失败整批回滚，商品价格或库存保持事务前状态，同时保留失败批次。

报价草稿编辑使 `row_version` 递增；候选和图片请求保存 `quoteRowVersion/comboVisualHash`。返回结果与当前版本相符才可进入当前可复核集合，否则标记为旧输入结果。锁定项与请求一起保存；编辑过程中晚到结果不得覆盖人工修改。价格/库存更新不是直接改写报价，而是添加需复核原因。

图片任务的供应商执行状态与业务复核状态分别维护。执行成功表示有候选文件，人工采用表示该文件经过对应版本复核；取消、生成失败、未采用都不是已采用。未知执行结果要继续回查，不能以网络超时作为重复扣费的理由。原图拼版交付可继续业务，但任务仍保留真实失败或降级原因。

报价草稿通过预检后锁定当前 `fq_quote + fq_quote_combo + fq_quote_detail` 为已确认版本；修订复制为新的 quoteId/versionNo。失效/作废与原金额分开保存。导出从排队进入生成，成功必须存在可读且可下载文件；失败重试使用同 `confirmedQuoteId + quoteHash + rendererVersion`，成功文件不能因另一记录失败被清除。

### 5 2 并发与幂等设计

生产批次发布用数据库事务比较 `baseDataHash + scopeHash + rowVersion`，当前商品价格或库存行的批量更新与导入明细状态在同一事务完成。价格批次和库存批次彼此独立，不人为制造跨资源实时一致承诺；同一商品价格范围或同一仓库重叠库存范围的并发发布只允许一个符合预期基线的请求成功。

方案保存用乐观锁；另一用户或标签页更新时返回冲突，保留用户本地副本。原型至少用工作区revision和存储变更检测展示冲突；单机存储无法作为多用户数据库锁，生产必须重复验证。

图片及导出请求使用“输入内容版本 + 请求意图 + 幂等键”去重，用户主动增加候选使用新意图。首期供应商状态使用轮询；若以后启用回调，须先补齐回调原文、事件幂等、保留和重放设计。队列重启后依据持久化记录恢复；最多两次自动重试、退避和人工处理入口，避免无限请求及无限费用。局部失败只重试失败项。

## 6 视觉交接和导出设计

原型视觉使用统一侧栏、页标题、状态标签、主/次操作、表格、抽屉/弹窗和空态，重点展示商品与方案比较。商品卡的款号、颜色、可售量和价格可读；组合页体现1–4个清楚槽位，锁定、替换及错误反馈就近呈现。主要动作有实际状态/文件结果，不用仅提示“成功”的按钮替代实现。

图片对比视图同时显示输入原图与候选图，逐项复核与版本状态可见；缺件、变款、禁用、来源为样例均不能只靠颜色提醒。费用与耗时标签按任务来源显示真实语义。报价页显示税口径、模式、SKU数量、折扣、费用、有效期和阻断原因，不能让大总额遮盖计价基础。

导出模板从已确认报价三层记录建立页面数据，再生成16:9 PPTX。标题、正文、报价表以原生文本/表格输出；图片按原比例contain，不能裁掉四品类关键物件。表格超出可用高度时自动续页并重复表头，长标题换行并限制最小可读字号。模板预览使用同一份页面数据；PPTX解析检查、缩略图或浏览器预览仍不能单独证明PowerPoint/WPS兼容。

文件命名包含方案、报价版本和日期，图片ZIP带图片清单；客户文件只投影对客字段。生成前核实所有引用图片可读取，生成失败不下发0字节或假扩展名文件。原型产物可加清楚的示例标识，生产模板通过已确认企业配置替换示例联系方式。
