## 2. 全局实施边界

### 2.1 产品定位与首期完成口径

本系统是企业内部销售使用的“服装选品、搭配、报价与文件交付工作台”，服务团购/批发客户。它从企业维护的 SKU 商品、当前销售价、当前库存和已授权图片出发，经过客户需求确认、一至四品类候选、图片复核和确定性报价，最终交付可编辑 PPTX 及配套文件。AI 只生成结构化草案、候选、解释和图片，不拥有客户、商品、价格、库存、正式报价或写入权限；Java/MySQL 是唯一业务控制面和事实源。

P0 完成口径是内部人员能在生产候选环境走通“商品/数据 → 客户需求 → 搭配 → 图片 → 报价确认 → 文件交付”，并取得权限、事务、恢复、容量、真实 Provider 试点及 UAT 证据。客户自助 Portal、移动端、订单/支付、ERP 实时同步、自研京东扩展、多客户/渠道价、超过四品类和自动发布均不在首期。

P0 单主 MySQL 使用一个规范化应用命名锁 `fashion:{database}:catalog-write` 保护所有商品资料/主图、当前价格、当前库存的发布与人工修改，以及报价确认时的最终重读。公共 `FashionCatalogWriteLock` 在 `IMP-02` 建立；解析文件、AI 推理和外部调用必须在锁外完成。锁定连接按“获取锁 → 完成 commit/rollback → `afterCompletion`/显式连接封装释放”执行，禁止提前释放；后续各阶段不得自创不兼容的锁名或顺序。
