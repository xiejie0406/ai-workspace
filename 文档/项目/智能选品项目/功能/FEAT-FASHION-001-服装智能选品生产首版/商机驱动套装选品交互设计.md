## 1. 本次修订结论

第一步直接看到商品筛选面板，同时配置1～4个品类。客户需求识别是筛选页的可选辅助：粘贴原文→预览建议条件→应用；不是独立必经步骤，不会覆盖已修改的条件。

第二步展示各品类候选主SKU的笛卡尔积方案池，支持成百上千方案的分页、检索、排序、跨页勾选和比较。第三步整理选中的方案，通过独立按钮打开模特试衣或PPT交付弹窗。保留客户需求和方案版本关联。

v0.1 中“三套推荐卡为主”“先识别才能筛选”“尺码供货确认后才能导出一切PPT”不作为本轮设计依据。正式报价要求仍保留，但选品提案PPT不必等同于正式报价。

本轮只修改设计、规格及任务范围，不改业务代码、不迁移数据库，不启动真实生图或导出任务。

## 2. 商品层级与展示单位

用户已确认：方案列表仅展示主SKU，颜色款/尺码不得把同一主SKU扩成大量重复方案。

**用户已确认模型**：一个款式一个主SKU，下面关联不同颜色和尺码。正式身份关系按此设计，方案池不按颜色款重复展开。

| 层级 | 职责 | 页面展示 |
|---|---|---|
| 主SKU | 组合身份、商品名、主图、品号、货号、品牌及分类 | 方案池每个品类一格，只显示主SKU资料 |
| 颜色款 | 颜色图及关联尺码；属于主SKU | 默认收起，在方案详情/试衣素材中选择 |
| 尺码SKU | 实际库存、仓库、价格明细和订货标识 | 展开库存/报价时使用，不参与方案池重复展开 |

品号、货号、主SKU编号分别保留，不擅自认定是同一个编码；支持精确查询和批量粘贴，前导零按文本处理。主图与选中颜色不同时，方案详情显示颜色图；PPT与试衣使用同一份已确认素材快照。

### 筛选字段完整清单

| 分组 | 条件 | 交互与口径 |
|---|---|---|
| 分类 | 三级分类直接多选 | 可搜索叶子名称；选项附完整路径区分同名分类，不要求先选一级二级；同一组多选是并集，组与组做笛卡尔积 |
| 基础属性 | 适用季节、性别、品牌 | 多选；同字段内OR、不同字段AND；不限与未知不同 |
| 编码与名称 | 品号、货号、主SKU编号、商品名关键词 | 编码精确/批量匹配，名称模糊搜索；分别有可见标签 |
| 商业价格 | 团购价最低/最高、VIP价最低/最高 | 两套独立字段；填两套时同时满足，标签汇总明确显示AND；缺失不是0 |
| 库存 | 仓库、可售数量最低/最高、有货/零库存/未知、更新时间/有效性 | 数量为所选仓库内满足颜色尺码约束的子SKU可售量汇总，每个SKU只计一次；未知项单列 |
| 颜色与尺码 | 颜色多选、尺码/制式、齐码要求 | 限定子SKU集合；要求齐码时每个指定尺码都有满足条件库存才通过 |
| 服装属性 | 风格、面料成分、版型、适用场景 | 属性不足明确为未知，不能暗中当匹配 |
| 资料可用性 | 上下架状态、有主图、图片已核对、分类已映射 | 默认仅有效商品；缺图可查看，选入需提示后续补图 |
| 套装条件 | 价格口径、整套总价区间、数量（可选） | 价格口径决定整套计算和排序；不能混用某件VIP价和另一件团购价 |

公共条件只在点击“应用到各品类”时写入；有单独修改的品类弹出差异预览，允许跳过，避免悄悄覆盖。每个品类可复制条件、清空条件；减少品类数先提示该品类条件保留但不参与本次计算。

条件编辑后显示“尚未应用”；匹配数量仍标明上次计算时点。点击预览/生成采用同一版本，不把旧计数当当前。某品类结果为0时准确定位，停留筛选页，不生成空任务。切换1～4类不会自动采用递进档位，默认只生成当前所选类别数的组合。

主SKU下价格不一致时显示区间；指定价格范围时，只有至少一组实际颜色/尺码取值满足条件才可纳入，保存其可用变体范围。未定颜色/尺码不宣称固定总价；按区间展示，预算验证区分“全部可选变体符合”和“仅部分符合”。库存汇总不意味着任何尺码都够，也不意味着已预占。

## 5. W2 方案池：真正的组合列表

设第i个品类筛选后的去重主SKU集合为Aᵢ，原始方案空间为 A₁×…×Aₖ，k=1…4。例如18×24×10×6=25,920套。先按单品条件缩小集合，再检查整套价格等约束；页面分别显示“原始组合数”“满足整套条件数”“已选数”。精确结果数计算中则显示“计算中”，不能编造计数。

```text
方案池  原始25,920套 / 符合条件8,460套 / 已选12套  [返回修改筛选]
[主SKU/品号/货号/名称检索] [整套总价] [库存状态] [已选/全部] [按总价升序▼]
[选择本页20套] [选择当前结果全部8,460套] [对比已选] [查看已选12套]
□ 编号  上装主SKU（图/名称/编码） 下装主SKU  鞋主SKU  帽主SKU 团购合计 VIP合计 库存摘要 操作
□ P001  外套M001                 裤M102      鞋M203   帽M304  368       340      待核实   详情/选入
…
每页[20/50/100]  上一页  1 2 3 … 下一页       保留跨页选择
```

- 默认表格列表，品类作为动态列；第一列勾选和右侧动作固定。图片可放大，长名称可展开，详情抽屉不打断列表位置。
- 可以切换缩略卡片视图，但不是仅输出少量“推荐”替代全部方案。排序只改变顺序，不丢掉合法组合。
- 组合身份按品类位置及主SKU ID构成；颜色尺码不重复展开。重叠分类默认禁止同一主SKU占两个位置，并展示被排除数量；同一集合的重复编码先去重。
- 按稳定次序分页/游标读取，不能在浏览器同时渲染数万行，也不能只截前N项冒充全量。更大组合量显示预估和后台计算进度，可取消/缩小范围；技术限制必须显示范围与原因。
- “本页全选”与“全部结果全选”是不同动作；全选全部显示准确范围及数量，排除个别项仍跨页保留。改变过滤范围不会静默扩大已选集合。
- 建议对比一次2～4套；更多已选留在已选清单，不要求重新勾选。支持固定某件主SKU后缩小其他品类组合，保留筛选条件可撤销。
- 返回修改筛选会创建新方案池版本；旧已选保留，标记哪些不再符合，用户决定移除或保留为旧版本，不能把新旧池混成同一事实。

每次商品/选色/图片变化使关联试衣图失效，提示重生成或改用商品原图，避免图物不符。无权限的价格类型在页面、PPT字段选择和文件内容中均不可见。

                                                   [更换颜色/图片]

任务：排队/生成中/待复核/已采用/失败       [取消未开始任务] [只重试失败]

- 使用已有模特库或有权使用的上传照片，展示模特缩略图和名称；明确每套使用哪一个模特。可对多套使用相同模特，一套多张结果可选择采用图。
- 必须使用当前所选商品/颜色图；缺图、无法识别服装区域等先提示对应商品，用户可修正再提交，不把灰框当输入。
- 开始前显示套数、模特数、预计生成张数。若真实调用涉及收费，在已有授权额度内执行，超出时才请求批准；服务不可用直接说明，配置留在管理入口，销售不必填写技术参数。
- 批任务部分成功可先复核成功项，重试只包含失败项。取消时明确哪些任务已开始且仍可能返回，避免误称全部取消或零费用。
- 逐图人工核对款式、颜色、件数、标识及变形；未复核不得当作已采用。试衣图属于AI搭配效果示意，不是实际合身保证。
- 成功结果与主SKU、选色/子项、模特及输入图版本绑定；切换商品、颜色、模特或图片后旧结果标过期。
- 不生成或生成失败时仍可由用户选择“商品原图提案PPT”；必须明确图类型，不能称作已完成试衣。本轮线框仅提供状态示例，不生成真实模特照片。

### 导出规则

- 默认每套一页，商品多或名称过长自动续页；一到四类均可。商品名称与商品图片为核心内容，不允许偷偷省略缺失项。可选封面和对比页，方案顺序与已选清单一致。
- 若用模特图，采用“大模特图＋商品图清单”布局；每张商品图明确对应名称与主SKU。未采用/过期模特图阻断该模式，但可由用户切换到原图模式。
- “选品提案”允许尺码人数未定，可不显示价格；选择价格后缺价要提示修复或显式切换不显示价格，不把0或其他价替代。标注参考价格与数据日期，不冒充正式报价。
- “正式报价”沿用实际SKU数量、费用、税口径、有效价格和库存时点复核；不能把主SKU合计库存当成每个尺码可供量。此为独立后续确认，不阻断正常选品提案的图片PPT。
- 可编辑商品名称/标题/表格，图片嵌入文件，不能整页截图冒充PPT。费用/内部备注/成本不进入隐藏层、备注页或元数据。
- 生成采用固定已选版本及图片版本；途中资料变化只提示，不混合新旧。任务可后台继续，重复点击不重复创建；失败保留配置并重试。
- 大量方案先展示预计页数；按服务实际限额明确分包，每包方案范围与序号可追溯，不静默截断或漏出已选方案。

## 9. 端到端操作示例（设计数据）

1. 选3品类：上装、下装、鞋；分别填秋季/性别/品牌/团购价/库存条件，保留品号和货号快速定位入口。
2. 三组筛选结果10、12、8个主SKU，方案池为960套原始组合；修改整套总价后明确显示符合数量。
3. 第一页选两套，第二页再选一套，已选持续为3；按团购总价排序不丢选择。
4. 查看三套，指定颜色与图片；对两套使用同一个模特试衣。
5. 第一套复核采用；第二套错色不采用并重试。第三套暂用商品原图。
6. 导出设置选择3套，采用图可用的页面用模特＋原图，其余明确选择原图；预览名称、图片、主SKU和选定价格，生成并下载PPTX。

## 10. 全状态与恢复矩阵

| 环节 | 异常/边界 | 用户能做什么 |
|---|---|---|
| 筛选 | 最低高于最高、价格缺失、无分类映射 | 就地提示，保留其余条件；查看被排除商品 |
| 组合 | 任一品类为0、组合极大、计算失败 | 定位空品类、缩小筛选、取消/重试；已选仍保留 |
| 分页 | 翻页/排序/刷新 | 选择按稳定组合身份保留；恢复到保存的池版本 |
| 数据 | 新价/库存/商品状态改变 | 显示差异并复核；历史已导出文件保留原快照 |
| 选中 | 全部结果全选、取消单个、范围改变 | 明确作用范围及排除项，不只选当前加载行 |
| 试衣 | 无模特、缺图、失败、部分成功、取消 | 定位输入、只重试失败、采用成功项、切回原图提案 |
| PPT | 缺图/缺价/过期图/无权限/过大 | 跳转修复、切换允许的内容模式、明确分包；不悄悄降级 |

## 11. 线框实现与交接

沿用后台桌面习惯：横向筛选行、表格、弹窗、批操作栏。默认每组占一整行，条件按多列横向排列，窄屏在本组内换行，方案表格局部横向滚动；已选数和下一步动作持续可见。键盘焦点可见，标签不依赖颜色；弹窗可取消、可关闭，操作状态有文字。

线框具备可操作的1～4类切换、逐类条件编辑、三级分类直接多选、主SKU候选预览、笛卡尔积分页、排序、跨页勾选、已选列表、方案详情与颜色、试衣状态示例和PPT内容预览。所有数据为合成设计数据，图片为示意图框；试衣与导出不调用真实服务，不能用线框替代验收。

当前明确要补的真实能力：主/子SKU关系与编码映射、团购/VIP独立价、分类与库存查询、完整方案池、跨页选择保存、模特及试衣任务、选品提案PPT与正式报价的分离。具体字段与接口在技术设计定稿后编码。

## 13. v0.3 用户批准与弹窗行为

用户明确认可v0.2业务方案，并要求横版筛选、仅三步、分类多选、模特图和PPT使用独立按钮。以本节及上文修订为当前交互基线，保留价格、身份、分页、试衣复核和文件真实性要求。

- 横版指每个筛选组占整行，季节、性别、品牌、价格等从左到右排列；组数为1～4，组内条件可折叠，避免四张纵向长卡。方案池继续使用横向表格。
- 分类直接搜索/多选三级叶子；组内取并集、组间取笛卡尔积。空分类明确显示未选择并阻止生成；同名分类展示路径用于区分。同组重复主SKU去重。
- 已选方案页保留“模特试衣”“PPT导出”按钮，也可从单套行操作打开并预选该套。按钮不增加步骤。
- 大弹窗承载任务列表、输入和结果，顶部固定标题和关闭按钮。关闭只是收起，不取消已提交后台任务；重新打开恢复当前进度。用户若取消任务须单独点击取消并查看影响。未保存的表单离开时提示保存/放弃。
- 弹窗支持Esc、焦点圈定与回到触发按钮；需要补商品资料时可在子弹窗处理，关闭后回到原任务。PPT缺图可跳转试衣弹窗，完成后保留导出设置。
- 当前线框的试衣/PPT仍为状态示例，业务编码按[多智能体执行计划](任务清单.md#157-多智能体编码计划)推进。
