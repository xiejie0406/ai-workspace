### 2.3 已发现缺口与修复

独立交叉复核和实际运行发现并修复了这些实质问题，保留失败证据后只复验受影响范围：

- 发布库残留 `process.env.NODE_ENV` 导致浏览器启动失败；非空文档的图层误识别为素材导致会话无法打开；revision=0 选区不能恢复；同实例切换会话可能串用旧选区/请求。最终技术浏览器已看到非空正式 DTO 的完整画布与整层工具。
- 付费调用结果不明在批量内部被误记普通失败；已知供应商异步任务的轮询/下载错误未保留原任务。现保留任务号并仅查询原任务，未知结果禁止自动重新 POST 或批量重试。
- ZIP 当前素材丢失画布编辑、65–200 成功输出无法完整打包、manifest 缺 ratio/会话等原字段。现冻结并渲染当前文档，导出最多 200 引用，原清单字段与非标准比例均有定向检查。
- 内部分割小图层被用户上传 32px 下限拒绝；现私有图层允许最短边 1px，用户上传仍保持 32px。真实 MySQL 综合检查已验证 8×10 图层产物。
- 全局异常 Advice 先于图片错误处理，导致实际 HTTP 错误丢失状态/errorCode；图片 Advice 仅限定本模块并优先处理，其他错误继续共享兜底。
- 服务端冻结选区不能沿多步普通修订使用、客户端伪造 selection_markers、错误一小时 TTL、重试漏查细分权限、到期租约可被心跳复活；分别改为冻结宽高核对、服务端注入、原 24 小时 TTL、重新检查工具权限、拒绝过期心跳。
- 批量失败再次重试同 key 可能重复派发，以及 Agent 批量部分成功/未知结果的关联恢复，已修复并通过定向单元及真实 MySQL 检查；原 batch 与成功 item 保留，普通失败 item 才派新 run，同 key 回放不重复派发，递增重试次数不被新子 run 的 attempt=1 倒写。
- Pydantic default_factory 未进入跨语言 JSON Schema，使省略格式/投放比例/批量步骤参数时与原 DTO 默认不同；唯一注册表导出已通用补齐，5 项 Python 定向检查和 Java 缺省参数检查通过，工具契约指纹为 `553745b0f7053684454a41ac5c23cf3c75cddbc4301b4cf10e18f631c89941ed`。创作列表已按原行为排除内部 mask/subject/background，正式图片墙与文档仍保留这些图层，专门检查通过。
- 宿主最初的 mock request 检查未覆盖共享 Axios 的真实转换，独立复核复现 FormData 被 JSON 化。现沿既有 multipart 方式清空 JSON Content-Type 并关闭文件的 JSON 防重缓存；真实 Axios 和连续不同文件检查通过。文件接口 JSON 错误在显式 preserveBusinessError 范围内复用平台认证/结构化错误，主动取消不弹连接故障，未选择该行为的旧接口不变。
- Chrome 首次 multipart 复验已看到 boundary，但 request.postData 没有提供文件字段，不能据此记完整通过；随后临时观察实际 XHR.send（立即恢复原函数），确认收到 FormData 和原 File 名称/尺寸，同时网络请求具备浏览器 boundary、中心返回未认证 401。此检查没有登录或写入正式素材，仍不能替代真实账号上传业务验收。
