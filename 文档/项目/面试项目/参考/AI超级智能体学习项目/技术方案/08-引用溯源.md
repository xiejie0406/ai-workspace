# KnowFlow Phase 3 引用溯源设计

> 阶段：Phase 3 RAG 问答与引用溯源  
> 目标：让每个 AI 答案都能说明“依据哪份文档、哪一页、哪一个分段”。

## 1. 为什么需要引用

企业知识库的核心不是“回答像不像”，而是“答案能不能被相信”。  
引用来源用于解决：

- 答案依据不可见；
- 文档版本不清楚；
- AI 编造不可追责；
- 管理员无法判断知识库质量。

## 2. 数据关系

```text
kf_qa_log
  -> kf_qa_citation
      -> kf_document_chunk
          -> kf_document
              -> kf_knowledge_base
```

## 3. Citation 字段

| 字段 | 说明 |
| --- | --- |
| `qa_log_id` | 所属问答日志 |
| `chunk_id` | 引用分段 |
| `document_id` | 来源文档 |
| `citation_index` | 回答中的编号 |
| `score` | 召回相关度 |
| `used` | 是否被最终回答采用 |
| `snippet` | 引用片段 |

## 4. 前端展示

回答正文：

```text
超过 7 天的退货需要主管审批 [1]，质量问题除外 [2]。
```

右侧引用卡：

```text
引用 1：售后处理流程.docx
第 12 页 / 超期退货
相关度 0.91
片段：超过 7 天的申请需由客服主管审批...
```

## 5. 点击交互

| 操作 | 结果 |
| --- | --- |
| 点击回答中的 `[1]` | 右侧引用卡高亮 |
| 点击引用卡 | 打开分段详情 |
| 点击查看原文 | 跳到文档分段抽屉 |
| 点击未采用分段 | 管理员可判断召回质量 |

## 6. 验收

- 每条回答至少返回 0-N 条引用。
- 有引用时能打开来源分段。
- 无引用时明确标记为未命中。
- 日志详情能复现当时引用来源。
