# KnowFlow Phase 2 分段与向量化策略

> 阶段：Phase 2 文档入库与向量化  
> 目标：让企业文档变成可检索、可引用、可追溯的 chunk。

## 1. 分段原则

- 保留章节标题、页码、来源文档。
- 分段长度优先控制在 300-700 tokens。
- 相邻分段保留 50-120 tokens overlap。
- 表格和列表尽量不被切断。
- 每个 chunk 都能被独立引用。

## 2. 默认策略

```text
优先按标题切分
  -> 标题下内容过长，再按段落切分
  -> 段落仍过长，再按 token 切分
  -> 添加 overlap
  -> 生成 metadata
```

## 3. Chunk 字段

| 字段 | 说明 |
| --- | --- |
| `document_id` | 来源文档 |
| `kb_id` | 所属知识库 |
| `chunk_index` | 文档内序号 |
| `page_no` | 页码 |
| `title` | 章节标题 |
| `content` | 分段文本 |
| `token_count` | token 数 |
| `metadata` | 来源、标题层级、URL、表格标记等 |
| `enabled` | 是否参与检索 |
| `vector_doc_id` | 向量库文档 ID |

## 4. Metadata 示例

```json
{
  "sourceType": "pdf",
  "documentName": "售后处理流程.docx",
  "chapter": "超期退货",
  "page": 12,
  "chunkSize": 512,
  "overlap": 100
}
```

## 5. 向量写入

写入向量库时，向量文档内容建议包含：

```text
标题：{title}
来源：{documentName}
页码：{pageNo}
正文：{content}
```

这样召回后更容易生成引用说明。

## 6. 分段编辑

编辑 chunk 后：

1. 更新 `kf_document_chunk.content`；
2. 标记旧向量失效或覆盖；
3. 重新生成向量；
4. 更新 `vector_doc_id`；
5. 记录更新时间。

## 7. 验收

- 每个 chunk 都有来源文档、页码、标题。
- 禁用 chunk 后不会参与召回。
- 编辑 chunk 后能重新向量化。
- 回答引用能回溯到 chunk。
