# 模拟面试流程规格

> 文档状态：Draft；Feature：FEAT-INTERVIEW-001；版本：v0.3；更新：2026-10-01
> 需求依据：用户要求两个面试官与一个 Agent 做上下文交流，回应用户问题并在结束时总结。
> 唯一设计：[面试项目完整设计 2.0](../架构/面试项目完整设计.md#business)；本文只维护流程要求。

## 1. 用户流程

选择岗位、训练方式和输入方式，说明项目经历→明确开始→与 HR 和技术面试官持续交流→可以回答、反问、澄清和更正→明确结束→回看全场总结与复练建议。题库提供依据，固定题量不作为交流主进度。

## 2. 必须满足的行为

1. 两位面试官共享本场上下文，交接继续已有经历，每轮只有一个主要说话人。
2. 用户提问先得到相关回应；含糊内容先澄清，不能一律当答案后换题。
3. 用户更正保留原话并建立修订关系，后续交流及总结采用修订后的事实。
4. 默认交流训练可以解释相关概念；严格模拟仍保留其场内不辅导边界。有提示的内容不算独立掌握证据。
5. 文字和语音进入同一场、同一对话决策。默认连续语音：用户开始并授权一次后，面试官主动开场和自动播报，播报结束自动听用户回答；有效语音结束且最终识别成功后自动提交并回应。临时字幕不作为正式发言，短暂停顿可继续说；手动确认作为可选方式。
6. 模型或媒体失败保留已确认发言和当前话题，恢复不创建第二场、不重复消息。
7. 结束总结引用用户有效原话，区分 HR 与技术反馈，内容不足明确显示；不输出不可解释的综合总分或录用概率。

## 3. 必须覆盖的状态

准备、开场播报、听用户回答、等用户说完、整理最终识别、正在回应、用户输入/转写待发、打断、暂停、断线、失败恢复、结束草稿确认、总结生成、部分完成、内容不足和完成。

## 4. 验收要求

采用固定对话分别核对反问、混合意图、更正、模糊、不知道、重复提交、模型失败、语音失败、打断、刷新恢复和结束总结；正确结果及方法见唯一设计第10章。实际证据和用户接受另记既有功能记录，v0.1原文在设计清理备份中保留，不把旧逐题通过记录当新对话通过。
