## 1. 产品定位

面向有 1–5 年 Java 经验、准备转向 AI 应用或 Agent 开发岗位的求职者，提供岗位化题库、短时模拟面试和基于回答证据的改进反馈。

首版只验证一个问题：用户是否愿意使用更贴近 Java → AI Agent 岗位的训练产品，并根据反馈持续练习。

## 2. 首要用户与问题

**首要用户**：有 Java 后端经验，正在准备 AI 应用/Agent 岗位，备考周期 2–6 周的个人求职者。

**核心问题**：

- 不知道 Java 能力如何迁移到 RAG、Agent 和 AI 系统设计岗位。
- 题库零散，题目质量、难度和岗位匹配度不稳定。
- 能回答知识点，但讲不清项目取舍、失败和边界。
- 刷题后不知道薄弱项，也不知道下一步练什么。
- 通用大模型反馈缺少稳定评分标准和原话证据。

## 3. 首次使用结果

用户在 10 分钟内完成 5 道岗位相关题目或一次短模拟面试，看到逐题反馈，并获得下一次训练建议。

## 4. 首版核心流程

```text
选择目标岗位与方向 → 获取今日训练 → 回答 5 道题
→ 进行 1–2 次有依据追问 → 查看逐题反馈
→ 将薄弱项加入下一次训练
```

## 5. 首版范围（P0）

1. Java 后端、RAG、Agent、AI 系统设计、项目表达五类垂直题库。
2. 题目搜索、岗位/难度筛选、收藏和错题记录。
3. 文本短练习与文本模拟面试。
4. 有限、相关、可解释的追问。
5. 逐题反馈：结论、用户原话证据、缺失点、改进动作和参考资料。
6. 训练历史与下一次训练推荐。

## 6. 延后范围（P1/P2）

- 语音面试邀测：依赖独立 Feature 规格和质量验证。
- 简历/JD 自动生成计划、个性化学习计划、订阅支付。
- 多岗位、多语言、B2B、高级运营后台。
- Realtime 打断、视频分析、数字人和摄像头评分。

## 7. 明确非目标

不做真实面试隐蔽辅助、招聘筛选或录用概率；不承诺 Offer、薪资或就业结果；不做无限自由聊天式面试；不把题量本身当作质量承诺。

## 8. 关键需求与验收

| ID | 需求 | 验收条件 |
|---|---|---|
| REQ-01 | 用户可选择目标岗位和方向 | 进入训练前能看到岗位、方向、难度和预计用时 |
| REQ-02 | 系统提供岗位化训练 | 5 道题至少覆盖所选方向，题目有版本和来源 |
| REQ-03 | 系统支持基于回答的追问 | 追问必须引用回答中的具体内容或明确说明证据不足 |
| REQ-04 | 用户可完成一次短练习 | 中断、空回答、失败和主动结束都有明确结果 |
| REQ-05 | 系统生成可执行反馈 | 每道题包含结论、原话证据、缺失点和下一步动作 |
| REQ-06 | 用户可继续训练 | 用户能从报告直接开始针对薄弱项的新练习 |
| REQ-07 | 题库质量可治理 | 题目具备审核状态、Rubric、来源、难度和重复检查记录 |
| REQ-08 | 首次路径易理解 | 新用户 30 秒内能找到唯一主操作，关键状态有空态/加载/错误/完成设计 |

## 9. 成功指标（首轮验证）

- 首次训练完成率 ≥ 60%。
- 完成训练后报告打开率 ≥ 75%。
- 用户反馈“有用”比例 ≥ 70%。
- 7 日内再次训练率 ≥ 25%。
- 逐题反馈包含有效原话证据的比例 ≥ 90%。

这些是验证目标，不是已达成结果。

## 10. 未决项与阶段门

- 需要 5–8 名目标用户访谈，验证岗位定位和训练时长。
- 需要建立 Java、RAG、Agent、系统设计的人工标注样本，验证评分可信度。
- 需要完成题库首批样本审核和界面原型评审。
- 本文保持 Draft；用户批准后才进入原型和技术设计，不因文档完成而视为已实现。
