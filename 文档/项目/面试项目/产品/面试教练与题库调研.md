## 1. 决策问题

本轮需要决定：

1. “题库 + 模拟面试 + 评测复盘”是否构成可商业化的完整用户闭环。
2. 语音模拟面试应该选择端到端实时语音模型，还是 ASR → 文本 Agent → TTS 级联方案。
3. PaiCLI 中哪些设计经验值得借鉴，以及新项目必须独立重建哪些能力。

不在本轮决定中：最终供应商合同、具体价格、生产部署地域、数据库选型、支付渠道和实现任务。

## 2. 用户、场景与危险假设

### 2.1 目标用户假设

- 核心用户：有 Java 开发经验、准备转型 AI 应用/Agent 开发的求职者。
- 扩展用户：准备 Java 后端、AI 应用、RAG、Agent、工作流和系统设计岗位的开发者。
- 后续 B2B 用户：培训机构、高校就业中心和企业内部转岗培训团队。

### 2.2 当前替代方案

- 零散刷题网站/文档：知识覆盖广，但缺少口语表达、追问和持续复盘。
- 通用大模型聊天：生成问题方便，但评分标准、内容版本、证据和学习进度不稳定。
- 真人模拟面试：反馈质量高但贵、难约、难以高频练习。
- 通用语音教练：擅长表达反馈，但技术正确性与项目深挖未必适配 Java → AI Agent 转型。

### 2.3 危险假设

| 假设 | 为什么重要 | 当前结论 | 关闭方式 |
|---|---|---|---|
| 用户愿意持续完成 20–40 分钟模拟面试 | 决定留存与成本 | 待验证 | 5–8 名目标用户访谈 + 可点击原型 |
| AI 对技术答案的评价足够可信 | 决定核心价值 | 高风险、不能仅靠 LLM 自评 | 建立带来源的评分 Rubric、Golden Set 和人工复核样本 |
| 语音体验比纯文本显著提高付费意愿 | 决定 MVP 投入 | 有竞品和案例支持，但对本用户群未验证 | 文本/语音两版原型和付费意愿访谈 |
| Java 转 AI Agent 的垂直定位足够窄且有需求 | 决定冷启动 | 符合发起人自身场景，外部证据不足 | 访谈、招聘 JD 样本和落地页转化实验 |
| 用户愿意授权录音、转写和简历处理 | 决定数据方案 | 未验证且具隐私风险 | 明示同意、默认不保留原始音频、可撤回/删除的原型评审 |

## 5. 语音技术路线比较

| 方案 | 流程 | 优点 | 主要风险 | 适合阶段 |
|---|---|---|---|---|
| A. 端到端 Realtime | 浏览器音频 ↔ 实时语音模型 ↔ 工具/Agent | 延迟低、支持打断、轮次自然、语气更像真人 | 供应商锁定、成本与地域、评测可观测性较弱、与新项目文本评测链的证据边界需设计 | P1 高级语音模式 / 差异化体验 |
| B. ASR → 文本 Agent → TTS | 浏览器采音 → 转写 → 新项目面试 Agent → 文本答案 → 合成语音 | 借鉴 PaiCLI 的 Java Agent 设计经验并在新项目独立实现；易记录、调试、评分、替换 ASR/TTS/LLM；可天然降级为文本 | 端到端延迟更高；打断、VAD、回声消除需要额外工程 | **推荐作为 MVP** |
| C. 纯文本 | 文本输入 → 面试 Agent → 文本输出 | 最便宜、最稳定、无麦克风门槛 | 无法训练口语表达与临场感 | P0 必备降级与免费体验 |

### 推荐结论

MVP 采用 B + C：先实现可观测的级联语音链路，同时保留纯文本模式；第一版语音以清晰轮次为主，可使用按住说话/点击结束或可靠的 VAD，暂不把自然打断作为 P0。P1 再以 Provider Adapter 接入 A 类 Realtime 模型做 A/B 测试。

推荐理由：这条路线最适合在独立项目中重建可观测的 Java Agent 能力，也更适合作为“Java 开发者转型 AI Agent 工程”的作品集；技术答案评分需要可重放文本、Rubric 和证据，级联架构更容易验证和审计。

## 6. 机会与不采用项

### 6.1 采用

- 垂直切入“Java 后端 → AI 应用/Agent 开发”，而不是一开始覆盖所有职业。
- 把题库、模拟面试、复盘和学习计划串成同一闭环。
- 评价分成“技术内容”和“表达交付”两条轴，低置信结论显式提示。
- 题目、评分点、追问和参考来源版本化，避免只靠一次 LLM 生成。
- Provider Adapter 隔离 LLM、ASR、TTS 和 Realtime 供应商。

### 6.2 延后

- 视频表情/眼神评分：偏差、隐私和误导风险高，先不进入 MVP。
- 真实面试实时 Copilot：容易越过求职诚信边界，明确不做。
- 全职业题库、招聘方 ATS、自动筛选候选人：范围过大且合规要求更高。
- 端到端实时打断、多方群面、数字人形象：待核心闭环和付费验证后再做。

## 7. 证据缺口与下一步

- 尚无 5–8 名核心用户访谈；当前“Java 转 AI Agent”价值主要来自发起人场景，应在原型前补齐。
- 尚无独立第三方证据证明竞品宣传的就业/绩效效果；这些数据只作为方向性输入。
- 新项目与 PaiCLI 无源码、构建、运行时或发布依赖；任何代码级借用都必须另行做许可证、来源和维护边界评审。
- 尚未比较中国大陆可商用 ASR/TTS/Realtime 供应商的区域、数据处理、价格和 SLA；技术设计阶段必须以官方合同/文档复核。
- 尚未建立技术答案评分 Golden Set；实现前需要 Java、RAG、Agent、工作流各至少一组人工标注样本。
- 结论：继续，但缩小为垂直 MVP；进入原型前先由用户批准 Canonical Feature Spec。
