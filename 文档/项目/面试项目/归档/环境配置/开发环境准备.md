## 1. 独立项目边界

- 不要求启动、构建或配置 PaiCLI。
- 不读取 `~/.paicli/`、`PAICLI_*`、`FREELLMAPI_*` 或 PaiCLI `.env`。
- 不使用 PaiCLI Jar、Runtime API、SQLite、Provider 类或前端代码。
- 本项目未来只使用自己的 Maven/Node 工程、数据库、环境变量、Secret、端口和部署。

## 2. 计划技术基线

| 类别 | 推荐基线 | 用途 | 当前结果 |
|---|---|---|---|
| JDK | Java 21 LTS | 新项目后端与 Agent Runtime | NotRun |
| Maven | 3.9.x；后续创建 Maven Wrapper | Java 构建与依赖锁定 | NotRun |
| Node.js | 实施时的 Active LTS，锁定具体版本 | 独立 React/Vite 前端 | NotRun |
| npm/pnpm | 与前端锁文件统一，只选一种 | 前端依赖管理 | NotRun |
| Git | 当前稳定版 | 新项目独立版本历史 | NotRun |
| Docker Desktop | 设计批准后再安装/启用 | PostgreSQL、Redis、对象存储本地环境 | NotRun |

| S3-compatible storage | 本地可用 MinIO 等兼容实现 | 临时音频、简历和导出物 | NotRun |

## 4. 外部账号与能力

### 4.1 文本模型

至少准备一个新项目专用的模型账号/Key，并确认：

- Chat/Responses 类文本生成能力。
- 流式输出。
- Structured Output/JSON Schema 或等价可靠结构化输出。
- 工具调用是否需要；评测 Agent 默认不开放高风险工具。
- 模型 ID、上下文、限流、价格、数据地域、保留和训练条款。

不得使用个人共享 Key 作为生产方案，也不得让浏览器持有 Provider Key。

### 4.2 ASR/TTS

语音进入开发前分别核验：

- 中文、中英混说和 Java/AI 技术术语。
- 流式/分段能力、音频格式、采样率、最大时长和并发。
- ASR 置信/时间信息、TTS 首包延迟和音色商业许可。
- 价格、数据地域、日志保留、是否用于训练和删除 SLA。
- Key 失效、余额不足、限流、超时和文本降级行为。

### 4.3 Realtime Voice

端到端 WebRTC/Realtime 属于后续能力。只有级联语音、评测证据链和付费价值通过后才申请或接入，不作为环境准备 P0。

### 4.4 延后申请

- 支付账号：等待经营主体、地区、退款和发票规则确定。
- 邮件/短信：等待注册与通知功能进入任务拆分。
- 域名/TLS/CDN：等待公网试用环境批准。
- 企业 SSO：B2B 阶段。

## 5. 新项目配置命名

正式配置键将在设计/任务阶段确定；命名必须使用本项目独立前缀，例如：

```dotenv
INTERVIEW_DB_URL=<secret-or-local-url>
INTERVIEW_DB_USERNAME=<secret>
INTERVIEW_DB_PASSWORD=<secret>
INTERVIEW_REDIS_URL=<optional>
INTERVIEW_OBJECT_STORAGE_ENDPOINT=<optional>
INTERVIEW_LLM_PROVIDER=<provider-id>
INTERVIEW_LLM_API_KEY=<secret>
INTERVIEW_ASR_PROVIDER=<provider-id>
INTERVIEW_ASR_API_KEY=<secret>
INTERVIEW_TTS_PROVIDER=<provider-id>
INTERVIEW_TTS_API_KEY=<secret>
```

这只是命名方向，不表示变量已经实现。禁止复用 `PAICLI_*` 或读取 PaiCLI 配置文件。

## 6. Secret 与数据规则

- `.env` 仅供本地开发并进入 `.gitignore`；生产使用 Secret Manager 或等价服务。
- LLM、ASR、TTS、对象存储、支付和邮件 Key 相互独立，按最小权限和环境隔离。
- 不在源码、Markdown、命令历史、日志、截图、fixture 或 Git 中保存真实 Key。
- 未核验供应商数据条款前，不发送真实简历、录音、手机号、身份证或生产数据。
- 测试录音使用本人明确授权、合成或脱敏样本。
- 原始音频默认临时处理；任何保留都要有用途、同意、TTL 和删除 Job。

## 7. 本地基础设施计划

设计批准后可建立独立 Docker Compose：

| 服务 | 目的 | 首次实现是否必须 |
|---|---|---|
| PostgreSQL | 用户、题库、会话、报告、Job、用量和审计 | 是 |
| Redis | 多实例会话、限流、锁和热点缓存 | 原型可否，商业试用是 |
| S3-compatible storage | 临时音频、简历原件和导出物 | 语音/简历进入开发时 |
| OpenTelemetry Collector | 本地 Trace/Metric/Log 联调 | 联调阶段 |

不在设计批准前创建未经审查的数据库 schema、Compose、端口、默认密码或持久化卷。
