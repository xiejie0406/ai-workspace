优先级口径：

| 优先级 | 含义 |
|---|---|
| P0 | MVP 必须具备；缺失会导致题库、模拟面试、报告或安全闭环不成立 |

| OUT | 明确不做或当前禁止 |

## 1. 产品一句话与定位

为 Java 开发者转型 AI 应用/Agent 开发提供“高质量题库 → 文本/语音模拟面试 → 可解释评测 → 个性化学习计划”的闭环式 AI 面试教练。

产品不是简单的“AI 出题器”，核心差异是：围绕真实岗位能力模型进行动态追问，用版本化 Rubric 评价技术内容与表达，并让每次面试的弱项自动进入下一轮训练。

## 2. 用户、问题与核心场景

### 2.1 角色

| 角色 | 主要目标 | P0 权限边界 |
|---|---|---|
| 求职者 | 刷题、模拟面试、复盘并持续提升 | 管理自己的资料、会话、报告和删除请求 |
| 内容管理员 | 维护题目、分类、评分点、来源和版本 | 不能查看用户私密录音/简历，除非有明确授权的支持流程 |
| 运营/审计管理员 | 处理套餐、投诉、风控和审计 | 默认只看必要元数据；敏感内容访问需记录原因和审计 |

### 2.2 核心场景

1. 用户按岗位、技术方向和难度浏览或练习面试题。
2. 用户配置一场 20–40 分钟的文本或语音模拟面试。
3. AI 面试官按能力模型提问，并根据用户回答进行有限、相关的追问。
4. 面试结束后生成技术、结构、表达、证据和改进建议报告。
5. 用户把弱项加入训练计划，再进行专项练习或复测。

## 3. 目标、成功指标、范围与非目标

### 3.1 产品目标

- P0：让新用户在 10 分钟内完成首次题目练习或短模拟面试并获得可执行反馈。
- P0：让技术评分可追溯到题目 Rubric、用户原话和参考来源，而不是只有笼统分数。
- P0：语音不可用或用户拒绝麦克风时，完整降级为文本面试。
- P1：通过岗位/JD/简历生成更贴近目标岗位的面试计划，但不自动夸大或编造用户经历。
- P1：验证个人订阅付费；后续再验证团队/高校套餐。

### 3.2 拟议成功指标（待用户批准）

| 指标 | MVP 目标 | 说明 |
|---|---|---|
| 首次价值达成 | 新用户中 ≥ 60% 完成首个短练习并打开报告 | 漏斗指标，不等于学习效果 |
| 模拟面试完成率 | 已开始会话中 ≥ 65% 正常完成或主动结束并生成报告 | 系统故障和用户主动退出分开统计 |
| 反馈有用度 | 报告有用度平均 ≥ 4/5 | 必须允许“不准确”反馈 |
| 评测一致性 | Golden Set 上 P0 评分结论与人工 Rubric 一致率 ≥ 80% | 具体统计方法阶段 5/8 定义 |
| 7 日回访 | 完成首场面试用户中 ≥ 25% 七日内再次练习 | 用于验证持续价值 |
| 文本响应体验 | P95 首个可见响应 ≤ 3 秒 | 不包含供应商大面积故障 |
| 语音响应体验 | P95 首段可播放语音 ≤ 4 秒 | MVP 级联方案目标，Realtime 另设指标 |

### 3.3 MVP 范围

- 账号与个人学习档案。
- 垂直题库：Java 后端、AI 应用基础、RAG、Agent、工作流/工具调用、MCP、评测与安全、AI 系统设计和项目表达。
- 文本模拟面试。
- 级联式语音模拟面试（ASR → 文本 Agent → TTS）与文本降级。
- 动态追问、时间控制、暂停/结束与故障恢复。
- 可解释评测报告、错题/弱项和学习计划。
- 题目与 Rubric 内容管理、版本、来源和发布状态。
- 最小商业化：免费额度、个人 Pro 套餐的权益模型；具体支付实现进入后续规格/设计。
- 隐私控制：录音同意、数据用途说明、导出/删除入口和留存策略。

### 3.4 非目标

- 不做真实面试中的隐蔽实时辅助、答题提示或作弊工具。
- 不在 MVP 使用摄像头做表情、颜值、眼神、情绪或人格评分。
- 不自动替企业筛选、淘汰或录用候选人。
- 不承诺面试通过、Offer、薪资或就业结果。
- 不在 MVP 覆盖所有职业、群面、视频数字人、真人教练市场和 ATS。
- 不要求保存原始音频；默认策略倾向于完成转写后删除，最终保留期由隐私专项设计批准。

### 4.2 题库分类（首版）

1. Java 基础：集合、并发、JVM、IO、异常与语言特性。
2. Java 工程：Spring/Spring Boot、数据库、缓存、消息、微服务、性能与可观测性。
3. AI 应用基础：LLM、Token、上下文、Prompt、结构化输出和函数调用。
4. RAG：切分、Embedding、向量检索、召回/重排、引用、评测与更新。
5. Agent：ReAct、Plan/Execute、Memory、多 Agent、工具、HITL 和失败恢复。
6. 工作流与集成：DAG、状态机、MCP、浏览器/RPA、幂等、重试和补偿。
7. AI 评测与安全：Golden Set、离线/在线评测、幻觉、Prompt Injection、权限和隐私。
8. AI 系统设计：成本、延迟、容量、模型路由、降级、可观测性和供应商切换。
9. 项目与行为面试：项目闭环、难点、取舍、失败、协作和 STAR 表达。

每道题至少包含：稳定 ID、题干、类型、方向、难度、目标岗位/级别、核心知识点、参考来源与访问日期、标准答案要点、常见误区、追问模板、Rubric、版本、审核人和发布状态。

## 5. 主流程

### 5.1 题目练习

1. 用户选择方向、难度和岗位级别。
2. 系统展示题目；用户可先作答，再查看解析和评分点。
3. 用户提交文本或语音回答。
4. 系统按 Rubric 标记已覆盖、部分覆盖、错误和缺失点，并引用用户原话。
5. 用户把题目加入错题本/学习计划或开始相邻题复测。

### 5.2 模拟面试

1. 用户选择目标岗位、级别、主题、时长和文本/语音模式。
2. P1 可选上传/粘贴 JD 和简历；系统先展示解析结果并允许用户修正。
3. 系统生成面试计划：能力维度、题目数量、预计追问和时间预算。
4. 用户确认后开始；AI 每次只提出一个清晰问题。
5. AI 根据回答和 Rubric 决定：追问、提示澄清、切换主题或结束。
6. 用户可暂停、继续、跳过、主动结束；系统故障时保存已完成轮次。
7. 结束后生成报告和学习计划；低置信评分必须显式标记。

### 5.3 语音流程

1. 首次进入语音模式时展示麦克风用途、转写/模型供应商处理、是否保存音频和删除方式。
2. 用户明确同意后浏览器请求麦克风权限；拒绝则一键切换文本模式。
3. MVP 以清晰轮次为主：录音 → 流式/分段 ASR → 用户可见转写 → Agent 处理 → TTS 播放。
4. ASR 低置信或关键术语疑似错误时，系统展示文字并允许快速修正后再评分。
5. TTS 失败时仍显示文本；任一语音供应商失败不得导致整场面试数据丢失。

## 7. BR-* 业务规则

| ID | 规则 |
|---|---|
| BR-01 | 一场面试的题目、Rubric、Prompt/策略和模型配置都必须带版本；报告可追溯到生成时版本。 |
| BR-02 | AI 每轮只问一个主问题；追问必须关联当前题目/能力维度，并受追问次数和时间预算限制。 |
| BR-03 | 技术结论分为“正确、部分正确、存在错误、证据不足/待人工确认”，不得把模型置信感当作事实。 |
| BR-04 | 分数必须伴随维度、证据和改进建议；不得只输出无法解释的总分。 |
| BR-05 | 语速、停顿和填充词只能评价表达，不得据此推断人格、诚信、智力、情绪障碍或录用适合度。 |
| BR-06 | 用户未明确同意前不得启用麦克风或向外部供应商发送录音；同意记录必须可查询和撤回。 |
| BR-07 | 原始音频默认不作为永久学习资产；最终留存期、地域和删除 SLA 必须在设计阶段批准并展示给用户。 |
| BR-08 | 简历/JD 个性化不得编造经历；模型提取结果必须允许用户修正，未经确认不作为评分事实。 |
| BR-09 | 免费额度耗尽不得中途无提示终止已开始的付费/获准会话；开始前展示预计用量，失败需保留已完成内容。 |
| BR-10 | 系统不得在真实面试页面上提供实时答案、隐蔽提示、覆盖窗口或规避检测能力。 |
| BR-11 | 内容草稿不能用于正式评分；已发布内容修改必须产生新版本，历史报告继续引用旧版本。 |
| BR-12 | 管理员访问敏感会话内容必须最小化、显式授权并写审计；运营默认只能看到汇总和必要元数据。 |

## 8. 状态、失败、拒绝、取消与恢复

### 8.1 面试会话状态

`DRAFT → READY → IN_PROGRESS ↔ PAUSED → COMPLETING → COMPLETED`

补充终态：`CANCELLED`、`FAILED_RECOVERABLE`、`FAILED_FINAL`。外部供应商失败优先进入可恢复状态，不能直接丢弃会话。

### 8.2 必须覆盖的异常

| 场景 | 产品行为 |
|---|---|
| 无题目/筛选为空 | 展示清空筛选和推荐分类，不生成虚假题目数量 |
| 麦克风拒绝/不可用 | 说明原因并切换文本，不阻断面试 |
| ASR 低置信/技术术语错误 | 展示转写、标记疑点、允许用户修正后再评分 |
| TTS 失败 | 显示同内容文本，可重试播放或继续文本模式 |
| LLM/Agent 超时 | 保留用户回答与当前题目，有限重试后允许继续/结束 |
| 网络中断/刷新 | 回到最近持久化轮次，避免重复计费和重复提问 |
| 套餐额度不足 | 开始前提示；已开始且已授权的会话按 BR-09 处理 |
| 评价证据不足 | 产出“待人工确认/无法可靠判断”，不得强行打分 |
| 用户撤回数据同意 | 停止后续处理，按已展示规则删除或匿名化，保留必要审计元数据 |

## 9. 数据对象与隐私意图

| 对象 | 内容 | 所有者/可见范围 | 生命周期意图 |
|---|---|---|---|
| Question / RubricVersion | 题目、来源、答案点、追问、评分规则、版本 | 平台内容；管理员维护，用户只读已发布版 | 历史版本不可静默覆盖 |
| InterviewPlan | 目标、能力维度、题目计划、时长 | 用户私有 | 可删除；作为会话输入版本保存 |
| InterviewSession / Turn | 状态、题目、回答、事件和恢复点 | 用户私有；支持访问需审计 | 按用户设置/套餐保留 |
| Transcript | ASR 文本、用户修正、置信信息 | 用户私有 | 可编辑/删除；评分引用修正版本 |
| AudioArtifact | 原始或分段音频 | 高敏感；默认仅处理链路可用 | 倾向转写完成后尽快删除，最终规则待设计批准 |
| EvaluationReport | 维度分、证据、限制、建议和模型/规则版本 | 用户私有 | 可导出、可删除、可反馈 |
| Resume/JD | 可选个性化输入 | 用户私有、高敏感 | P1；单独同意、最小留存和删除 |
| Consent/Audit | 同意版本、时间、用途、访问和删除记录 | 用户可查询；审计角色最小可见 | 依法规与安全需要设定保留期 |

## 10. 评测报告规格

报告至少包含：

1. 会话摘要：岗位、范围、时长、完成状态和版本。
2. 能力雷达/列表：Java、AI 应用、RAG、Agent、工作流、评测安全等本场适用维度。
3. 逐题证据：题目、用户原话、覆盖点、错误/缺失、追问表现和低置信提示。
4. 技术内容：正确性、深度、边界意识、工程取舍和失败恢复。
5. 表达交付：结构、简洁度、例子、语速、停顿和填充词；仅语音模式展示语音指标。
6. 三项优先改进动作：每项关联题目或专项练习，而不是泛泛建议。
7. 用户反馈入口：有用/无用、评价不准确、隐私或内容投诉。

总分为可选展示，不得遮蔽维度差异；在 Golden Set 未达门槛前，产品应突出“练习反馈”而非权威判定。

## 13. 依赖、风险与阶段 5 输入

### 13.1 可借鉴的 PaiCLI 设计经验（不产生项目依赖）

- 借鉴 Java Agent/Plan/Multi-Agent 的职责分离思想；在本项目独立实现面试官、评测员和学习教练。
- 借鉴 Memory/RAG 的分层设计；本项目独立建设题库检索、用户弱项和历史进步，模型记忆不能成为题目权威来源。
- 借鉴 Runtime 事件和流式交互经验；本项目新建自己的 Spring Boot API、SSE/WebSocket 和 React 应用。
- 借鉴 HITL、权限和 AuditLog 的治理思想；本项目独立实现认证、授权、同意和审计。

### 13.2 新增能力

- 账号/租户、业务数据库、内容后台、订阅/用量。
- 浏览器麦克风采集、音频上传/流式通道、ASR、TTS、VAD/轮次控制。
- LLM/ASR/TTS/Realtime Provider Adapter 与成本/配额观测。
- 题目/Rubric 版本、评测 Golden Set、报告证据链。
- 同意、留存、导出、删除、供应商数据处理和合规审计。

### 13.3 阻断风险

- 参考项目暴露出的 `0.0.0.0`、CORS `*` 和前端本地 API Key 风险只能作为反面经验；新项目从第一天独立设计认证、会话、租户、CORS、密钥和部署边界。
- 技术答案评分存在幻觉与偏见风险；没有 Golden Set 和人工校准不得以“权威评分”宣传。
- 音频、转写、简历可能跨境或由第三方保存；没有供应商 DPA/地域/保留核验不得上线真实用户链路。
- 模型成本与延迟可能破坏单位经济；必须记录每会话音频分钟、Token、失败重试和成本。
- 题库版权与来源风险；不得直接抓取/复制受版权保护的商业题库全文。

## 14. 未决项与用户评审清单

1. MVP 是否坚持“Java 后端 → AI Agent 开发”垂直定位，还是同时覆盖普通 Java 面试。
2. 语音 MVP 是否批准采用“级联方案 + 文本降级”，并把端到端 Realtime 延后为 P1。
3. 是否把简历/JD 个性化留在 P1，以降低第一版隐私和范围风险。
4. 个人订阅是否作为首要商业模式；团队/高校是否明确延后。
5. 是否接受“练习反馈而非权威判定”的产品措辞，以及不做真实面试 Copilot 的伦理边界。
6. 原始音频默认转写后删除的方向是否符合预期；具体保留期进入隐私/架构设计再批准。
