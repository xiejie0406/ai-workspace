三、目标与非目标

目标：关闭当前工作区中仍阻碍“范围内实现 + A 包证据”的缺口，并形成一个可以进入 B 包实际数据库/联机验证的稳定基线。

目标链路：

`RuoYi principal/RBAC -> consent/preflight -> voice session/ticket -> WS start/chunk/stop/cancel -> controlled storage -> PostgreSQL Artifact/Transcript/version/execution -> user correction/confirm -> stable answer/next turn -> TTS state/chunk/cancel -> durable stream -> authenticated SSE replay/410/snapshot -> three clients recover`

非目标：

- 不新增第二个 Boot main、SecurityFilterChain、账号、Cookie Session、query token 或独立认证入口。
- 不删除、移动、重命名或归档旧 `backend/`、`frontend/` 和历史迁移。
- 不新增未经 OpenAPI/AsyncAPI/Approved 设计支持的 endpoint、event、状态、字段或权限意图。
- 不实现 Realtime speech-to-speech，不扩展报告、学习、支付或无关后台。
- 不猜云供应商、bucket/region、Secret、模型、voice、价格、保留期或数据出境条件。
- 不把静态 SQL、fake、Testcontainers、构建或截图描述为真实 PostgreSQL、真实 Provider、真机或 UAT 通过。

四、剩余任务顺序

### TASK-VOICE-REMAIN-01 当前差异与契约矩阵

- 形成 `operation/event -> controller/handler -> use case/port -> adapter -> schema -> client -> test/EV` 矩阵。
- 逐项核对 OpenAPI、AsyncAPI、REST、WS、SSE、主 React、Portal、Mobile H5/非 H5。
- 删除或修正只描述旧状态的活跃代码注释/UI 文案；历史记录不静默重写。
- 若必须改变公共 API/event/schema/权限意图，停止并退回阶段 5/6。

### TASK-VOICE-REMAIN-02 PostgreSQL 可达 SQL/schema 完整性

- 不只检查 `JdbcVoiceRepository`；列出从 voice preflight/session/confirm/snapshot/durable stream 可达的全部 JDBC SQL 和表。
- 核对 V1-V5 是否足以支撑真实 Voice 垂直链。重点检查 `catalog`、`billing`、`platform.job/idempotency/outbox`、`evaluation` 等被 Interview 创建、确认、恢复投影直接访问但新 Flyway 尚未拥有的最小事实。
- 在 `ruoyi-interview/src/main/resources/db/migration/` 仅新增后续版本；不得修改 V1-V5，因为其执行可能性未知。
- 保持 `BIGINT ruoyi_user_id`、tenant 隔离、不可变版本、乐观锁、幂等、sequence/cursor/retention 和删除约束；不得恢复 `identity.*`，不得建 PostgreSQL 到 MySQL 的物理外键。
- 增加 Testcontainers PostgreSQL migration/repository 测试；Docker 不可用时记录 Blocked，不以字符串断言冒充 migration Pass。

### TASK-VOICE-REMAIN-03 WebSocket 与 TTS 状态机收口

- 审查当前 `VoiceCaptureCoordinator`/`VoiceWebSocketHandler` 的最后差异，确保 client/server sequence、重复 ACK、gap NACK/resync、generation、codec、chunk/总字节/时长、背压、取消、断线清理、旧连接写入均符合 AsyncAPI。
- 证明 `client.tts.cancel` 可在 SPEAKING 期间被接收，停止后只改变 Voice execution/音频 Artifact，不改变 Interview Session。
- 证明 TTS `STARTED -> chunk* -> COMPLETED`、`CANCELLED`、`FAILED/degraded` 均有终态；无下一题、socket 已断和 Provider 未配置时不能停在 THINKING/SPEAKING。
- Provider 调用不得占用无界线程、无限重试或把 Secret/文本/音频写入日志。
- test-only deterministic ASR/TTS fake 必须只在 `src/test`，不得进入生产 profile。

### TASK-VOICE-REMAIN-04 长连接 SSE

- 当前 SSE 候选是有限 replay 后完成并由客户端重连；审查并改为真正有界资源的长连接：先 replay，再等待新 durable 事件，定时 heartbeat，断开清理，最大连接时长/空闲策略明确。
- 支持空 cursor、有效 `Last-Event-ID`、重复去重、顺序、过期 410/snapshot、无效/外来 cursor 不泄漏存在性、最大 replay 数。
- SSE 只发送 allowlist 中的 ID、版本、状态、计数和 reasonCode，不发送 Token、音频、完整回答/转写、Prompt、Provider/对象存储 Secret。
- 主 React 继续使用同一 RuoYi JWT 的 fetch stream；不创建第二套 session/ticket，除非已批准设计明确要求且重新获批。

### TASK-VOICE-REMAIN-05 主 React 完整接入

- 将 `VoicePreparation` 从“仅本地录音”改为真实使用既有 `useVoiceSocket`；不要平行实现另一套 socket state machine。
- Recorder 需要在用户手势后按服务端 chunk/window/duration 限制发送，不把完整音频写入 localStorage/sessionStorage/日志。
- 覆盖 hello、flow-control、ACK/NACK、ASR final、低置信编辑、ConfirmTranscript、TTS chunk/play/cancel、断线 snapshot 恢复、失败转文字和资源释放。
- 复用 `AudioPlayer` 或最小扩展，不在组件卸载后保留 Blob URL、MediaStream、timer、socket 或 pending chunk。
- 删除“当前不会建连或上传”等与实现冲突的活跃 UI 文案，但不得伪称已取得运行证据。

### TASK-VOICE-REMAIN-06 Portal / Mobile 对齐

- 复核刚写入但未构建的 Portal/Mobile H5 TTS 内存播放与取消；补齐 `COMPLETED/FAILED/CANCELLED`、播放拒绝、资源释放和 socket 关闭行为。
- Portal/Mobile 必须落实 server flow-control、ACK window、重复/乱序、总字节/时长/codec 限制，不能只发送 chunk 而忽略背压。
- 三端共享同一 reasonCode/状态语义；不复制互相冲突的协议常量。
- 非 H5 仅在 `uni.connectSocket`、录音文件分片和子协议认证可满足已批准契约时接入；否则保持 Blocked/文字降级，不把 H5 构建描述为小程序/原生通过。
