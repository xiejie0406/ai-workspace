# PaiFlow 逐模块核对入口

> 文档类型：模块选择与使用入口；日期：2026-10-05；维护者：Agent；适用范围：PaiFlow 已确定迁移与验收范围。
> 依据：用户 2026-10-05 要求每个业务模块单独固定报告，交付结果并汇报后明确开始下一个模块，沿既定目标继续。

本入口用于选择业务模块、找到要求及固定报告位置，不另维护项目长期状态。24 个业务组来自[完整迁移设计第 5 节](完整迁移设计.md#5-业务验收方法)，表内核对内容只是导航摘要，完整规则、正常与异常步骤仍以设计及适用要求为准；不能凭摘要删减验收范围。

设计写的是未来步骤，不是实际验收正文。[设计资料核对记录](设计资料核对记录.md#当前接续与登录循环修复)保存源码迁移和技术事实，不能当作页面业务通过。下表父组报告尚未生成；已建立的独立子模块正文及报告见表后入口。代码形式的报告路径是约定位置，不是已存在链接。

## 1. 怎样开始和继续

1. 选定一个独立业务模块，核对要求、现有实现、依赖、授权和已有证据，先说明该模块的完整流程与正确结果。已有唯一验收正文就继续沿用；尚无正文时，在该模块报告同目录建立一份 `验收记录.md`，首个业务操作前展示并保存清单。执行前再次核对现有文件，避免并行任务已建立正文后又另建一份。
2. 每个独立模块固定一份 `verification-report.html`，从唯一验收正文生成并原位更新。新增、编辑、查询、详情等属于同一模块的操作作为场景维护；跨模块流程按主要业务结果归属，其他模块引用已有步骤、前提和证据，不复制全量 24 组步骤或重复统计。
3. 按业务步骤操作，核对同一条记录或明确关联的一组数据从输入、提交、处理、列表/详情直到后续使用；每个有业务意义的页面步骤或状态保存实际截图并逐张回读。有效通过基线沿用，只复验受影响及未完成项；技术检查与业务结果、截图完整度、用户接受分开。
4. 完成、观察到失败或确定真实受阻后，更新该模块唯一记录与独立报告，按下列六项交付并明确“开始下一个模块：〈名称〉”，沿既定目标继续。相关项可安全修复时完成修复与定向复验；共享阻塞影响下一模块时如实说明，选择可独立推进的既定工作。
5. 不因等待用户接受硬暂停后续已授权工作。用户接受仍只由用户或其指定负责人决定；继续执行不自动增加服务启动、账号、真实业务写入、费用、数据库迁移、发布或 Git 权限。缺新决定时仅停止受影响动作。

当前“先不启动服务”的限制仍有效。真实页面业务验收缺少已运行且与待验版本相符的环境时，说明受影响步骤和恢复条件，不反复尝试启动，不用旧运行包或隔离测试冒充业务通过。已授权的隔离源码迁移、定向检查和安全修复继续，结果进入已有技术记录；已明确违反要求的实现保留失败/差距，不能统一改写为环境受阻。

模块交付和进度汇报统一说明：

1. **本模块范围**：本次承接的业务流程与正常、拒绝或异常分支。
2. **已完成项**：具体完成哪些步骤、得到什么产物；本次执行与沿用证据分清。
3. **未完成项**：具体哪些步骤未完成、原因、下一待验步骤及继续条件。
4. **当前业务结果与影响**：通过、未通过、受阻、未执行等真实结果及用户业务影响；技术检查、截图完整度和用户接受另列，不能相互代替。
5. **独立模块报告入口**：该模块固定报告链接；尚未生成时说明缺什么及恢复动作，不能给空报告或假链接。
6. **接下来开始的具体模块及前提**：明确名称、入口和必要依赖，不只说“继续完善”。

关键完成位置变化或用户询问时，也按当前模块简述已完成、未完成和下一步；不逐工具调用播报。模块交付是持续推进目标的一个完成位置，不自动暂停整个目标。

## 3. 可复制的执行指令

把下文的模块名称与接续模块换成上表名称，或让执行者按已有依赖选择；不需要为每个模块另开聊天。

```text
请从 PaiFlow 的“〈模块名称〉”继续，按逐模块核对入口和完整迁移设计第 5 节核对完整业务范围。先查该模块现有唯一验收正文和有效证据；没有正文才在约定报告目录建立验收记录.md，展示并保存完整清单，不复制全部 24 组步骤。

按同一记录或明确关联的数据逐步操作、截图、回读和核对业务结果。已有有效通过基线沿用，只复验受影响及未完成项。该模块单独固定 verification-report.html，从唯一记录生成，保留完整步骤、实际失败、受阻、未执行和继续条件；技术检查不能算页面业务通过。

模块完成、失败或真实受阻后，更新唯一记录并交付该模块报告，按六项汇报：本模块范围；具体已完成项及产物/沿用；具体未完成项、原因及下一待验步骤；当前业务结果与影响（技术/截图/接受分开）；独立模块报告入口；接下来开始的具体模块及前提。明确“开始下一个模块：〈接续模块〉”，在已有授权范围内继续，不硬暂停等待我接受。关键位置变化或我询问时也简述该模块进度，不逐工具播报。共享依赖受阻时明确影响并选择可独立推进的既定模块；我未明确接受不能替我记接受。大组可按独立职责缩小当前执行单元，但不能降低完整范围。

当前先不启动服务的限制继续有效。缺最新运行版本或真实验收前提时，说明具体受影响步骤和恢复条件，不冒充通过；已授权的隔离迁移、检查和安全修复继续。账号、数据库真实写入/迁移、费用、消息、发布和 Git 等仍遵守原授权范围。
```
