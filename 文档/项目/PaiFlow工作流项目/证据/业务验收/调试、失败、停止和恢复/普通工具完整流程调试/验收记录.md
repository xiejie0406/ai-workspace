## 2. 要求、原算法差异与场景覆盖

| 已确定要求与来源 | 本模块承接的结果 | 对应场景 |
|---|---|---|
| 设计第 5 节第 8 组：全流程输入输出、错误定位、终态一次 | 完成开始→普通工具→结束，输出能追溯到同次操作 | 第 1、2、4 项 |
| 设计第 3.4 节：固定引擎、版本及资源，原算法保真 | Python 和 Java 分别保留自身参数、输出和引用规则 | 第 2、3 项 |
| 设计第 5 节第 8 组：停止待确认不假已取消 | 已发送但未确认的操作保留未知；不自动重发 | 第 5 项 |
| 设计第 5 节第 8 组：同序号不重复、断流续读 | 从原游标继续，终态一次且不重新调用工具 | 第 6 项 |
| 设计第 1.1、3.4 节：身份、空间和操作边界 | 错误权限、版本或回执不得继续；私有材料不进入公开结果 | 第 3、4、5 项 |

原算法差异决定独立正确结果，不能把一种引擎的输出规则用于另一种：

- Python 参数位置使用原 Link 编码，Unicode 转义的 JSON 经 UTF-8/Base64 传递；空位置省略。业务参数遍历找到当前字典中的键后仍可能继续队列并被后续值覆盖。输出只取声明字段，缺值或类型不符采用原类型默认值。
- Java 普通插件保留原字面值和首个业务匹配，包括显式 null；保留整 Map 的额外字段、null 和实际类型，后续节点支持原数组索引引用。四位置及 body 默认规则沿用原执行器，不能改为 Python 投影。
- Python 完成帧在原节点帧中承载输出；Java 生命周期事实和原流帧分别承载事实及显示内容。两侧都必须关联同次中心运行，保留空内容开始／完成帧，不能将原整体结束帧当作 Worker 自定中心终态。

普通工具正式版本、工具市场、收藏、上架、复杂 OpenAPI、认证方案与全部工具参数规则归第 16 组“HTTP工具与工具市场”；这里只使用已经满足条件的固定版本并引用其结果。模型、数据库、知识、问答、迭代、子流程、Agent、MCP、RPA 和语音等节点分别归第 7、14—23 组，不因本流程可运行而记为已迁移或已验收。
