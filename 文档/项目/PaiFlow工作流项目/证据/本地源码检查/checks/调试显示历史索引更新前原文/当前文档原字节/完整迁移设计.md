## 1. 需求与业务逻辑

### 1.1 用户完成什么工作

用户在现有若依账号中进入“PaiFlow 工作流”，管理个人或团队空间中的智能体、流程、模型、知识和工具；通过可视化画布组合节点，调试输入和变量，查看逐节点执行情况，生成文字、结构化结果、图片或播客音频。调试符合预期后发布固定版本，供对话、API、MCP 和经授权的外部渠道调用。工作流、资源、运行及发布可以追溯到同一身份、同一版本和同一业务记录。

迁移范围包含原项目中具有页面、服务、执行器或可调用接口的全部业务能力，以及本设计明确列出的闭环缺口；分步骤建设只表示依赖顺序，不表示缩减为 MVP。原React前端、页面布局、画布、路由和状态管理直接保留，后端迁入`ruoyi-paiflow`；原身份请求接入若依认证，业务接口优先在后端兼容，不迁到Vue或逐页重做。仅在 README、SQL、文档中出现而没有实现的训练、支付、Go Tenant 等不宣称原有已实现；其资料状态和处理办法单列。

本文描述**目标行为与实施范围**，实际实现和检查事实见[核对记录](设计资料核对记录.md)。源码核对说明“有实现代码”“存在占位”或“缺资料”，均不代表实际运行通过；代码引入不代表全部迁移完成。未启动参考服务，未核实旧库、供应商账号、模型效果及渠道权限。

### 1.2 业务流程和允许条件

1. **进入与空间选择。** 使用若依登录、注册、用户、部门和角色；注册是否开放沿用平台配置。选择个人空间或成员所属团队空间，所有流程、资源、聊天和导出先检查资源归属。空间成员是业务资源关系，不产生第二套账号或平台角色。无权限时显示原因和返回入口，后台拒绝同一操作。
2. **创建与编排。** 从空白或原模板建智能体/流程，编辑名称、头像、说明、开场白、推荐问题与输入示例；节点输入可以是字面值或前置节点变量，文件类型和结构按节点契约校验。保存草稿不改变已发布版本；导入先预览资源映射、节点兼容和密钥缺口，不把包中的账号和凭据带入系统。
3. **调试与恢复。** 单节点调试显式填写前置变量；全流程调试固定草稿版本和模型/工具版本。问题回答节点可等待用户补充，恢复令牌只属于当前运行和用户。比较调试使用相同输入、不同快照，展示输出、耗时和用量。停止请求与真实执行终止分开呈现。
4. **发布与调用。** 发布前须通过结构、资源可用性、引擎能力和授权校验，并有该版本调试记录；调试记录仅为发布条件，不作为业务质量接受。发布不可变快照，恢复历史版本产生新草稿或新发布版本，禁止覆盖旧快照。渠道回读成功才显示已发布；失败、配置缺失和状态未知分别显示。
5. **对话与成果使用。** 对话支持历史、继续、重新回答、附件绑定/解绑、文件与音频播放、推荐问题和停止。下载、分享、API/MCP 调用均使用资源权限及有效发布版本。语音识别、语音评测、播报与播客合成保留各自输入和供应商失败提示。
6. **维护与删除。** 模型、知识、工具、数据表和 RPA 被发布快照引用时不可直接破坏引用；先停用新调用或建立新资源版本。删除空间需要显示成员、流程、发布和运行影响，停止新任务，归档资源；历史运行与审计按保留期处理，不连带删除共享平台账号。转让最后一个空间所有者须由当前所有者完成，不能留下无所有者空间。

### 1.4 全部节点与两引擎差异

Python 节点以 `core/workflow/engine/nodes/cache_node.py` 实际注册为依据；Java 以 `getNodeType()` 注册的执行器为依据。Java 的枚举列出更多节点，但 `node/impl` 只有 START、END、LLM、PLUGIN。`ParallelWorkflowEngine` 使用 cached thread pool；现有公开 Controller 注入 `WorkflowEngine`，不能声称公开调用默认已接入并行引擎，也不能从 README 推断使用 LangGraph4J 或虚拟线程。

迁移保留两引擎：Java 继续承担原四节点链路，Python 承担其注册的全节点。画布按所选引擎显示能力，已有复杂流程导入后推荐 Python；用户显式选择不兼容 Java 时拒绝构建/运行，不静默漏节点、不混合两引擎执行同一次图。Java 不支持的节点无需重复用 Java 重写才能算完整迁移，但 Python 全部能力必须接入中心且通过验收。Java 将有代码的并行执行器接入显式 `parallel` 模式并补限流和汇合测试；顺序模式兼容原链路。

| 编排者 | 创建/修改草稿、调试/导入/导出、资源绑定 | 权限如 `paiflow:workflow:edit/run/import/export`；空间资源版本同域 |
| 资源维护者 | 模型/知识/工具/数据/RPA管理与调试 | 各 `paiflow:<resource>:add/edit/remove/debug`；密钥读出禁止 |
| 发布管理者 | 固定版本、市场/API/MCP/微信/飞书发布与下线 | `paiflow:publication:publish/offline`，平台权限+空间内授权+渠道账号范围 |
| 空间管理者 | 邀请、成员变更、转让/归档 | `paiflow:space:manage`，不能提升自己的平台角色、不能绕过被移除状态 |
| 运维/审计者 | Worker状态、故障处理、日志与用量 | `paiflow:runtime:query/manage`，日志仍脱敏；管理员例外保留审计 |

按钮权限由 `sys_menu F`及后端`@PreAuthorize`维护；原React组件读取平台权限结果做局部可见/禁用处理，不使用Vue的`v-hasPermi`指令。若依入口与平台角色关系由服务器维护，原React菜单只呈现业务导航。Java获取 `userId`，不相信客户端 `uid/deptId/spaceId/appId` 作为身份。空间成员只进一步收窄已有平台权限，不能给无平台发布权限的成员自行授予发布。

原默认个人区以空或缺省 `space-id`、资源 `space_id IS NULL` 和当前 UID 表示，与具名个人空间分开。中心以每个平台用户唯一的隐藏 `default_personal` 域承载它，内部资源、版本与运行继续使用明确正 ID；legacy 返回原 `spaceId=null`，仅新增请求兼容辅助器把该值与原 store 的空字符串匹配。客户端空 ID 不等于任意已加入空间，也不能挑最近具名空间代替。默认域仅属本人且同时检查平台权限；不出现在具名空间列表/容量中，不开放邀请、转让、成员管理或删除。原默认智能体数量检查按当前 UID 全部未删除智能体计数（包括具名和团队中的本人记录），保留原 `count>100` 的拒绝条件，不改成单默认域计数。

默认域的只读查询不建记录；尚无物理表示时返回当前用户真实空目录，已知资源仍须实际存在。原 `visitSpace('')` 是写访问时间的明确操作，可在短事务建立内置域并记录默认个人访问时间；最近入口比较该时间与具名空间访问，默认个人较新时返回原 null。首次资源创建可随明确写操作建立该用户内置域的物理表示，WF/Agent 关系与正式保存保持原事务边界。模型先检查平台主体、纯候选形状及所需凭据/Provider/部署端口；缺端口时所有中心表零写。端口齐备后若需首次建立默认域，先以独立短事务完成，再在事务外取得批准与真实探测，最后按实际域 ID 和原条件 CAS 保存；探测拒绝可留下内置域初始化记录，但模型及版本零写，不能将初始化称为模型成功。无需新增原前端初始化流程或要求先建其他资源。上述为保留原默认私域的实施细化；旧 NULL 数据按已核实 UID 映射进入该域，孤儿 UID 继续隔离，真实导入仍须原库与数据授权。

API key 是业务应用调用凭据，限制应用、空间、发布版本/操作、IP/域名、限额和期限，不是平台第二登录栈；只返回一次明文，保存 hash 与 keyId，可撤销/轮换，禁止通过 API key访问后台账号管理。第三方 callback 不使用平台浏览器 token，独立受限入口做签名/回放/渠道绑定校验后转换为业务命令；权限决策仍由中心。内网 Worker 使用短期服务身份和 runId/lease/scope，不能借用户 token长期持权。

原 SQL **全表清单**和逐表归类位于[源码覆盖索引第6节](源码覆盖索引.md#6-原-sql-全表覆盖与迁移归类)。历史 `*_bak/*_copy/z-*`、无消费表不能当活跃事实源，先保全导出再确认；所有有真实数据的表必须映射、明确只读历史保留或经用户决定舍弃，不以未调用删除。表存在不证明训练、支付或外部服务已完成。

迁移拟按以下顺序执行，实施前另取得目标与数据授权：

1. 校验旧 MySQL/可能的外部 PostgreSQL实际位置与版本、字符集、时区、数据量、资源对象及拥有者；保存一致性备份和当前未提交源码/配置基线。只读采样脱敏，不把配置中的口令复制到文档。
2. 建 batch 和 UID/space/flow/tool/model/knowledge/app/object ID映射；同名账号不自动合并，孤儿 UID隔离为待认领。平台账号由已授权现有用户关联或按平台流程创建，密码/令牌全部重新签发。
3. 在指定原业务库建设增量 `paiflow_` 表；按身份映射→空间/成员→模型/工具/知识/数据/RPA→智能体/草稿→版本/发布历史→聊天/运行/对象顺序导入。每批保存源hash、源/目标计数、关系及JSON/对象hash对照，资源无法绑定进入冲突清单。
4. PG节点语法/字段、工具硬编码 ID和V1.0/appId、旧版本比较、文件URL、匿名分享和外部发布记录做显式转换。导入原“已发布”只作为历史声明，渠道重新回读并授权切换后才标当前可用；模型/语音密钥通过原托管引用迁接，不导出明文。
5. 停旧正式写入，最后增量导入并核对快照；切入口与运行派发后旧控制面只读。禁止两中心双写“同步一段时间”；Worker旧 DB用户撤权并验证无法读写正式表。
6. 回滚先停止新派发、冻结中心写入并导出切换后新增记录，再恢复指定旧快照/入口；若已产生真实外部副作用，先回读/补偿并由操作者确认，不靠恢复数据库假装撤销消息或RPA动作。新数据按差异合并方案恢复，不能整库回退覆盖其他项目。

建议保留运行元数据/脱敏事件90天、调试明细30天、分享7天可配置、正式文件随资源保留、审计按平台既有政策；需要用户审核数据保留和空间归档要求。备份频率沿用实际原业务库策略，切换前必须额外可恢复快照；建议发布切换窗口内 RPO=0（停写后最终校验）、控制面故障 RTO≤2小时，实际能力须用恢复演练证明，不能在设计中宣称已经达到。

### 3.4 中心 API 与 Worker 契约

公共标准接口根路径 `/paiflow`，JSON使用`AjaxResult`，列表用`TableDataInfo.rows/total`和`pageNum/pageSize`。保留原前端意味着它是明确的旧格式消费者：`/paiflow/legacy`兼容入口或网关映射覆盖源码索引第9节的全部实际业务调用，按各原调用返回code/data/message、分页、字段/ID和流事件，不强制前端改用标准信封。兼容Controller只映射DTO和调用同一业务Service，复用相同认证/权限/审计，不复制旧Hub或业务规则。维护原路径→兼容入口→中心接口→权限→响应fixture矩阵，对资料不足的原请求明确返回不可用及原因；账号、支付/训练等缺实现不因兼容要求恢复独立控制面或假成功。原外部消费者另登记授权范围，标准接口消费者不会收到legacy信封。

跨运行器机器契约维护在 `contracts/paiflow/`；现有[内部OpenAPI](../../../contracts/paiflow/internal.openapi.json)、[任务schema](../../../contracts/paiflow/worker.schema.json)、[事件schema](../../../contracts/paiflow/events.schema.json)和[问答检查点schema](../../../contracts/paiflow/checkpoints.schema.json)作为各消费者同一字段源。完整业务OpenAPI与DSL参数schema仍需随相关实现补齐，不以现有部分协议声称全部契约完成。Worker网关使用 `/internal/paiflow/v1`：

- **任务提交/领取：** 带schema版本、独立短期服务身份、不可变版本和运行资源范围。`dslCanonicalBase64`携带中心规范化UTF-8原字节；Worker对解码字节计算SHA256，并核对JSON内容与dsl一致，不按各语言的浮点/Unicode重序列化另算hash。verify响应的valid/租约元数据与严格assignment对象分开。Worker回能力清单、引擎构建版本和接受结果；未知契约/不支持节点在执行前拒绝。
- **执行前一次登记：** verify只核对当前快照和授权，不授予重复执行资格。Worker完成本地预检后，在进入原引擎前只请求一次`execution/begin`；中心行锁/CAS保存签发时间，首次ACK绑定run/lease/attempt/版本/hash。重复、超时、ACK未知或绑定不符均不得进入引擎，也不得由失败请求方提交终态。签发过许可只表示可能开始，不能证明节点或外部动作完成；中心继续按租约和正式记录核对。
- **心跳/事件/结果：** 中心校验租约与连续序号后落库；同seq同内容幂等确认，同seq不同内容或跳号拒绝。运行终态事件只由中心保存终态时生成；未派发取消的中心事件使用attempt=0和leaseId=center，Worker事件仍须有效attempt>=1。结果类型包含文字delta、reasoning、节点状态、用量、artifact、等待补充、错误和终态。Worker成功不能直接写 publication 状态。
- **资源与工具：** Worker凭运行范围读取snapshot、授权文档/检索或请求数据操作，拿短期工具凭据；禁止读取完整空间的秘钥/账号。Java同一次资源策略校验适用于Python agent、Link和Java plugin，不复制第二规则。
- **固定模型与逐次调用：** 原画布和客户端元数据保留；版本编译在独立 `resource_snapshots_json` 保存中心公开绑定，执行副本使用 `model:<modelId>:version:<modelVersionId>`。运行和每次模型调用分别取得中心批准，核对固定节点、运行输入及已落事件所能证明的消息来源。Worker只读公开描述和原始帧，不取得地址、凭据或私有许可；受控 SDK 桥使用准确版本材料，并在数据库事务外派发。没有真实批准、托管引用或 SDK 桥时明确不可用，管理页的 Hello 校验不代替费用许可。首批接入限定 Python 顶层 OpenAI 文本 chat，历史、嵌套、图像、FC 和 Spark 的原有能力仍须逐项接通，不能由这一限定删掉迁移目标。
- **模型幂等与结束事实：** 同一运行、attempt 和原始幂等标识保存同一操作，派发标记只取得一次；未知 ACK 不重新调用供应商。幂等标识支持原节点所需的 4096 字符，正文最多 2MiB；原帧逐项保留 null，单帧 64KiB、累计 10000 帧和 8MiB。真实结束帧先落库，随后接收用量尾帧；只有 SDK 流结束回执准确引用最后帧和结束帧才给完成。游标分页读到最后帧后给终态，允许空最终回执。停止必须保存准确操作的停止证明，本地连接关闭或布尔自报不能把未知副作用改为已取消。字段以[模型操作契约](../../../contracts/paiflow/model-operations.schema.json)为准，当前实现与检查结果仍由核对记录维护。
- **原画布编译与纯计算迭代：** 原 React 画布、节点字段和布局继续保存，中心只在执行副本中按原 Toolkit 规则转换类型、输出属性、分支句柄与重试配置。不可变版本单独记录编译规则标识；历史无标识版本按原规则校验字节与哈希；恢复原画布后，再创建的版本采用当前编译规则。先接通单层纯计算迭代：输入为已声明的根开始数组，节点各自归属主流程或一个迭代体，禁止交叉引用、环路、孤立节点和变量地址冲突；入队与 Worker 登记执行前均检查每批最多 64 项、图最多 128 节点、路径最多 128 条、单路径最多 64 节点、展开节点最多 4096。此批拒绝启用重试、模型及外部资源的迭代图；嵌套、共享上游引用、模型和外部节点迭代仍保留为后续迁移范围，不能计入已接通能力。
- **原问答等待与回复：** 先接通顶层静态直接问答和静态选项问答，沿用原模板、选项顺序、忽略与终止算法以及中心持久检查点。参数按原 Pydantic 的有效类型编译；历史执行副本的编译规则与字节保持可验证。启用模型处理的直接问答、历史与嵌套问答仍须另行接通；`needReply=false` 仍等待真实回复或到期，不自动代答。原页面的 `/workflow/chat`、`/workflow/resume` 和流帧通过薄兼容层对接同一运行、固定版本与检查点；普通 chat 没有固定版本令牌，必须先补可核对的 build→chat 关联，不能取最新版本猜测。缺关联令牌或 SSE 适配时明确不可用；需要 App/资源授权的节点另核真实绑定，不将静态构造兼容的空字符串视为 App。原生检查点接口不代表原页面已接通。
- **原调试构建与同次回执：** 在现有 WorkflowService 的校验、编译及不可变版本保存步骤中复用同一规则。普通 `/workflow/build` 在当前权限、空间与草稿 revision 保护下保存本次原画布，再固定调试快照；`/workflow/add-comparisons` 固定本次比较画布，保留当前草稿、选中版本和业务版本列表。调试来源在版本表新增独立 nullable 的 mode、发起者、比较标识、请求幂等标识、请求 hash 和实际 Agent 绑定字段；普通历史版本保留 null，不把可写 metadata、版本名或工作流 owner 当调试发起者。调试快照从普通版本列表、计数、最新版本、详情和恢复入口隔离。按同一发起者及请求标识查重，同标识不同画布、流程、条件或模式拒绝；失败时保存与快照一起回滚。响应仅给本次工作流标识、原空间表示、固定 snapshotRevision/ETag 和独立 `debugReceipt`；重复回执不回读较新草稿 revision。原 build→chat 调用链局部传递这份回执，普通与比较分支读取同一次状态；比较回执不提升草稿编辑条件。会话、空间、工作流或调试窗口切换后，本次上下文失效，不建立按 flowId 查最新构建的缓存。
- **原聊天、恢复与流：** `/workflow/chat` 重新核对回执的真实版本、发起者、空间和 Agent 绑定，再以固定版本、原输入和本次运行幂等标识调用现有 RunService；断线及重复 POST 附着同一 run，同标识不同请求拒绝。运行、任务、检查点和终态仍使用现有表，不另建调试运行真相。流先从原 TokenService 重核同一 JWT/Redis session，后台每批读取在独立 SecurityContext 中重新核对当前账号、菜单和成员，并在结束时清理；调度复用共享 scheduledExecutorService，连接数、单批事件和生命周期有界。短读取事务固定 run 的真实事件水位，按数据库 seq 顺序投影该水位内事件，SSE id 使用 runId:seq 并校验重连归属；被过滤的辅助事件只推进当前扫描游标。原消费者仍接收既有流帧，必要的检查点 revision 来自实际中心记录；首次回复前固定 revision 和回复 key，重复请求走同一 CheckpointService.reply 回执，再续读原 run。只有中心持久终态可以产生流程结束，等待、空 EOF、连接关闭和取消请求都不标运行成功。问答 abort 保留原 23802/FAILED 含义，其缺少 content 的旧请求只在精确 abort 类型补空串；普通停止调用现有 cancel 并核真实状态，停止和回复短请求独立于被关闭的流 signal。首批调试限定已核对的顶层纯计算及静态问答；模型、资源、历史和迭代流逐项接通，缺能力明确拒绝且不创建运行或外部操作。
- **单层纯迭代调试流：** 在已批准的纯计算迭代范围继续接通原调试页面，沿用原节点ID与流帧，不增加前端迭代展示或第二份运行状态。现有PureIterationPolicy的同一次结构分析同时提供节点归属和固定输入批次数；主图及容器事件不得携带迭代标识，内部事件只接受所属容器与规范批次序号，序号须小于本Run真实输入或原缺省数组的长度。新事件在写入和推进序号前核对，流投影读取时再核对；旧事件原文不重写，已存完全相同序号/内容仍按原租约和权限规则重取回执，不能据此新增非法事件。原两参能力门保持保守；取得固定Run输入后的入口才开放单层纯迭代。chat入队前校验真实输入，page、resume、cancel从实际Run取得固定输入，并核assignment的DSL、规范字节、hash、引擎和资源仍与本次回执快照一致。输出不伪造每批进度，也不施加原排序回调没有保证的全图串行顺序；原终帧与中心终态规则继续复用。嵌套、问答、模型与资源混合迭代仍按各自接续验证，不能用本批结果声称已就绪。
- **原工作流调试显示历史：** 直接接通原页面的 `POST /workflow/dialog`、`GET /workflow/dialog/list`、`GET /workflow/dialog/clear`，不修改原React页面、状态库或SID/SSE格式。显示记录由中心独立表保存，内部关联实际Run、固定调试版本、事件水位、空间与平台用户；它只保全客户端观察到的问答显示内容，不替代正式Run结果、审计、会话或Runtime记忆。新保存必须显式type=1、workflowId为内部正Long，SID为本人实际Run；复用既有构建回执、Run固定副本和当前Agent绑定校验，核对同空间/工作流/固定版本及当前账号、按钮权限、成员与发起者，旧空SID或Spark SID没有真实映射时拒绝，不猜最新Run。QA等待或运行中可保存，同Run/SID/chatId或相同内容的每次POST都追加，不加运行或内容去重键；只返回原chatId字符串（可null），不另建会话ID。question仅接受原输入数组或null、answer仅接受原显示对象或null，外层null与原JSON字符串中的null/falsy内容都原样保全；answerItem仅按原规则剥最外层双引号而不反转义。保存前校验实际MessageAsk/history消费者所需JSON形状、Unicode，以及独立20MiB显示请求预算和每字段16MiB减1字节的MEDIUMTEXT边界。原页面会重复JSON编码问题/答案显示项，该预算须容纳中心已支持的1MiB输入、2MiB结果及显示副本，不能把Run结果预算直接当作显示POST预算；现有Run预算不变，错误不吞为空成功。读取仍返回原13字段、本人type=1未删除记录的最近十条，以createTime倒序并用id稳定同时间顺序；清除保持原GET兼容并返回Integer受影响行数，修正原缺少本人条件的问题，仅软删当前用户在该空间/工作流的显示记录，不触Run、事件、结果、CP、取消或费用。缺type的查询在核权后返回空数组或0，type=2正式App历史仍明确503，其他类型拒绝。新增019 SQL仅作为本地可审阅草案，随机H2/MockMVC核查不证明真实库、联机HTTP或页面业务通过；正式会话、旧显示记录导入与真实身份映射继续各自处理。
- **原智能体输入类型同步：** 原调试入口的 `/workflow/bot/get-inputs-type` 读取真实绑定流程的原画布 Start.outputs，沿用原 Toolkit `BizInputOutput/BizSchema/BizProperty/BizValue` 的接口投影和 Hub `WorkflowInputTypeDto` 的12字段响应；投影仅用于本次响应及派生元数据，不改原画布中的未知字段、布局或字节。响应仍包含 `AGENT_USER_INPUT`，在元数据计算前排除它，保留该固定输入原有的空 schema、空 allowedFileType 等字段。工作流型智能体按原次序保存中心派生的 `extraInputsConfig`、`extraInputs` JSON 字符串及 `supportUpload`，保留文件首类型、旧首项选择、数组文件和未知类型的原限制；不能用执行副本的 JSONSchema 替换原数组协议。原指令型智能体表单的 `supportUpload` 及其非派生配置继续保全。空间→Workflow→Agent 的既有锁序、当前平台权限/成员和默认域所有权在同一事务核对，Mapper 的 revision 比较保护写入，回读的工作流 revision 同时记录为派生来源；客户端不得覆盖工作流型智能体的这三个派生字段，任何类型的智能体都不得制造派生来源字段。非固定输入的空 `allowedFileType`、缺少 `schema` 等无效结构明确拒绝并且不写元数据；这项边界同时保护原页面对 file/schema 的读取，具体原异常和新拒绝分别记录。它不创建 Tenant App，也不执行发布；正式 App 创建、API 发布与文件上传执行分别依赖真实端口和回执，不能由这份元数据标为已接通。15个原算法材料见[输入类型合同核对](证据/本地源码检查/checks/工作流原输入类型合同材料.json)，其中纯DTO/转换实际执行与Maas元数据源码推导分别记录。
- **断线/重连：** 浏览器按seq续读中心已落事件；SSE每15秒心跳、重连携最后seq，超保留返回快照与“部分流文本不可续读”。队列慢消费者按容量断开并可续读，不阻塞Worker。浏览器断开不自动取消真实任务。
- **错误：** 区分 `DSL_INVALID`、`ENGINE_UNSUPPORTED`、`RESOURCE_UNAVAILABLE`、`VERSION_CONFLICT`、`QUOTA_EXCEEDED`、`TOOL_POLICY_DENIED`、`DEPENDENCY_TIMEOUT`、`LEASE_LOST`、`EFFECT_UNKNOWN`；普通用户显示中文原因与恢复动作，日志保留关联ID而不泄露供应商secret。

### 3.5 运行、并发、恢复和副作用

运行状态：已排队→运行中→完成/失败/已取消；运行中可进入等待补充→运行中，取消请求先进入取消处理中。租约失联或外部副作用无法确认进入状态待核对，不能标成功/已取消。终态仅一次 CAS写入，重复回调不重复计费/注册成果；事件顺序与节点的并行完成顺序分别保存。

Java/MySQL保存队列与租约，Redis用于通知/短缓存，不另引入Kafka作正式任务源。原Kafka/OTLP日志链可保留为可选遥测输出，不依赖其决定业务成功。任务领取按 CAS锁定、租约心跳续期；崩溃超过租约期限后由中心核对节点/外部操作记录。只有中心已有可证明无副作用的恢复记录与明确恢复路径时才可考虑纯计算新attempt，当前一次性许可不自动重签；非幂等副作用转人工核对。持久队列恢复有最大次数和隔离列表，不无限重试毒任务。

每次运行和迭代有独立变量池，引用必须来自可到达的上游与已声明输出，数组/嵌套访问路径校验；并行分支输出按节点命名空间隔离，禁止两个分支写同一全局键无冲突策略。汇合等待可执行上游完成，未命中分支标跳过，错误分支按DSL明示；条件与消息节点不能导致提前结束。迭代输出按输入次序，最大次数/递归深度、节点总数与子任务预算有上限；子流程固定快照且取消沿调用树传播。

原 `retryConfig` 有 timeout/shouldRetry/maxRetries/errorStrategy/customOutput，迁移保留字段，补退避/可重试错误类型和幂等分类。默认普通节点60秒、纯读取最多2次退避重试；模型/TTS费用调用需供应商幂等或显式接受重复费用策略；正式数据写/RPA/外部消息不自动重试。默认单用户同时2个任务、单空间10个、Worker按容量限流；排队有超时和位置反馈。RPA原24小时超时不能作为全局默认，单独长任务上限与心跳；具体容量在实施压测后审核，界面不写死成功承诺。

问题回答节点把checkpoint保存到Java：DSL/版本、变量、待回答字段、已执行节点、用量、effect记录与expiry；恢复校验用户、版本与revision，重复token拒绝，不重放已完成副作用。原Java Controller中不存在恢复路由，原回调的恢复标志不能证明已有恢复API；Java引擎没有等价恢复实现时报告不支持，不以空响应假继续。

代码执行保留算法但改沙箱：独立受限进程/容器、只挂临时run目录、内存/CPU/时间限制、默认禁网与只读根目录；原 local executor不得在中心Java或用户主机直接exec。SQL通过解析与结构化操作、资源表映射和参数化，不允许任意拼接/平台表/多语句。RPA仅调度已登记位置与账号，不将节点中header全量写日志。

文件上传检查大小、真实mime、扩展名、病毒/内容规则按已有基线，URL导入在网关防SSRF、DNS重绑定、内网/本机访问及无限重定向；文件路径不接受任意磁盘位置。Markdown/HTML、OCR和模型结果经过安全渲染；检索文件/工具输出视为内容，不能改变权限或批准写入。模型输出类型校验失败记失败或明示回退。用户/空间配额由确定性规则扣用，模型推断不授予权限。

### 3.6 模型、知识、多模态、工具和渠道闭环

**模型与Agent。** 模型调用支持原OpenAI风格和Spark provider以及用户已有DeepSeek/Qwen等兼容配置，不假定全部参数兼容；能力目录标文字/图像/视频/工具调用/结构化输出。temperature/token/上下文参数按provider范围校验，密钥仅从托管引用解析。Agent保留OpenAPI runner、chat/cot/workflow runner、MCP/Link/知识/工作流插件，但bot_config由Java下发不可变快照。提示优化与模型生成头像/开场/代码/推荐问题都记录来源版本、成本和结果，用户确认后才写草稿。

**知识处理。** 原文件/HTML/URL→抽取→清洗/切分预览→用户调整→索引→检索测试，所有任务有Java状态/进度/重试记录。未提供外部知识服务时，Python处理Worker实现抽取及embedding接口，派生索引采用版本化文件/对象集合和manifest，可重建；不引入第二业务数据库。普通/专业知识库在同一资源权限下分别保留TopK、阈值、策略、重排/返回字段，不能因缺服务把专业节点别名成普通节点且不提示。来源片段、文档/offset可回查；被删除或撤权文档立即禁止检索，新索引完成前保持旧版本或显示待处理，不让半成品索引替换当前可用版本。

**HTTP/MCP。** 原工具OpenAPI解析、调试、临时版本、V1.0、appId与工具schema关联保留兼容映射；Java持有工具schema，Python Link不直接写tools_schema。消费MCP原SSE适配保留，目标新增传输按所选协议验证，环境参数通过secretRef、短期授权绑定；服务器工具schema变更列差异，已发布workflow不得自动跟随最新版本。原本地JSON MCP目录加载/缓存/分类/分页/详情迁为中心目录导入，逐条记录来源、协议、参数schema和可用性；不能把JSON中`authorized=true`当平台授权，也不能据目录内容自动在用户主机执行任意启动命令。HTTP工具公开/收藏/反馈由中心管理；临时工具不可发布引用。

**语音和播客。** 导入原AI播客模板，主题、听众、时长和风格→可编辑脚本→发音人/语速/供应商→生成MP3→播放器/下载/再合成。保留Qwen/Spark TTS、smarttts、RTASR、ISE、翻译、图片理解/OCR/生成的已挂载能力；未单独挂载的普通TTS client按统一能力网关暴露所需操作。发音人列表、speaker选择、自定义VCN绑定/启停纳入`/voices`，原无声线训练闭环时仅接受已获授权的供应商voiceId，不把配置CRUD写成已完成声音克隆。播报与合成成果分开；音频不是字符串URL就算成功，记录对象hash、mime、size、时长/可解码、权限与保存结果。生成失败保留脚本，可只重试语音节点，避免重新消费LLM。图片/视频/音频输入传artifact授权引用，视频帧/字幕处理保留原frame_processor算法并记录抽帧参数。

**数据表和RPA。** 原createDatabase/execDDL/DML HTTP依赖改为Java逻辑数据表，保留字段、默认、类型、测试/正式、复制、导入导出和查询。PGSQL字符串先解析，支持的SELECT/INSERT/UPDATE/DELETE映射到资源操作，任意DDL/函数/类型不等价时提示具体冲突；导入不可跳过失败行且记全部成功，返回行号/原因和原文件hash。正式写入先校验已批准effect policy、资源版本、行revision和幂等键。RPA接真实Runner协议：登记来源→导入项目/参数schema→配置执行位置→调试/正式运行→事件/结果/停止回读；项目不可用、认证失效和停止未知分别处理，不提供假执行器冒充原RPA完整实现。

**五渠道。** 市场发布写中心目录并验证分类/标签/visibility；API发布签发受限调用endpoint和凭据，速率/CORS/版本/撤销生效；MCP发布实际生成工具schema、登记endpoint、握手并调用验证；微信实现官方签名/解密、授权票据、appId绑定、回调/消息与下线；飞书实现app授权/事件校验/去重、绑定、真实调用回执及下线。所有外部动作需指定账号/目标/版本授权后实施，不在本轮发送或发布。校验通过不等于渠道生效，必须记录外部结果ID并回读；没有授权只能做预检，不改变发布事实。旧`McpPublishStrategy`抛未实现、`Api/Feishu`返回空成功必须替换，微信测试set-verify-ticket仅测试配置可用，不能暴露生产路径。

**原讯飞渠道兼容。** 原`flow.ts`的AIUI智能体列表、渠道公告/信息/状态与开放平台同步，以及版本抽屉的讯飞语音平台/讯飞云结果，不能因新版五渠道枚举而丢失。目标渠道配置额外支持`IFLYTEK_AIUI`和`IFLYTEK_OPEN`，由同一发布Service调用受控适配；原MAAS应用认证/发布/同步只保留作为外部资源协议，不迁第二tenant/license控制面。缺完整服务定义时先补协议及配置预检、固定版本同步、发布结果回读和下线；用户选择不使用时保留数据/历史并标未配置，而非声称已经可用。评测、trainable-nodes和历史训练集调用按1.5的固定用例评测实现；真正模型微调单列资料不足。
