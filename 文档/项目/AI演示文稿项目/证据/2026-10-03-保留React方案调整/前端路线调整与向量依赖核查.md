## 2. 向量依赖核查

本次只读搜索原 Python 后端、原 Java 后端、原 React src，以及当前 aippt Worker/Java 模块中的 Python、Java、TS/TSX、TOML、POM、SQL 和 Markdown 文件。搜索词包括 pgvector、embedding/embeddings、vectorstore/vector_store/vector_db、Milvus、Qdrant、ChromaDB、FAISS、向量和语义检索，未发现匹配。依赖声明也没有对应向量数据库或检索依赖。

原 `backend/app/services/sources.py` 将输入解析为 sections，保留章节和定位；`backend/app/services/outline_inputs.py` 将这些 sections 纳入生成输入指纹；`backend/app/workflows/outline.py` 的 prepare_outline_input 按章节整理材料，原总字符预算 12000、单节预算 2000，再调用 OutlineGenerator。这个链路没有执行向量化或向量检索。

结论：现有演示文稿能力不要求向量库、Embedding 或 RAG。MySQL 持有项目、材料章节、提纲、页内容、任务和版本，文件通过现有私有对象存储保存；保留原内容裁剪及其限制。以后若要求从跨项目海量知识库召回材料，再单独设计检索接入，不能借当前迁移新增需求。
