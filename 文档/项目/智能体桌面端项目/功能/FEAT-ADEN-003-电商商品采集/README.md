## 目标与范围

在现有 Electron/Vue Aden 中输入一个或多个电商商品链接，观察每条采集进度、失败原因、取消或失败重试，预览并修正实际存在的商品及 SKU，保存来源草稿，导出智能选品商品 Excel 和来源清单。首轮目标约 20 款、至少 60 个真实存在 SKU；不足如实报告。正式商品、销售价、库存和报价继续归智能选品 Java/MySQL。

只访问公开 HTTPS 页面和页面公开的商品数据；首期适配 JSON-LD Product/ProductGroup 与 Shopify 公开 Ajax 商品接口，并尝试京东公开页面。访问拒绝、登录/验证码或结构不足时停止该项并提示人工处理，不提供 Cookie 导入、伪装反检测或绕过手段。商品链接支持不等于所有平台动态页面均可读取。

不下单、不发送消息、不调用付费模型、不写选品数据库、不安装更新用户已有桌面安装包。真实采集不使用合成 SKU 或精确库存数字凑数。

## 技术设计

### 边界与流程

沿用 main → 窄 preload API → renderer。main 以固定业务方法代理只读采集；renderer 不获得任意 HTTP/文件/Shell 能力，也不渲染源 HTML。RuoYi 仍是登录、工作空间、任务、审批与审计的唯一中心，本切片不新增离线任务账本：前台采集会话生命周期仅在当前登录工作空间内，持久资料是明确标识的本地草稿文件。开始、载入和保存/导出前从既有中心接口复核工作空间访问；与现有合成任务类型无耦合，不把本地进度上报为服务端任务成功。

main 使用 Node HTTPS GET，DNS 解析结果校验为公网 IPv4并绑定连接地址，保留域名 TLS 验证。只允许 HTTPS 443、不含 userinfo；无 Cookie/Authorization；同源跳转最多三次，每跳重新校验 DNS；每响应最多 6 MiB、超时 20 秒；每次一个商品，商品间间隔一秒。429/登录/验证码不自动重试。HTML 只解析公开 JSON-LD 和必要平台标记，不执行脚本；Shopify 只在正常取得公开商品页并确认平台后读取同源 `.js` 商品资源。字符串和不安全整数 ID 分别处理；不能精确表达的数值 ID 拒绝，不静默舍入。

不引入浏览器登录态或外站运行窗口。遇必须登录或验证码的来源显示“需用户处理／公开读取不可用”，用户可以正常在浏览器处理后再试；若公开读取仍不可用，保留失败原因，接受其他公开来源。此限制作为实际验收项记录。

### 草稿、修正与导出

数据包括 source（原始URL、规范URL、提取URL、采集时间、适配器、响应摘要）、items（只读原始字段、可编辑字段、availability）和修改记录。每个商品一组真实 SKU 行；没有变体证据时仅保存商品草稿，不虚构 SKU。预览提供分组属性编辑和 SKU 切换，所有未知字段保持空串。草稿文件带 schemaVersion，载入时严格校验大小、字段白名单、字符串长度、URL及状态；不从载入文件自动发起网络请求。

XLSX 导出使用标准 OOXML 文本单元格和 ZIP；不输出公式，不使用 CSV 改后缀冒充 Excel。一个工作簿含商品资料和来源工作表，同时导出机器可读来源 JSON。文件对话框由用户选定路径，以原子替换写单文件；不自动覆盖业务数据库。来源表是观察证据，不是正式价库/库存模板。

选品契约 owner 在 `contracts/fashion/product-import-v2.json`；对接时由脚本读取指定契约、校验 54 个唯一字段和关键边界，生成带来源摘要的只读消费常量，禁止自行手抄第二套字段规则。当前契约来源为 fashion-remediation 独立工作树；候选状态需保留，最终交接使用其验证版本。不复制修改选品业务代码。

### UI 与异常

复用 Aden 现有侧栏、字体、卡片和按钮。新页面为链接输入 → 逐条进度 → 商品/SKU 清单 → 属性编辑 → 保存/载入/导出。结果计数、草稿缺失与失败原因有文字，不只靠颜色；输入有标签，操作可键盘访问，长表格局部滚动。网络操作不阻塞取消按钮，窗口退出清理控制器和临时状态。错误保留输入，重试只处理失败/取消项。
