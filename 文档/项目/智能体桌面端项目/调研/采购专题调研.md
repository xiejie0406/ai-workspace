# Aden 电商采购与桌面 Agent 专项调研

> 类型：产品研究；版本：1.0.0；owner：Codex  
> 取得日期：2026-09-11；研究方法：官方公开资料核查、原始需求分析  
> 上游：[项目控制页](../README.md)；输出：[PRD](../产品/统一设计文档.md#requirements)<br>
> 证据边界：没有购买、安装或实测竞品，没有商家访谈、平台账号接入或真实询价；官网能力声明不等于效果验证

## 1 决策结论

**产品推断：** 建议把 Aden 定义为“面向采购人员的商品信息与询价执行中心”。第一版完成商品采集和供应商沟通，再把两者汇成可追溯的报价比较。对端为 AI 客服、人工客服或未知身份，都使用同一套会话与报价对象。

市场已有高度重叠产品，尤其 Accio Work。Aden 需要验证国内采购渠道、企业已有供应商资料和报价口径的实际差异，不能将“会操作电脑”或“会自动询价”作为独有能力。

**用户事实：** 用户在 2026-09-11 明确首要用途是替采购方联系商家、询问商品、价格与交期。原始 Word 的卖家微信客服流程不纳入本轮首版，但保留历史原文。

## 2 竞品比较

| 产品 | 与 Aden 的关系 | 官方资料支持的能力 | 尚不能推出的结论 | 产品启发 |
| --- | --- | --- | --- | --- |
| Accio Work 与 Sourcing Toolkit | 首要直接竞品 | Alibaba.com 连接器、供应商匹配与比较、批量联系、自动询价及谈判；安装插件并连接账号，帮助页要求相应客户端版本 | 未证明同等支持 1688、千牛或个人微信；未验证询价完整率与企业部署效果 | 对标完整采购流程；差异必须具体到渠道、行业字段和采购决策证据 [S01] |
| 1688 AI 版 | 平台原生直接或潜在直接竞品 | 2026-06-03 生效的内测版服务协议将其定义为面向生意与采购的 Agent 工作台，涉及任务、网页、文件和工具 | 协议不是可用功能清单；公开上线、系统支持和自动谈判成熟度未核实 | 重点考虑平台原生竞争，验证跨渠道资料与团队协同价值 [S02] |

| 实在 Agent | 桌面执行侧竞品 | 自然语言理解、任务规划、RPA 与屏幕语义执行；官网有电商数据采集分析场景 | 任意电商聊天窗口的长期稳定性、自动询价支持矩阵未核实 | 通用执行已存在，需要业务对象、异常恢复和可复用采购模板 [S04] |
| 晓多 AI Agent | 相邻产品，供应商一侧的客服代表 | 电商接待、多平台消息聚合、商品知识与推荐 | 不等于替采购方到外部店铺询价；客服回答不保证实际库存或履约承诺 | 对话需处理重复模板、未回答、转人工与条件性承诺 [S05] |
| Gorgias AI Agent | 海外商家客服相邻产品 | 基于店铺商品、订单、知识和配置动作答复或转人工 | 不等于跨店采购平台，也不证明可获取任意商家的内部数据 | 需要区分对端提供的资料、已确认的交易条件和待核实声明 [S06] |

不据本次公开资料估算市场份额、竞品营收或采购节省率。未取得可直接对比的完整合同报价，因此不编造价格排名。

## 3 电脑端 Agent 能做什么

| 能力 | 实际可用的技术形态 | 进入 Aden 的方式 | 需要验证的业务后置条件 |
| --- | --- | --- | --- |
| 浏览商品与提取参数 | 浏览器 Agent、连接器、页面工具 | 按任务读取允许的平台页面，形成商品快照 | SKU、阶梯价数量、单位、地区、时间与来源一致 |
| 与客服多轮交流 | 获授权消息接口或浏览器 / 桌面会话控制 | 询价、缺项追问、等待回复、人工接管 | 对象无误、无重复发送、回答与当前商品数量匹配 |
| 本地资料处理 | 文件工具或桌面应用 | 读取授权目录，整理历史报价、导出采购建议 | 文件范围正确，导出金额可复算，版本可追溯 |
| 本地业务系统操作 | 连接器、API、桌面 GUI | 后续接入内网供应商档案和采购系统 | 权限、状态、失败恢复与真实写入核验 |
| 长任务与多任务 | 任务中心加专用执行机 / 持久等待 | 保存执行检查点，等待时释放交互资源 | 关页面不丢任务；离线、锁屏不被误写为仍执行 |
| 监测与提醒 | 调度与业务事件 | 报价超时、有效期临近、待人工事项 | 不无界催问，不承诺电脑离线仍能本地执行 |

**能力依据：** Microsoft 文档区分托管浏览器与 Cloud PC 执行；Power Automate 说明 Windows 无人值守对用户会话的限制。Browser Use 提供浏览器 Agent 和身份 Profile，Manus Browser Operator 复用指定浏览器会话。Anthropic 提供电脑使用工具接口，UI-TARS 提供 GUI Agent 参考实现。[S07–S13]

**工程推断：** 优先使用正式连接器和稳定页面工具，确需原生软件时使用桌面执行。中心负责任务、数据、人工控制与结果核验，执行机负责具体动作。模型能够提出下一步动作，不等于整个系统具备稳定的任务完成能力。

## 4 必须说明的执行边界

1. 员工当前桌面与专用执行电脑不同。有人值守可在员工设备执行；常驻任务建议使用专用环境。Windows 上不得默认承诺多人和多个 GUI 任务同时争用一张桌面。Power Automate 的具体无人值守限制不能外推成所有执行器的统一限制。[S08]
2. 本地执行不等于模型推理在本地。UI-TARS 的本地操控可使用远端模型 endpoint；数据处理范围须逐个配置说明。其免费 Remote Operator 已停止的说明也不能写成仍有免费远程服务。[S10]
3. 网页能打开不代表目标平台允许全部自动化能力。1688 智能服务市场协议提供开发和入驻路径，并要求按平台及用户授权范围处理数据；不等于 Aden 已获得商品搜索或聊天接口。[S14]
4. “和 AI 客服沟通”不要求先建设跨公司 Agent 协议。本轮证据不足以证明有通用于各平台的 Agent-to-Agent 采购接口，先按实际会话通道核查。
5. 遇到验证码、登录失效、页面大幅变化或发送结果未知，任务要保留证据并转人工。采集重试与消息重发必须分开，不能因未见回执而默认再发一次。

## 5 产品取舍

| 可行路线 | 优点 | 主要成本与限制 | 本轮建议 |
| --- | --- | --- | --- |
| 人工浏览、聊天、Excel 汇总 | 灵活、立即可做 | 多页面切换，缺项追问和证据易丢，口径不一 | 用作真实用户基线，先测每份可用报价耗时 |
| 直接采用平台采购 Agent | 货源、账号与平台内交易上下文紧密 | 平台覆盖和团队采购规则受产品范围约束 | 必须试用 Accio / 1688 路线作对照，避免重复建设已足够满足的能力 |
| 通用 RPA 加人工维护流程 | 确定性操作可复用 | 页面适配和采购业务规则仍需实施 | 可作为执行层候选，不提前锁定厂商 |
| 自研采购中心加可替换执行器 | 可统一商品、会话、报价与企业规则 | 连接许可、运行可靠性、证据和维护均需自建 | 本轮 PRD 采用此候选方向，先验证一条授权通道再扩平台 |

最危险的产品假设是“已有采购 Agent 仍不能满足目标客户，而客户愿意为 Aden 的结果质量与协同付费”。原型只能帮助检验使用流程，不能证明商业需求成立。

## 6 后续实证计划

这些是生产实现前的研究任务，不是本次已经完成的事实，也不阻止交付原型。

| 待验证问题 | 验证方法 | 可决定什么 |
| --- | --- | --- |
| 客户价值是否成立 | 5 位目标采购人员，每人复盘 3 个真实询价任务；记录人工用时、缺项和现有工具 | 目标行业、常用字段、是否继续投入 |
| 平台接入是否覆盖 | 对一个正式授权平台核对商品读取、商家身份、发送与回执、回复获取的逐项能力 | 是否能交付全自动闭环，或先交付采集与辅助沟通 |
| 报价抽取是否准确 | 服装、包装、通用日用品固定样本，含 AI 客服模板、条件价格、矛盾和缺项 | 模型与人工复核范围 |
| 桌面是否稳定 | 页面变化、断网、锁屏、重启、人工接管、发送回执丢失等故障任务 | 专用执行环境与恢复设计 |
| 是否优于现有竞品 | 在同一商品、相同约束和允许通道下比较人工、平台 Agent 与 Aden | 可用报价成本和产品差异 |
