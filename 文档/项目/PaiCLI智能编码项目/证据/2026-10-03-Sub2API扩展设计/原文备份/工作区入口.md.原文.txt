## 2. 阅读顺序

1. 工作区工程边界：[根目录说明](../README.md)与[协作规范](../AGENTS.md)。
2. 共享平台或业务项目：从上表选择唯一入口。
3. 产品目标：进入所属项目的 `产品/`。
4. 功能实施：进入所属项目的 `功能/`，再读取 Feature 控制页、规格、设计、任务和验证。
5. 跨功能设计：读取所属项目的 `架构/` 和 `决策/`。
6. 已发生动作：项目内实现记录放项目 `开发记录/`；跨项目迁移见[工作区开发记录](开发记录/README.md)。
7. 历史追溯：只在需要时进入项目 `归档/` 或[工作区归档](归档/README.md)。

## 3. 归属边界

- “文档里出现若依”不等于它是通用若依规则。面试、智能选品或桌面端如何接入若依，仍由对应业务项目拥有；[若依框架中的面试集成入口](若依框架/README.md#面试集成入口)只负责导航。
- “文档里出现 Agent / Python”不等于它属于智能体桌面端。智能选品的 Python 智能体架构仍归智能选品项目。
- 行业调研中提到服装、采购或排产不改变调研所属项目；以研究问题和事实 owner 判断归属。
- `prototype/` 是可运行工程资产，目录名受运行路径和脚本约束；本次只更新它对文档事实源的引用，不把原型目录当作文档目录改名。
- 工具约定的 `README.md`、Feature ID、OpenAPI / AsyncAPI / JSON 证据和必要技术标识可保留；其余 `文档/` 下人读目录和文件使用中文语义名称。

## 4. 当前与归档

当前文档只放仍服务于当前决策、实现或验证的事实。自称 `Superseded` 的旧任务、已被新技术路线替代的候选架构、旧阶段/窗口提示词和已删除工程说明进入所属项目 `归档/`。

归档原文不表示曾经获得批准、已经实现或验证通过，也不得重新作为当前任务源。需要恢复其中结论时，应先提炼成新的当前文档。
