## 1. 需求与业务逻辑

### 1.1 要交付的产品

让已登录若依的开发者在授权仓库中完成理解代码、制定计划、执行修改、运行检查、人工批准、复盘与恢复；同一用户也能通过原有 CLI、inline TUI、Lanterna TUI 和微信文本通道使用适用能力。后台统一登记工作区、会话、计划、审批、任务、模型配置、记忆和审计，实际本机文件、shell、浏览器和索引操作交给独立 Java Runner。新业务归属 `ruoyi-paicli`，不并入 Aden 采购/桌面任务。

完整迁移覆盖原实际实现的全部功能、17 个内置工具、动态 MCP 工具、全部命令和原生评测设施，不能以 Web 聊天替代终端产品，也不能只搬 ReAct 主流程。原路线图中的尚未实现功能保留为明确边界；其中中心接入必需的安全、持久化、可靠性差距纳入本方案必须完成的工作。源码存在只表示静态实现证据，本轮没有运行原项目或验证真实业务。

唯一需求、方案、实施顺序和验收方法维护在本文件；[原功能与目标对应表](设计附录/原功能与目标对应表.md)仅维护源码追溯、命令和工具覆盖；[源码清单](设计附录/源码核查清单.csv)用于防止漏迁；[原配置入口映射](设计附录/原配置入口映射.csv)列出静态检出的环境变量/JVM入口、源码位置和建议接入归属，不含配置值。图稿是设计资产，不是实际界面或验收证据。

用户使用入口见[页面使用说明](页面使用说明.md)；执行前的详细业务步骤与实际结果沿用[完整业务验收记录](证据/2026-10-03-完整功能与数据库/完整业务验收记录.md)，阅读版见[页面使用与业务验收逻辑](证据/2026-10-03-完整功能与数据库/页面使用与业务验收逻辑.html)。这些说明不改变设计要求，不将源码逻辑核对或空页观察计为业务通过。

### 1.2 用户与操作范围

| 使用者 | 可以做什么 | 约束与拒绝条件 |
|---|---|---|
| 开发者 | 在分配的工作区发起会话、检索、计划、执行、提交审批、查看自己的结果 | 同时校验若依按钮权限、工作区成员关系、Runner 能力、资源版本与路径策略；无成员关系返回 403，猜测他人 ID 不泄露内容 |
| 工作区批准者 | 查看完整影响、批准/拒绝指定操作、反馈或改参数 | 只能批准所管理工作区；审批绑定输入哈希、根目录、Runner、计划版本、失效时间，不能批准被硬策略拒绝的操作 |
| 业务配置管理员 | 绑定 Runner、分配工作区、配置供应商/MCP/Skill/微信映射、设预算和保留期 | 密钥只写不回显；配置变更生成版本和审计；不能通过配置获得任意服务端 shell |
| 审计及评测人员 | 查工具证据、成本、原始/压缩上下文引用、评测报告 | 读取原始提示词/源码/图片需独立权限；正式评测仍受原暂停决定约束，重新执行需单独明确授权 |

平台登录、注册、账号、角色、部门、菜单、权限与公共操作日志全部复用若依。源项目没有独立 Web 账号系统可迁移，原 Runtime API Key、微信 bot token 和模型 Key 是设备或供应商凭证，不能变成平台账号。终端首次联机时打开现有若依登录页，已登录用户批准一次设备绑定；中心签发限定本用户、本工作区和有效期的设备会话，注销/撤销后停止新执行。该设备凭证属于已有认证体系的业务扩展，不另建用户名密码库。离线状态只能查看已缓存资料，不能另起一套可写正式控制面。

### 1.3 三条编码流程

1. **直接执行**：选工作区与在线 Runner → 输入文本/路径引用/图片 → 使用 ReAct 查资料与工具 → 展示流式答复、工具影响、成本和变更 → 查看诊断及快照。模型自然结束；预算或停滞命中后关闭工具并收尾，保留部分成果和未完成项。
2. **计划执行**：选 Plan 或 `/plan` → 生成唯一任务 ID、有效依赖且无环的 DAG → 用户展开、取消或补充要求修订 → 批准当前计划版本 → 执行独立任务批次 → 失败时按原规则重规划或跳过传递下游 → 汇总已完成、失败、取消、跳过。完成度小于 50% 才触发失败重规划，默认最多 2 次；取消不计失败也不重规划。达到上限后不启动新任务。
3. **团队协作**：`/team` 或页面团队执行 → Planner 拆解 → Worker 按 DAG 执行 → Reviewer 用严格 JSON 审查 → 被拒绝时携反馈重试最多 2 次 → 显示各角色轨迹和未通过结果。模型 Reviewer 的通过仅表示模型评价，不能替代测试、人工审批或用户接受。目标实现须修正原 `AgentOrchestrator` 在 Reviewer 错误及重试耗尽后仍 `markStepCompleted` 的行为：保留产物，标记“审查失败/未通过”，阻止依赖要求已审查结果的后续任务。

三条路径统一工具注册、策略、记忆、快照和原始账本，不维护第二份影子上下文。只读工具白名单并行最多 4 个，结果按原调用顺序回灌；写入、命令、MCP、回滚、未知工具及含浏览器工具的批次串行。DAG 跨任务并行须额外进行根路径资源锁，同根写入不并发，读任务共享已声明版本；不能只靠“每批写工具串行”假定跨会话安全。

### 1.4 原有能力和需要补齐的边界

| 能力 | 原代码事实 | 目标规则 |

## 3. 后台处理设计

### 3.1 运行与信任边界

用户浏览器/联机 CLI → 若依身份与菜单授权 → `ruoyi-paicli` 工作区/会话/审批/任务服务 → 原项目算法构成的独立 Java17 Runner → 受限仓库、命令隔离环境、MCP/CDP/模型供应商。

`ruoyi-admin` 只装配中心业务，不加载 ToolRegistry shell、JLine、Lanterna、JGit 进程执行或源 Runtime 的 localhost HTTP 服务。ReAct/Plan/Team 算法保留在独立 `ruoyi-paicli/paicli-core` 核心及 `paicli-runner` 执行产物内；运行事件、批准和终态由中心验签/核对并写 MySQL。原 SQLite 任务表/线程表（启动会把 running 重置为 enqueued）、长期记忆 JSON 和本地审计改成离线只读导入来源、缓存或发送队列，不再拥有正式状态。

Runner 主动连中心，以短期设备凭证换租约，避免中心直连每台本机。每次执行绑定 runnerId/workspaceId/userId/taskId、版本、预算、能力和真实根目录指纹；Runner 拒绝本机未登记的目录、旧租约、错工作区和越权工具。批准后的参数也需重新校验。中心不可达时停止新副作用和计划调度，记录本地已发生操作待上送，不能把离线缓存当正式批准。

**与 Aden 复用边界**：已存在 `AdenOperatorController`、`AdenRunnerController`、`AdenEventStreamController`、Runner Session/Claim/Heartbeat/Receipt/LeaseRecovery 服务以及 credential codec/filter，可参考租约、幂等、凭证哈希和事件游标机制；这些类型均绑定 Aden task/workspace/capability 和 `aden:*` 权限，不能直接拿来存 PaiCLI 任务。推荐先复用若依公共设施，PaiCLI 保持自己的数据和协议。若后续需要提取真正无业务语义的设备认证工具到公共模块，须单独审查共享影响；本方案不要求修改 Aden 或桌面安装版，也不创建第二 Aden 控制面。

### 3.2 一次请求的处理顺序

1. 中心从若依登录身份取得用户，不接收客户端声明的 userId；校验菜单权限及工作区成员。校验 input、附件、模型、计划/策略/配置版本、幂等键与运行容量。
2. 在一笔事务内登记 turn/task、不可变执行参数快照与 dispatch outbox。返回 taskId、version、eventCursor；事务内不调用模型/Runner。
3. Runner 领取带期限和 fencing token 的 lease；同一会话仅允许一个活跃 turn，多余输入显式排队。Plan/Team 独立任务按依赖并行，工作区写锁保证跨会话互斥。
4. Runner 在工具执行前提交提议。中心以当前配置决定拒绝、需批准或可执行；需要批准时持久化 pending approval。模型分类器返回仅能增加批准要求，不能覆盖成员、路径、命令或网络拒绝。
5. 中心签发一次性 permit，绑定 toolCallId、参数哈希、输入文件哈希、lease、policyVersion、期限。Runner 在执行点检查路径和隔离；完成后发送 before/after 哈希、exitCode、脱敏结果与 permit 消耗证据。
6. 中心按 runner eventId/toolCallId 去重、按会话序号写事件，检查合法迁移并记录审批与审计。客户端查询增量事件或 long-poll，断线按 cursor 续查；超出保留期返回 410 并提示重新取当前快照，不能静默丢事件。
7. 完成/失败/取消持久化后才给用户终态。业务成功要求所有强制步骤和审查条件满足；已经执行但回执丢失显示“结果待核对”，禁止盲重放写入或 shell。

### 3.3 正式数据与存储

接入该新项目获批准的 MySQL 数据源/既有若依 MySQL 中的 `pc_` 业务表，平台 `sys_*` 数据所有权不变。不因独立 Runner/端口创建或克隆数据库；具体连接由用户审核后的真实运行方案确认。中心无跨业务表写入，关联 `sys_user`/`sys_dept` 用稳定 ID 与平台服务权限查询。SQLite 仅为代码向量派生索引，明确允许“缓存第二存储”而非第二权威数据库。

| 表组（拟新增） | 核心字段与约束 | 所有权/生命周期 |
|---|---|---|
| `pc_workspace`、`pc_workspace_member`、`pc_runner`、`pc_runner_credential` | bigint ID；workspace/member 唯一；root fingerprint、capabilities、revokedAt；credential hash、过期、版本 | PaiCLI 工作区和设备；真实路径对普通审计隐藏；凭证撤销立即阻断领取 |
| `pc_session`、`pc_turn`、`pc_message` | owner、workspace、model/config version、sequence、role、tool_call_id、content/artifact ref；会话序号唯一 | 原始消息真相；压缩视图引用原消息，清空上下文不删除审计 |
| `pc_task`、`pc_plan`、`pc_plan_step`、`pc_task_lease` | mode、planVersion、dependencies、reviewStatus、replanCount、预算、state、version；task+lease fencing | 中心正式任务与计划；终态不能被迟到事件复活 |

| `pc_idempotency`、`pc_import_batch` | 请求指纹、加密响应、原资料摘要、源产物、提交与回撤版本 | 同范围重试与离线导入；不复活旧任务、批准或消耗过的许可 |

上述共 35 张正式业务表。V1 建立业务账本，V2 登记若依菜单及按钮字典，V3 保存导入批次，V4 补齐按功能查询的业务字段、索引、约束与提示词覆盖表。业务生成字段从既有 `payload` 及记录类型、状态、父对象等唯一字段投影，禁止独立双写；原始 SQLite 的线程、事件、任务归中心，代码片段与关系仍为可重建的 Runner 派生索引。逐字段来源和检查范围见[功能字段机器清单](../../../ruoyi-backend/ruoyi-paicli/paicli-api/src/main/resources/paicli/functional-schema-v4.json)。

大型工具及控制结果允许以最多 4MiB 的分块提交，单工具文本或完整控制事件产物最多 128MiB，覆盖原合法 MCP 聚合结果；单任务分块产物累计最多 512MiB。每步核对同一已消费工具调用、租约及 fencing，冻结总大小和 SHA-256；顺序、分块摘要、完整摘要及 UTF-8 校验完成后才发布不可变产物。普通附件仍受 50MiB 限制。控制事件保留实际能力元数据与完整产物引用，不把大正文再次塞进事件 JSON；原始结果支持鉴权下载和有界读取。中心确认之前保留本机完整证据，上传重试不能重新执行工具副作用。

完整工具文本按UTF-8字节游标读回，单页4字节至1MiB，只在完整码点边界推进；每页绑定会话、产物ID、总大小和完整SHA-256。大PAI原文使用明确的`PAI_SOURCE`用途、严格UTF-8及原字节摘要上传，再由项目规则登记引用；直接正文最多1MiB，单来源最多50MiB、规则与明确imports累计最多128MiB。派生提示预算与原文保留分别处理，不能将派生截断内容冒充原文件。

JSON 参数/内容使用 MySQL JSON 或受大小约束的 TEXT，依赖边要在 Java 确定性校验；time 用 UTC 毫秒精度，页面按 Asia/Shanghai 显示。索引覆盖 workspace+状态+时间、session+序号、approval+状态+过期、outbox+待发送、task lease expiry。金额/成本使用 decimal 与供应商计价版本，usage 缺失显示未知，不能当 0。

拟定保留基线供审核：普通事件/对话 90 天、图片和超大工具产物 30 天、工具/批准安全审计 180 天、最近 20 个轮次快照且至少 7 天；用户显式保留/法律要求须另定，不自动永久留源码或密钥。导出/删除须成员和专门权限；删除工作区先停止任务、吊销凭证，再处理存储及元数据，记录留存冲突。对象文件复用现有上传设施的存储接口，存路径/哈希引用，不把图片 base64 塞进每条事件；不得混入 Fashion/Aden 私有桶命名或资产所有权。

### 3.4 接口与命令接入

所有操作者接口 `/paicli/v1` 使用若依现有 token/filter、`@PreAuthorize`、`SecurityUtils`、`BaseController`、分页返回与 `AjaxResult`，业务错误带稳定 code。设备接口 `/paicli/runner/v1` 在既有 Spring Security 中增加限定设备 principal/filter，只授权设备协议，不接受平台用户 token伪装设备。所有传输协议在审核后维护于 `contracts/paicli/`，本轮只说明目标。

接口实际路由、HTTP字段与权限由[操作者机器契约](../../../contracts/paicli/operator-v1.openapi.json)、[设备机器契约](../../../contracts/paicli/runner-v1.openapi.yaml)和[事件及账本结构](../../../contracts/paicli/events-v1.schema.json)维护。操作者契约保留若依AjaxResult或TableDataInfo及直接导出响应的区别，引用的扩展JSON对象仍须执行服务端成员、owner、版本和许可校验，不能仅凭schema获得授权。

增量事件默认有限批次 200 条，上限 500；轮询返回最新 cursor，可设最长 20 秒 long-poll；前端用共享 request，不创建 EventSource token URL 或第二认证流。真正持续 SSE 可在后续采用已有经审查的流传输能力，但本方案的可续查事件必须首先实现，原一次性 `text/event-stream` 不足以代替它。

原 `/v1/threads` 三条 API 的兼容门面保留在 Runner loopback，仅把调用转发中心：以中心已签发的设备会话换旧 Key的映射；API Key 不授予新业务权限，迁移初期明确兼容版本，旧 Key撤销后失效。不可启用原直接 runHeadlessTask 或本地 SQLite线程真相。旧事件 ID 到中心 cursor 维护导入映射，无法对应返回错误，不猜序号。

通用错误：400 schema/空输入、401 凭证、403 权限/硬策略、404 对象、409 版本/并发/审批失效、410 cursor 已过期、413 输入/附件过大、422 DAG/模型能力不支持、429 队列/预算、503 Runner/供应商不可用。响应提供中文原因与可行下一步，正文不包含秘密和堆栈。

### 3.5 工具、网络和安全规则

17 工具完整输入及验收在附录维护。中心发布工具 schema/version 和能力快照，Runner 原 `ToolRegistry` 只注册获授权工具。所有工具结果用 `ToolResultBoundary` 保持 `untrusted-data`；外部网页、MCP、Skill 与仓库提示文字只能是资料，不能升级权限或让模型取得凭证。

文件写入在真实根目录内，新增路径检查最近存在祖先，目录/符号链接变化时执行点再次校验；真实路径解析失败时拒绝，不能沿用原IOException后退回词法路径的降级；目标实文件哈希不同就拒绝修改，临时文件原子写回。restore 逐文件预览、拒绝新软链逃逸、保存原文件模式和恢复前备份；遇一项失败先恢复本次已改项并显示未恢复列表。禁止处理系统盘根/用户密钥/其他业务安装目录。命令字符串只有进入隔离进程、已批准工作目录、环境变量白名单和执行资源限制后才能执行；黑名单和模型判断只是辅助，不能视为 shell 沙箱。

模型`revert_turn`先由中心选择正式快照，通过未向模型暴露的内部只读预览产生已确认回执，再冻结目标ID/版本、预览调用、逐文件影响和当前树指纹，使用新的执行调用ID申请恢复批准；执行前再次核对。跨成员批准者可在`approval:decide`和工作区批准角色范围内分段读取该申请冻结的完整预览，不开放申请者普通产物下载，不允许客户端另选产物。物理恢复失败时保留实际结果及未完成项，只补偿本次仍未被外部再次修改的文件。

快照清理按工作区独立生成只读完整缓存清单，包含实际HEAD、引用、提交及尚未登记的派生项；冻结摘要与正式快照版本集合，明确展示清理范围。批准后再次核对缓存与元数据，先保存可恢复的私有备份及摘要，再清理活动缓存。未知派生项不提升为正式快照事实；后续新增提交或引用不能被旧批准删除。全部工作区操作保留各任务的独立游标和成功、失败、未派发情况，不能只等待当前会话就宣布全部完成。

联机默认 `commandSandbox=required`，Linux 采用低权限隔离 Runner/容器，Windows 采用独立受限环境或 WSL2/容器适配；原 bubblewrap/Seatbelt 可以保留验证，但 Windows 产品级隔离未见原实现，必须补齐或显示“命令执行不可用”。网络仅开放已批准 provider/MCP/构建源；原沙箱无网络、看不到 `~/.m2` 的行为需要设计专用只读依赖缓存，不能挂整个用户目录解决。没有隔离环境时停止 command/create_project 中外部构建流程，文件模板仍可在获批根生成。

Web 搜索保留 GLM/SerpAPI/SearXNG/DeepSeek 四实现及显式 provider 优先级。`web_fetch`/导航只接受用户顶层 URL 或当前分支结构化搜索 discoveredUrls；依赖 DAG 才继承 URL。DNS及每次重定向检查内网/loopback/metadata 地址、大小/超时，不通过换 MCP 绕过 URL 拒绝。CDP loopback 属于用户已批准的本机浏览器连接能力，与网页网络访问分开；shared 登录态对敏感改写逐次批准，isolated 会话不持有用户常用 profile。MCP stdio 命令视同代码执行，配置 hash 逐项批准后才能启动；项目配置不能悄悄覆盖同名用户服务。

图片保留本地文件/剪贴板/base64解析与处理：原实现来源 50MB上限、API base64 5MB上限、过大才缩放至2000建议尺寸并压缩；未过大小阈值不强制降尺寸。Web 上传同样先检查实际 MIME/解码/像素预算、防图片解压炸弹与元数据泄漏；目标像素上限拟4000万，超限明确拒绝。文本模型不得悄悄忽略图片。

配置密钥采用中心受控 secretRef；供应商调用在受限 Runner按本次短期授权获取必要凭证，不能向 TUI/Web日志回显或持久化原 `config.json` Key。若审核选择“完全不向本机下发供应商密钥”，需在中心新增 provider relay，仍不执行本机 shell，须同时验证流式/usage/reasoning/图片协议兼容。原默认本地文件明文 Key不直接迁为正式存储。

威胁重点是恶意仓库/网页提示注入、项目MCP启动代码、CDP登录态、模型生成shell、快照覆盖后续编辑、跨用户记忆、重复回执与密钥泄漏。对应控制为不可信边界、确定性权限、MCP信任hash、敏感动作批准、隔离执行、哈希/CAS/资源锁、scope过滤、幂等permit/事件序号及日志脱敏。批准者只能处理业务许可，不能解除硬安全边界；安全审计写入失败时停止新副作用，不能沿用原“账本打不开仍运行”的静默降级。

### 3.6 异步、模型与故障

任务状态拟定为排队→已租用→执行中→等待批准/取消中→完成/失败/取消；租约超时进入待核对，不自动重新执行未知副作用。每次尝试保留 attemptId/fencingToken，迟到旧尝试的事件归档但不能推进当前状态。同会话清空/切换模型/压缩在无活跃 turn时执行或排队，防止历史和预算被运行中修改。取消杀当前工具进程树，等待回执确认；超时转“取消结果待核对”，不能马上显示已撤销。

原8 provider及 capability 模板保留，model refresh只请求列表且只追加；未知模型默认128k文本，不用推理请求试能力。启动选择沿用环境→项目env→用户env→保存模型→默认的可见优先级，但正式密钥从secretRef取得；环境模型必须在中心登记且当前用户可用，不能覆写中心预算。切换保存失败保留旧选择；thinking的reasoning_content续轮回传、DSML仅转已暴露合法工具、未知块给“调用未执行”提示；确定性4xx不重试，408/429/可恢复5xx有限退避总3次；一旦已交付正文不自动重放半截输出，留失败及续接提示。

拟定可评审容量：每用户2个活跃会话、每Runner默认1个写任务/4个只读工具、全局队列100个、单task累计内联输出及事件20MiB（完整大结果按3.3节产物预算处理）、单command保留60秒原超时、普通模型请求超时120秒（长模型需登记单独上限）、审批15分钟、lease60秒/心跳15秒、断线事件查询不丢序。限制都是目标配置，不是测得性能承诺；达到限制429并显示排队/缩减建议，任务预算耗尽保留部分结果。联机上线前用同配置验证资源/成本上限与并发隔离。

拟定恢复目标供审核：中心 MySQL 与artifact索引RPO不超过24小时、RTO不超过4小时；正在执行的外部命令不承诺自动恢复，须停机核对。中心备份恢复与Runner spool/lease对账先完成，才能重新发permit；派生RAG索引无需全量备份，按manifest重建。磁盘满、审计失败、permit持久化失败停止新副作用，UI保留已有结果与明确原因。

### 3.8 数据迁移、配置和恢复

迁移不移动/删除原目录。审核实施范围后在目标模块复制源码及测试，记录来源路径/hash和迁移差异；原压缩包与参考目录保持只读。新项目业务控制面与其他四/五新模块隔离，端口由真实启动指南追加分配，不沿用原8080撞共享服务；Runner无需公开入站端口，compat loopback默认关闭，需要时用户明确选择空闲端口。

导入顺序：获批平台身份/工作区映射 → 去秘密后的provider/MCP/Skill配置 → PAI/长期记忆 →会话JSONL与原runtime/tasks SQLite导出 →快照元数据和产物 →评测历史/冻结资料。先只读预检来源schema、条数、scope、hash、文件owner、时间/编码及秘密；没有身份映射的资料隔离为待归属，不映射到超级管理员。SQLite通过事务一致性副本含WAL取得，只读导出，不在原库初始化/升级。running任务导入“待核对”而非继续执行，enqueued需用户确认后才重新排队，旧批准全部过期。原API事件只有提交/终态不含完整工具证据，标“历史证据不足”，不能补造审计。

每批导入使用source fingerprint+legacy id唯一键、batchId与迁移映射，失败可回滚该批数据库事务；对象文件先暂存核hash再发布元数据。导入记忆保留待核实/冲突，不自动解决不同版本。RAG仅导入manifest并重建向量，不能假定原embedding模型与目标模型相同；PAI原路径内容保留为项目规则但不可授予工具权限。真实secret留受控原位置，通过明确配置录入，导出包不携带Key/微信token。

恢复时先停新任务并吊销新permit、对账活跃lease与已发生副作用、导出迁移后的用户新增数据；恢复数据库/对象元数据备份及配置版本，原参考不被覆盖。中心恢复后人工核对未知shell/MCP结果，幂等事件可重放、未知副作用不可重放。撤销导入只处理该batch无后来修改的记录，存在后来编辑则保留并给冲突清单。文件恢复只能使用对应Runner快照和真实hash，不能用旧Git HEAD覆盖用户未提交内容。源项目根未找到许可证文件，正式复制/再分发前须确认代码和教程授权；此项不影响本轮只读设计，但影响实施与发布。

## 5. 业务验收方法

### 5.1 影响完整迁移的待审核决定

1. **执行环境与发布平台**：建议Windows/Linux/macOS保留终端兼容，但联机shell只在已验证受限环境启用；Windows采用WSL2/容器或独立受限环境的具体选择影响部署、依赖与验收。不能批准“admin直接无限制本机shell”。
2. **供应商密钥位置**：建议中心受控secretRef与短期能力下发；若禁止本机接触Key，则实现中心provider relay并核全部协议。需要明确成本预算、可用模型/embedding和真实供应商验收范围。
3. **工作区数据及保留**：批准MySQL落点、成员/批准者职责、个人global语义、90/30/180天与20轮快照基线、备份指标；不克隆其他业务数据库。任何扩大跨工作区共享需单独确认。
4. **代码再分发许可与微信归属**：确认PaiCLI原代码/教程许可，以及iLink测试账号、sender→若依身份绑定和工作区，才可实施复制/分发或真实通道验证。
5. **评测范围**：完整搬迁已有评测设施并保持暂停；若要求同步补齐正式28题/榜单，须另批准D5/E3/E4、E2与其余准入差距、模型/重复/预算/证据合同和单次真实运行。不能把完整产品功能迁移与正式榜单完成混为同一事实。

审核本方案后才能进入代码迁移。审批该方案不代表源能力已迁移、业务已验证、用户已接受或已发布。
