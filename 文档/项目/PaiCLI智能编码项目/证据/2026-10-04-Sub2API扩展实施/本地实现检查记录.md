## 2. 实际组件浏览器检查

检查页使用真实 `connections/index.vue` 和 Element Plus，子功能展示组件替换为空组件，接口为本地内存夹具。独立 Vite 仅监听 `127.0.0.1:18126`；独立 Playwright 会话使用本机 Edge 内核，没有接管用户页面或共享验收进程。

1. 新增供应商下拉有 Sub2API；选择后出现必填 API，隐藏 LoRA。未选 API 点击保存，显示提示，模拟 request 的 PUT 数量为 0。
2. 选择 Responses 并填写根地址，最终路径为 `https://sub2api.example/v1/responses`；只显示托管引用，未显示 token。已选择协议时清除之前的缺项提示。见[协议表单复验截图](实际组件-协议配置-复验.png)。
3. 模型表单显示完整 ID；图片、工具和“已核验能力”不能由普通表单伪造。输出留空沿用中心预算，思考强度留空不传参数。见[文本模型限制复验截图](实际组件-文本模型限制-复验.png)。
4. 点击验证出现最多两次合成调用、每次最多 256 输出 Token 的确认；取消后 verify 请求为 0。见[费用确认截图](实际组件-验证费用确认.png)。
5. 确认后模拟请求携带 `If-Match=3`、`modelId=15`、`modelVersion=5`、`confirmCost=true` 和幂等键，见[实际模拟请求记录](浏览器模拟验证请求.log)。这里调用的是内存夹具，不是中心或模型服务。

五张首次/复验采集图均已逐张回读。首次截图中“留空沿用模板”等通用提示与 Sub2API 无模板设计不一致，已改为中心预算/不传参数；首次图片和复验图片同时保存。浏览器唯一错误是本地夹具没有 favicon 的 404，无页面 JavaScript 异常；未宣称全部控制台请求无错误。

[本地检查报告](本地实现检查报告.html)已在同一独立检查通道实际渲染，[渲染截图](检查报告渲染.png)已保存并回读。检查完关闭本次 Playwright 会话和临时 Vite，核对 18126 已无监听；其他验收页面和共享服务保持原状。

## 3. 首次失败与修正

- [中心首次失败](中心测试-首次失败.log)：测试回执没有先消费真实控制许可。补齐夹具许可流程后再检查真实版本行为。
- [中心第二次失败](中心测试-轮换校验修复前.log)：轮换测试只改变 metadata 而解密仍返回旧版，暴露发放前后的一致性边界。现在同时校验实际解密版本和当前启用版本，并新增相反方向的不一致测试。
- [前端首次失败](前端测试-首次夹具失败.log)：测试将单对象政策接口模拟成数组，触发旧模板 `.join`；按实际接口修正夹具，没有改动原政策行为。
- 最终源码自查关闭 Sub2API 的旧厂商补 call ID 行为，并拒绝非法/部分用量；最终 Core 57 项包含这次修正。取消时的 MockWebServer 空连接告警、原 Maven Shade 重叠资源与构建提示保留，构建均成功。
