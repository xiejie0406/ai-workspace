## 1. 三个入口各做什么

| 页面 | 用来做什么 | 用户日常操作 |
|---|---|---|
| 智能编码 | 提出目标，让Agent分析、执行并交付可核对的结果 | 输入要求、选择处理方式、看进度、确认影响、查看文件与检查、打开终端 |
| 我的文件 | 保存本人资料，下载文件或选择资料交给Agent | 上传、筛选、下载、回到对话分析 |
| 模型与设置 | 选择默认模型，维护自己的供应商与高级设置 | 选用平台可用模型，或配置本人模型；需要时展开搜索、向量及其他高级项 |

对话是持续沟通的上下文：保存要求、回复、文件引用和后续补充。本次执行是Agent为完成一条要求所做的步骤、工具调用和结果。它们在同一页呈现；用户不需要先创建另一份“任务”。历史中的进行中对话可以随时回来继续查看。

原后台任务和审计详情保留为执行追踪能力，由具体对话和记录进入，不再作为第一次使用时的独立创建入口。没有人类成员、工作区或Runner登记步骤；执行服务由部署者准备。

## 2. 第一次开始

1. 登录已有若依账号，打开“PaiCLI智能编码 → 智能编码”。
2. 在输入框写出目标。可点击“读懂代码、实现功能、排查错误、审查改动”示例，再改成自己的要求。
3. 使用默认模型和默认文件位置。只有需要处理已有项目时才更换目录；无需给新对话取标题。
4. 点击发送，系统用首条要求建立对话并生成标题。Agent回复和本次执行出现在同一页。
5. 查看成果里的实际文件、修改差异及检查回执。完成后直接补充下一条要求。

“新对话”进入新的输入草稿。运行中可以继续写草稿，等当前执行完成或停止回执确认后再发送；当前版本不把运行中输入自动插入已经冻结的执行。

有模型和受信执行服务、但文件目录尚未准备时，可以进行纯文字分析；纯文字执行不访问文件或调用文件工具。没有模型或服务时，输入保留，状态说明具体缺项，不把保存配置当作已经可执行。

## 3. 目录怎样使用

每人使用自己的文件位置，归当前若依稳定用户ID所有。默认位置在Agent执行机器的个人数据根内；新对话的文件放到本人 `files/conversations/<对话ID>`。账号改名不会改变归属。

用户不选目录时，系统按需准备当前对话目录；首条要求可以先提交，涉及文件的执行等待真实目录证明后继续，不要求重发。选择已有项目时，只能选择当前受信宿主上本人 files 内已核实的目录。

浏览器上传的是文件内容，不能自动取得用户电脑上任意文件夹的访问权。当前实现拒绝个人 files 以外的路径。运行中的对话和终端使用已冻结的位置，不能直接换到另一目录；需要换位置时先停止相关执行或新开对话。

## 4. 处理方式、执行过程和成果

| 选择或区域 | 作用 | 应该怎样理解 |
|---|---|---|
| 直接处理 | 让Agent围绕目标推进实际处理 | 涉及受控影响时仍显示必要确认 |
| 先出方案 | 先形成可查看的方案，再按确认推进 | 方案步骤与已执行工具步骤分别显示 |
| 只分析 | 服务端和执行端限制为只读范围 | 输入中写“只分析”之外，还有确定性的只读控制 |
| AI协作 | 使用已有多个AI协作的执行能力 | 不需要登记人类成员；仍属于当前对话执行 |
| 本次执行 | 显示当前要求的实际状态、步骤、等待原因和确认 | 等待目录、等待确认、失败、停止都有对应原因；不是模型自行描述的进度 |
| 此对话的成果与检查 | 累计查看当前对话形成的实际结果 | 文件差异来自实际修改前后内容；命令检查来自实际退出回执 |

需要确认时，先看具体对象、参数和影响再决定。拒绝或停止后以中心回执为准；停止按钮点击成功不代表外部动作立即撤销。

文件修改显示完整差异。较大差异从实际产物分段读取并核对摘要；二进制、非UTF-8或超出完整差异支持范围时，显示原因，不用截断内容冒充完整差异。没有实际命令退出码时，不显示检查通过。

## 5. 我的文件与资料分析

上传后保存的是本人文件；选择支持分析的资料，再进入对话提出要求。普通文件引用和图片引用分别传递，不混成同一种附件。

当前正文分析支持核实后的UTF-8文本/代码资料。PDF、Word和二进制文件可以保存、下载；尚无对应正文解析时会显示不可分析原因，不能点击后假装已读出全文。成果是否已经落盘，以实际文件和执行回执为准。

## 6. 打开终端

在智能编码页点击“打开终端”，使用当前对话的真实目录和原CLI能力。目录准备期间等待核对，不要求用户手填指纹或选择执行设备。关闭终端面板和停止执行是不同操作，应按界面状态处理。

终端需要部署者启用真实PTY通道、准备可信宿主及对应CLI分发。若不可用，页面显示实际原因并保留对话；终端启用开关、桥接能力、在线状态与文件准备分别核对。命令执行继续遵循既有沙箱要求；Windows缺少有效的REQUIRED隔离时，受保护命令会拒绝执行。

## 7. 模型与设置

普通用户优先选用管理员明确发布的可用模型。平台模型只显示公共名称、模型ID和能力，不显示发布者私有配置、密钥引用或备注；用户不能通过平台模型入口修改他人配置。

用户也可以配置本人供应商和模型，并设为自己的默认模型。密钥通过既有托管机制保存，不回显正文。搜索、向量、MCP等高级项按需展开，不作为第一次发送的表单前提。

平台默认模型必须经过管理员明确发布和授权范围核对。撤销发布后，新执行和续期不能继续借用该授权；已经发生的外部调用无法通过撤销追回。预算、模型可用性和调用费用仍按原中心边界处理。

## 8. 页面不能继续时看什么

| 提示 | 含义与下一步 |
|---|---|
| 没有可用模型 | 选择已有可用模型；有配置权限时配置本人模型，或由部署者发布平台模型 |
| 执行服务未准备 | 部署者核对可信宿主、绑定与在线状态；普通用户无需登记Runner |
| 文件目录正在准备 | 保留首条要求，等待真实目录证明；失败时查看原因再重试 |
| 等待确认 | 核对具体影响后允许或拒绝；不是再次发送同一条要求 |
| 执行失败或停止 | 查看实际原因、已形成的结果和回执，再决定补充要求或重新开始 |
| 终端不可用 | 按终端具体原因核对PTY开关、桥接和宿主；不与模型未配置混为一个提示 |
| 历史记录只读 | 旧归属或共享记录被冻结为可读档案，不能继续以旧工作区权限执行 |
| 中心尚未升级 | 运行包仍为旧接口；草稿保留，由部署者完成对应版本切换 |

实际可用条件和本次检查结果以实施记录为准。说明文档、界面图、构建和模拟测试分别只证明自身范围，不能替代真实目录、模型、文件和终端的联机结果。
