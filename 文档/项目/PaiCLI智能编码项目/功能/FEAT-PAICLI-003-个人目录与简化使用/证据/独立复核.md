## 3. 已核实的边界

### 3.1 用户、模型和历史资料

- 活跃个人资源按若依稳定 userId 与记录 owner 判权，客户端不能通过提交 owner、Runner 或旧 workspace 字段改变归属；旧工作区/成员入口不作为新任务授权依据。
- 历史共享访问来自迁移时固化的允许快照，并保持只读；历史凭据、宿主和成员机制冻结或撤销，没有将原共享密钥自动复制到个人模型。
- 平台模型发布需要既有管理权限和管理员角色、明确受众及共享确认；发布固定模型、Provider 配置和密钥版本。跨 owner 的普通模型列表、详情和会话投影经过公开字段白名单，执行领取、Provider 取密钥和许可续用仍核对有效发布。
- 会话消息、事件和分页按已授权的稳定 session 读取，不因默认 home 切换至 conversation 目录丢失第一条输入；消息仍限本人 owner。跨本人对话的图片复用使用显式图片引用和冻结来源，而工具输出继续按原任务、会话与目录严格取用。H2 使用实际 mapper XML 和实际附件字节验证该路径。

### 3.2 目录、纯问答和原生执行

- 固定个人运行目录与文件目录 readiness 分开；缺少文件目录可执行 nullable `directoryContext` 的 textOnly 问答，但中心与原生均拒绝工具、文件、命令、快照和 MCP 副作用，不能用私有运行目录替代授权文件目录。
- 实际 cwd 必须落在可信 owner 个人 files 根内，检查规范化/realpath、目录链、owner、Runner、目录版本和指纹；准备、证明、冻结均使用同一目录契约。默认目录是对话子目录，显式目录只能选择本人允许位置。
- 同物理 cwd 与重叠父子目录执行使用物理目录锁；会话 ID 不能代替实际文件锁。固定宿主运行锁限制重复宿主。Windows 命令的 REQUIRED 操作系统隔离仍确定性拒绝，不能以 `projectPath` 声称已形成命令沙箱。
- 原生 Agent 与三个既有 CLI renderer 保留；textOnly 也运行原 Agent。第一条输入等待 DIR_PREPARE 完成后转换到实际子目录，不要求用户先登记工作区、成员或 Runner 表单。

### 3.3 工具、结果和终端

- 修改文件先消费中心许可，再执行本地实际动作；许可冻结参数、资源哈希、策略、计划、目录、owner、凭据和 fencing token。旧租约的待定结果保留并核对，不盲重放副作用。
- 工具原始输出先保全，文件证据取实际修改前后 UTF-8 内容生成完整 diff；无法支持的证据给出原因，超过内联限额转完整产物与 SHA/size，不截断原结果或用模型回复冒充检查通过。
- 终端 START 冻结本人实际子目录，原生启动前核对顶层和目录对象指纹。快照授权按本人且绑定同宿主的 VERIFIED 目录，而非误将所有快照限制在宿主 home。此处已检查代码和离线帧，不代表已启动真实 PTY。
- 前端首条发送允许在目录准备 CONTROL 期间提交唯一 CODING 输入；发送模型、执行模式和可选目录保持同一入口。成果和检查显示来自实际工具回执、diff、exitCode；待配置、准备中、只读历史与执行中保留输入草稿。
