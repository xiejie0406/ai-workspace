## 1. 审查结论与证据边界

本次沿真实调用链核对了网页登录票据、Runner 设备身份、CLI 短期能力、原会话与关联任务范围、VT 回放与输入确认、浏览器图片、分页输出及导出下载。初次发现的六项问题及收尾发现的读取/控制作用域、事务消费、持久历史命名空间等问题已交实施者修复，并在收到源码冻结通知后逐项回读。最终所列问题已静态消除，本次审查范围内没有待修复的明确代码发现。不能据此声称端到端业务或安全场景已验证通过。

下列边界在所读源码中有明确实现：

- 浏览器只使用 30 秒单次 Redis 票据和精确 Origin；终端流拒绝平台 Authorization。Runner 沿既有专属 SecurityChain 使用 SESSION 设备凭证。CLI 使用 90 秒绑定终端/会话的短期能力，每次 RPC 检查原登录、账号状态、资源权限与设备撤销。
- 子 JVM 固定执行同一已打包 CLI 制品、固定 Java 路径和 TerminalChildMain；子环境不继承平台 JWT、设备凭证和 Provider 密钥。Windows 请求 ConPTY，返回类型不符时拒绝回退。
- 终端宿主独立于业务任务槽；输入使用 writerEpoch、inputSeq 和 ACK，浏览器不重发未知结果的按键。回放按完整 VT 序列恢复，浏览器 ACK 在 xterm write 回调完成后发出。
- 网页图片使用用户主动操作、待确认请求及中心私有 artifact 引用；提交前检查 owner、workspace/session、图片用途、大小和摘要。工作区文件图片经过 PathGuard；网页托管拒绝读取 Runner 宿主剪贴板。
- 工具长输出逐 UTF-8 字节分页，并校验完整摘要；导出分页固定截止，先补齐账本和集合再生成 Markdown/JSON。发布只接收固定文件格式，不接受 Runner 文件路径，网页经既有 artifact 下载权限获取原产物。

以上是代码路径事实，不是运行通过结论。Windows 原生库装载、ConPTY 实际输入/调整大小、三种 renderer、剪贴板权限、持续断网、登录与设备撤销、并发接管、事务回滚和文件 ACL 均未进行动态验证。

## 2. 初次审查发现

### 1. 跨工作区清理授权没有冻结实际对象（P1）

位置：`PcTerminalService.authorizationRequest`、`authorizeOperation`，以及原 `PcKnowledgeService.cleanAll`。

证据：请求只冻结 `operation=SNAPSHOT_CLEAN_ALL` 与字符串 `snapshot clean all`；确认时再调用原命令。原 `cleanAll` 此时重新枚举 `visibleWorkspaces` 和在线 Runner。用户看到请求后到点击批准期间工作区集合、Runner 或版本变化，会导致批准范围与执行登记范围不一致。原各任务仍有独立审批，这降低实际副作用风险，但不能补足网页这次授权对象不明确的问题。

建议：请求时记录并展示工作区/Runner 和版本清单；确认时核对清单未变化，只对被冻结对象登记任务，变化则拒绝旧请求并要求重新确认。

### 2. 中心发送可能让慢浏览器阻塞整个终端（P1）

位置：`PcTerminalService.send`、`pump`、广播调用，`PcTerminalWebSocketConfiguration.Stream`。

证据：`send` 在 `synchronized(socket)` 下直接 `socket.sendMessage`；`pump` 常同时持有 `synchronized(Terminal)`。没有专属发送时限或缓冲硬上限。浏览器停止接收可使发送阻塞，连带阻止该终端输入 ACK、短能力续期、停止和能力认证。

建议：采用有明确发送时限和总缓冲上限的异步发送通道；超限分离慢浏览器。仅包装并仍同步阻塞发送不能独立保证发送线程及时释放；必须核对实际 WebSocket 容器的写入行为。

### 3. 图片与授权请求记录无界增长（P1）

位置：`PcTerminalService.Terminal.attachments/authorizations`、`attachmentRequest`、`attachmentCancel`、`authorizationRequest/approvalAuthorization`、`expire`。

证据：只限制当前 PENDING 请求；已完成、失败、取消请求保留至整个终端移除。有效能力可以重复创建/取消请求，持续增加中心内存。终端最长八小时不等同于记录数量的硬边界。

建议：请求有效期、已结束记录保留数量、总记录硬上限同时具备；过期待办显式取消/拒绝，不能静默丢弃 READY 图片或进行中的授权。

### 4. 当天累计结束九个实例后 Runner 重连被拒（P1）

位置：`RunnerTerminalHost.onOpen/tick` 与 `PcTerminalService.reconcileHost`。

证据：Runner 报告 `terminals.values()` 全部实例，退出缓存只在创建满 24 小时后 purge；中心拒绝 `HOST_HELLO.terminals.size()>8`。当天累计创建并结束第九个实例后，下一次重连必然超限，活跃实例也无法恢复。

建议：只报告活跃及确需交代的结束实例；同时限制结束缓存数量与总字节，及时安全清理已交代实例，保留尚未交代的退出状态。不能单纯放宽中心列表上限。

### 5. 结束实例仍附着浏览器时中心 VT 缓存不释放（P1）

位置：`PcTerminalService.expire`。

证据：结束状态需 `lastActivity+600 秒` 且 `browsers.isEmpty()` 才移除；结束窗口保持 WebSocket 即可持续占用至多 16 MiB VT。活跃实例配额不计这些结束实例，可累计绕过 owner 总缓存限制。Runner 结束缓存同样应有总量边界。

建议：结束实例保留到期后关闭 WS 并释放中心内存，网页已渲染画面仍可保留；或设置 owner 总结束缓存数量/字节硬额度。

### 6. 中心托管丢失后详情缺 terminalId（P1）

位置：`PcTerminalService.detail` fallback 与 `useTerminal.open/connect/stop`。

证据：无内存实例时返回 `store.view(r)`，只有 `id` 而非 `terminalId`。前端按 PcTerminal 使用 `opened.terminalId` 请求票据/结束，形成 `/undefined/tickets`，阻碍结束旧实例后重开。

建议：fallback 归一化 terminalId、renderer、hostEpoch/writerEpoch 等字段，明确 LOST/托管丢失状态；提供可操作的显式清理，保留真实记录。若只改字段但仍以 DB RUNNING 状态要求不存在的内存实例发票据，恢复仍未完成。

| 发现 | 后续静态结果 | 依据 |
| --- | --- | --- |
| 跨工作区清理授权未冻结对象 | 已静态消除 | 新 `freezeSnapshotTargets` 固定工作区/Runner 清单、工作区版本与 Runner 安全配置 hash；`executeFrozenSnapshot` 先核对全部对象再对原清单登记任务。前端显示 `frozenTargets`，后续新增工作区不会加入旧请求。 |

新增的跨当前会话 `TASK_LOG/TASK_CANCEL` 网页授权已静态追踪：请求检查 owner 和当前 workspace、冻结 taskSessionId/taskVersion；确认重新检查权限、任务版本与归属，然后才加入关联任务集合。发现过 TASK_LOG 授权同时被控制路径接受的问题；后续改为读取路径使用 associatedTasks，外部 cancel/approval/plan 控制路径使用 generatedTasks 或重新进行网页单次授权，日志读取不授予控制权限。其并发状态变化与真实审批窗口未动态验证。

## 4. 收尾补充复核

- 授权待确认期间新增关联任务的竞态：确认时在同一 Terminal 锁下重新核对容量并预留批量 READY 目标数，创建并注册完成/失败后在 finally 释放；Gateway 创建事务使用 reservation、afterCommit 注册与 afterCompletion 释放。初次请求的容量检查不再是唯一检查点。
- 图片消费事务：冻结后回读确认，`consumeAttachments` 在外层事务 afterCommit 才写 CONSUMED；commit 失败保持 READY，避免任务未持久化时丢失批准图片请求。
- CLI 导出：网页累计记录预算 24 MiB，单文件 16 MiB、两文件合计 24 MiB，失败临时文件保留限 64 MiB/32 文件，并预留两文件名额。分页截止/进度发生变化或超限明确失败，不截断冒充完整。成功发布必须与本机两份文件的 name、SHA-256、size 全部匹配，再删除本次两个私有中间文件。磁盘故障与中心事务失败未动态验证。
- 持久输入历史：冻结后回读确认可信 START ownerId/workspaceId 与契约一致；历史目录按规范化 centerUrl 的 SHA-256、ownerId、workspaceId 分区，在工作区及单实例目录之外。私有锁文件、进程内锁和 FileLock 保护原子 read/trim/clear；默认 JLine 文件路径移除，save 不以旧内存覆盖共享磁盘。三个 Pattern 均使用 `(?is)` 覆盖跨行秘密/标志/base64，保留原 8000 字符过滤；JSON 记录读写 64 Ki 字符对称，10000 条/256 MiB 硬限。读取异常仅固定安全说明，原 JSON 不进入错误回显。实例 purge 不删除持久历史。曾怀疑长单记录破坏加载，继续追踪原 8000 字符过滤后撤回该判断；实施者仍补充了对称检查。

## 5. 最终结论与未验证项

此次独立审查覆盖实际中心—Runner—CLI—Vue 调用路径，最终静态结果支持继续交付候选代码与构建产物；没有由本次审查确认、尚未修复的明确缺陷。它不证明功能全集迁移已经运行通过，也不构成用户接受或发布决定。构建与能力全集核对分别由其既有记录承载，不能与这里的静态安全结论合并计数。

仍未动态验证的边界包括：

1. Windows ConPTY/native/JNA 加载、UTF-8/中文/IME、resize，inline/Lanterna/plain 完整交互。
2. 多窗口输入接管、断网时输入写入未知、输出重放与 DSR 抑制、慢网络写入/队列超限和退出缓存清理。
3. JWT 原登录撤销、角色权限变化、设备撤销、90 秒短能力续期与子 JVM watchdog。
4. 跨工作区目标/版本改变后拒绝旧授权，TASK_LOG 只读与 TASK_CANCEL 单次控制，真实事务提交失败后的 reservation/图片消费状态。
5. 浏览器主动剪贴板读写、图片失败/取消/模型切换、同一轮附件顺序与有效摘要，工作区文件路径和 Windows ACL。
6. 大账本分页、导出发布失败及摘要不符时保留原文件、原文件下载、私有中间文件清理与磁盘故障。
7. 同中心/不同中心、不同 owner/workspace 持久历史隔离；并发子进程 add/clear、文件锁中断与退出恢复。

本次未运行任何上述业务或产品测试，不把静态已消除写成动态“通过”。
