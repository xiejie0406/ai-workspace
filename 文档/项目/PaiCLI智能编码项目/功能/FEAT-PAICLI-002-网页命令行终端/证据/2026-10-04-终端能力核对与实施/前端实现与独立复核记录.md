## 1. 实际缺口与实现

核对前，编码工作台只有网页对话、会话记录、计划审批与图片上传，没有真实终端组件、原 CLI 输入/输出通道、打开/附着/接管/恢复流程。Vite 既有 `/dev-api` 同源代理已经支持 WebSocket，无需新增终端服务。

| 实际修改 | 内容 |
|---|---|
| `frontend/admin-web/src/views/paicli/workbench/index.vue` | 增加网页对话/网页终端/会话账本页内切换和“打开终端”；复用既有新建会话、计划、批准、取消、历史与原账本组件。会话ID作为终端组件key，切会话销毁旧网页对象，只分离原PTY。 |
| `frontend/admin-web/src/views/paicli/components/WebTerminalPane.vue` | 动态加载真实xterm/fit及CSS；三renderer、尺寸、状态、单写控制、快捷键菜单、复制与中断、中文输入法、多行粘贴确认。输出进入终端解析器，禁止OSC52自动写剪贴板，链接限制http/https且主动打开。 |
| `frontend/admin-web/src/views/paicli/useTerminal.ts` | 接入中心冻结REST/WS协议；同源票据子协议、完整VT回放、写入画面后ACK、有界重连。输入序号仅在socket.send成功后推进；ACK须为实际已发送范围内的正安全整数；未知按键不重发，INPUT_REJECTED停止输入。接管携带expectedWriterEpoch。 |
| `frontend/admin-web/src/api/paicli/terminals.ts`、`src/types/paicli-terminal.ts` | 复用若依request和原Envelope，保持终端专用类型。未修改并行Sub2API的connections页面、connections.ts或paicli.ts。 |
| `frontend/admin-web/src/views/paicli/components/ImageAttachments.vue` | 沿用已有图片准备、上传、预览；仅暴露复用方法、上传错误与明确放弃入口。终端默认沿原8张UI上限，不另建图片上传API。上传失败阻止继续输入，重试或明确放弃后继续。 |
| `frontend/admin-web/package.json`、`package-lock.json` | 精确锁定`@xterm/xterm`6.0.0和`@xterm/addon-fit`0.11.0；安装使用`--ignore-scripts --no-audit --no-fund`，仅增加这2项依赖。 |

浏览器粘贴/上传图片只在当前原输入追加` @clipboard `，不追加Enter。用户在原CLI提交该轮后，网页显示同requestId的图片请求并确认已上传引用；未重新读取剪贴板、未另发turn。`@clipboard`远程请求出现时只提供用户主动粘贴/上传入口。Ctrl+C明确直送原CLI，即使有选区或正在等待图片/授权也不改成复制。

网页承接中心的`AUTHORIZATION_REQUEST`，展示原冻结命令与影响；关联任务审批展示完整preview、版本、决定、反馈和拟改参数，再走原JWT确认。原`/export`的`EXPORT_READY`显示真实Markdown/JSON产物，用户点击既有下载API保存至浏览器；另外保留既有完整中心证据JSON导出入口。

## 3. 中心与Runner的独立静态复核

本执行者实施前端，未参与中心、Runner及CLI后端文件的编码。下面是对其他执行者实现的独立静态阅读，前端本身的自审不计为独立复核；主执行者已另行复核前端。

| 核对点 | 实际位置与结论 |
|---|---|
| 终端身份 | `PcTerminalSecurityConfiguration.TerminalFilter`对精确终端路径认证，拒绝平台Authorization，浏览器用一次性ticket子协议，CLI用短期能力；`PcTerminalWebSocketConfiguration.Handshake`分别核browserIdentity和原RunnerPrincipal。未发现匿名permitAll。 |
| 归属与单写 | `PcTerminalService.authorize/ticket/claim/browserFrame`核owner、原登录/权限/会话/设备；claim比较expectedWriterEpoch；每个写帧核host/writer版本。多窗口只能显式接管。 |
| 固定宿主与环境 | `PtyProcessManager.start`固定Java/JAR/TerminalChildMain、核制品hash和工作目录，白名单环境，私有home/tmp，能力一次文件；无用户Shell/任意argv。Windows返回类型必须ConPTY，不能静默winpty回退。 |
| 任务通道 | `RunnerTerminalHost`独立PTY托管/线程与命令队列；不占既有任务执行槽。该结构能避免长期终端任务占唯一槽的设计死锁，真实同机任务仍未操作验证。 |
| 输入写入不明 | 初次复核发现通用enqueue吞PTY输入写异常，可能出现未知输入/gap。已报告，Runner接收INPUT现专门失败处理，中心INPUT_REJECTED置inputUncertain/canWrite=false；前端停止输入而非重放。此为静态修正，非故障演练证据。 |
| 输出/恢复 | Runner保存完整VT顺序流、增量UTF8解码、有界背压；中心逐帧outputSeq与bytes分离，回放末尾后恢复写权。浏览器ACK只在xterm.write回调后发出，回放期间不把设备状态响应/输入送旧CLI。 |
| 能力边界 | `PcTerminalClientGateway.execute/commandScope/task`只枚举RPC并核绑定session与关联任务，不是任意URL代理。原跨工作区快照清理与关联任务审批通过明确JWT二次确认执行，CLI短期能力不直接升级跨scope。 |
| 冻结审批信息 | 初次复核发现publicAuthorization移除frozenInput后未展示REVISE新参数。已报告，中心现只公开decision/feedback/revisedArguments/inputHash及原preview，前端显示这些审核材料。原完整frozenInput未开放。 |
| 图片刷新与控制权 | 中心在REPLAY_END后重播PENDING图片请求，接管使旧requestId失效；附件归属与实际中心产物再核。浏览器没有权限/能力时保持失败与当前输入，不能静默提交纯文本。 |
| 实际导出 | `PcTerminalClientGateway.exportPublish`限定Markdown/JSON、绑定session/原导出权限，`PcArtifactService.publishSessionExport`保存中心私有产物，`PcTerminalService.exportReady`提交后通知并重播最近64产物；前端走原下载鉴权，不把Runner路径当下载链接。 |
| 停止范围 | Runner停止持有的PTY对象，私有清理核目录、所有者与无链接，不按任意PID终止。中心结束不隐式取消业务任务；用户另选取消时仍走已有任务取消API。 |

上级对前端另发现同工作区切会话旧图片异步回写风险，以及输入ACK/发送序号边界不足；本轮已按会话key隔离、限制ACK范围并仅在成功发送后推进序号。后续真实验收仍须核对这些路径，不能用编译成功替代。
