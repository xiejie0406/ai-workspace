## 1. 目标

文档按事实所有权归入若依框架、面试项目、智能选品项目、智能体桌面端项目和生产排产项目，避免依靠关键词、旧编号或临时执行窗口判断归属。当前事实与历史原文分开，同一状态只维护一处。

## 2. 标准目录

```text
文档/
├── README.md
├── 若依框架/
│   ├── README.md
│   └── README.md                     # 共享资料与项目集成入口
├── 项目/
│   ├── README.md
│   ├── 面试项目/
│   ├── 智能选品项目/
│   ├── 智能体桌面端项目/
│   └── 生产排产项目/
├── 开发记录/
├── 规范/
└── 归档/
```

每个项目按需使用以下职责目录，不为凑骨架创建空目录：

```text
项目名/
├── README.md
├── 原始需求/
├── 产品/
├── 调研/
├── 功能/
├── 架构/
├── 决策/
├── 原型/
├── 开发记录/
└── 归档/
```

`releases/` 只在产生真实发布批次时创建。业务工程、源码和可执行原型不属于 `文档/` 目录改名范围。

## 3. 分类和事实唯一归属

| 事实 | 唯一正文 | 其他位置允许内容 |
|---|---|---|
| 工作区工程边界与协作入口 | 根 `AGENTS.md`、根 `README.md` | 链接和局部说明 |
| 若依上游与共享工程导航 | `若依框架/` | 各项目只写自己的集成事实 |
| 项目范围与状态 | 对应项目 `README.md` | 工作区入口只做摘要 |
| 产品定位、范围、REQ / BR / AC | 对应项目 `产品/` 或 Feature 功能规格 | 摘要与上游链接 |
| Feature 当前阶段、阻塞、下游入口 | Feature `README.md` | 项目总览只读汇总 |
| 技术契约与设计取舍 | Feature `技术设计.md`；跨 Feature 设计放项目 `架构/` | 引用，不复制正文 |
| 可执行任务与授权包 | Feature `任务清单.md` | 开发记录只写实际差异 |
| 技术验证证据 | Feature `验证记录.md` 与 `证据/` | 控制页只汇总结论 |
| 用户验收决定 | Feature `验收记录.md` | Agent 不代签 |
| 已发生迁移与恢复方式 | 工作区或项目 `开发记录/` | 入口只链接 |
| 历史原文 | 对应项目 `归档/`；跨项目历史放根 `归档/` | 当前文档只说明替代关系 |

分类按文档主体和业务事实所有权判断，不按单个关键词判断。面试项目的若依接入仍归面试项目；智能选品项目中的 Python 智能体仍归智能选品；桌面端行业调研提到选品或排产也不自动改变归属。

状态冲突时不能自行挑一个写成真相；由对应 owner 在唯一正文统一，其他入口随后同步摘要。

## 4. Feature 资料包

目录名使用 `FEAT-<DOMAIN>-<NNN>-<中文语义>`；既有稳定 ID 可以保留，但必须带中文语义后缀。默认文件为：

```text
README.md          控制页：范围、阶段、状态、入口、授权与限制
功能规格.md        REQ / BR / AC；简单功能可并入 README
技术设计.md        数据、接口、状态、安全、兼容和恢复
任务清单.md        唯一任务源与验证范围
验证记录.md        实际技术验证
验收记录.md        用户或业务负责人验收
证据/              必要的机器输出、截图和报告
```

只创建有独立事实的文件。简单 L2 可以合并说明和设计；L0/L1 不为凑目录建立 Feature 包。不存在的任务或验证文件必须明确写“尚未创建”，不得使用失效链接或空文件冒充事实源。

## 5. 命名与元数据

- 文档根目录固定为 `文档/`；其下所有项目自有目录名必须包含清晰的中文语义。
- 除工具或生态约定的 `AGENTS.md`、`README.md`、`LICENSE*`，以及 OpenAPI、AsyncAPI、JSON 等机器可读契约或证据外，项目自有人读文档使用清晰中文文件名。
- 用户级验收规范固定的 `verification-report.html` 是该类 HTML 报告的精确文件名例外；其他人读文件仍按中文命名。
- 日期、版本、Feature ID 和必要的 API、AI、Agent、Python、RuoYi 等稳定标识可以保留；除稳定标识外，目录和文件名仍需包含中文语义。
- 原始 Word、PDF、HTML、Markdown 和纯文本等人读材料纳入中文命名要求；第三方原始文件可在确有追溯必要时保留原名并在入口解释。
- 时间线记录使用 `YYYY-MM-DD-<中文主题>.md`。
- 项目自有归档文件也使用中文名称，但不改写历史正文。
- 项目规范必须包含类型、版本、状态、owner、批准依据、日期和适用范围。
- Feature 控制页必须包含 Feature ID、风险、当前阶段或状态、owner、批准依据、关联产物和限制。
- 实际证据必须写明环境、动作、预期、实际、结果、时间和限制。

## 6. 当前与归档边界

满足任一条件即进入归档候选：描述已删除工程；被新的事实源明确替代；只服务已结束迁移；状态长期冻结且不再驱动任务；属于旧窗口提示词、旧阶段拆分或旧原型审计。

归档前必须列出源和目标、确认入链、保存未提交原文、说明语义变化和恢复方法。归档后保留原文，不批量篡改历史状态；只允许修复因移动产生的相对链接或增加归档说明。

归档内容不得重新成为当前执行规则。确需恢复时，应先把仍有效的事实提炼为新的当前文档，而不是直接复活整套旧计划。

## 7. 禁止模式

- 禁止同一 REQ、状态、任务或验证结论在多个文件双写。
- 禁止用“阶段完成”“报告存在”或“代码存在”替代验证或验收事实。
- 禁止按 Agent、窗口、波次或提示词建立新的长期状态目录。
- 禁止在当前目录保留指向已删除源码的可点击链接。
- 禁止把外部绝对路径作为唯一证据入口。
- 禁止把一个项目的数据、权限或模块边界写成若依共享规则。
- 禁止无映射、备份和恢复说明地批量移动、重命名、压缩或删除实质内容。

## 8. 维护检查

每次文档结构修改至少检查：

1. 根入口、`文档/` 与纳入范围的原型说明中的本地 Markdown、HTML 相对链接可以解析。
2. 当前文档以 `ruoyi-backend/`、`frontend/`、`miniapp/` 和 `python/` 为活跃工程入口；不把旧 `platform-backend/`、`backend/`、`apps/` 或迁移过渡期保留的根目录副本写成当前入口。
3. 五类入口齐全，四个项目目录互不混写当前事实。
4. 每个当前 Feature 最多只有一个控制页、任务事实源和验证事实源；缺少时如实说明。
5. 归档没有被当前规范或任务入口当成执行基线。
6. Git 差异中没有秘密、缓存、运行产物或无关用户修改。

仓库检查命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-docs.ps1
```

脚本检查目录骨架、中文命名、本地链接、已删除工程的可点击路径和旧当前目录；语义唯一性、状态真实性和批准边界仍需人工审查。
