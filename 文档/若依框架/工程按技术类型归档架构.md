## 1. 当前工程结构

| 目录 | 放什么 |
|---|---|
| `ruoyi-backend/` | 共享 Java / Maven 工程；`ruoyi-admin` 是 HTTP 装配入口，业务模块为 `ruoyi-interview`、`ruoyi-fashion`、`ruoyi-aden` 和 `aps/` |
| `frontend/` | `admin-web` 管理端、`portal-web` 面试门户、`desktop/aden-desktop` 桌面端，以及前端共享包 |
| `miniapp/` | `interview-mobile` 面试小程序 |
| `python/` | `fashion-ai-runtime`、`aden-agent-runtime`、`aden-runner`，各自保留依赖和运行入口 |
| `contracts/` | 跨语言 API 与事件契约；工程整理不改变契约字段或版本 |
| `prototype/` | 可运行原型；原型存在不代表生产功能已经实现 |
| `scripts/` | 跨工程构建、启动和检查脚本 |
| `文档/` | 共享框架及四个业务项目的资料 |

各工程的 `_reference/` 保存上游原文与许可，仅供对照，不进入活跃 Maven 或前端构建。新开发沿用上述目录，不把历史旧目录作为第二套活跃入口。

## 2. 项目、进程和数据边界

共享 Java 源码、构建和装配入口，不等于只能运行一个后端。当前并行环境运行四个独立 Java 实例，每个实例只开启对应业务模块；端口和启动命令统一见[启动指南](多项目并行开发启动指南.md)。模块开关与依赖要求见[Java 装配说明](Java业务模块统一装配.md)。

| 项目 | Java 模块 | 客户端或独立服务 | 数据与处理职责 |
|---|---|---|---|
| 面试 | `ruoyi-interview` | 门户、小程序；语音能力按功能配置 | PostgreSQL 持有面试业务；MySQL 持有平台账号，按稳定用户标识关联，不做跨库外键、关联查询或事务 |
| 智能选品 | `ruoyi-fashion` | 管理端、Python Runtime | Java / MySQL 持有正式商品、库存、价格、报价及写入；Python 提供计算，不直接拥有正式业务数据库 |
| 智能体桌面端 | `ruoyi-aden` | 本机安装版、Runner；Agent Runtime 按功能启用 | Java 是任务、审批和审计的中心；桌面与 Python 不维护第二套权威状态 |
| 生产排产 | `aps-api` 及相关模块 | 管理端、独立 `aps-worker` | API 与 Worker 按公共契约使用排产业务数据源；Worker 独立承担求解与原生库资源消耗 |

若依平台模块负责账号、认证、角色、菜单和权限。前端、桌面与 Python 仍需接口认证和权限校验；同一仓库不赋予跨项目权限。数据库迁移、真实模型与外部写入分别按所属项目的批准范围执行。

## 3. 旧新路径与恢复

| `platform-backend/ruoyi-ui/` | `frontend/_reference/ruoyi-ui/`，旧 UI 参考 |

迁移前未提交内容的历史备份位置为 `.codex-tmp/legacy-paths-20260925/`，实际保存与检查记录见[迁移记录](../开发记录/2026-09-25-工程按技术类型目录迁移.md#未提交内容与恢复)。恢复前先核对所需备份完整性，不能仅用 Git 提交代替未提交原文。

需要恢复工程目录时，按以下顺序处理；本次文档整理不执行这些工程操作：

1. 明确恢复版本和进程影响，保存迁移后新增或修改的文件，停止已确认从待恢复目录运行的进程。
2. 按上表反向恢复活跃工程和上游基线；逐项比较后再选择复制，不覆盖后续有效修改，不把两套同名模块混合。
3. 同步修正 Maven、脚本、CI、代理、工作区配置、公共包引用和文档链接。目录恢复不改变数据库、接口、鉴权或业务规则。
4. 完成下面的对应检查后再采用恢复目录。发现文件丢失、路径冲突或意外数据库、接口变化时，停止后续操作并保留原文。

原迁移要求的内部编号继续沿用，检查内容合并如下；历史执行结果只保留在原迁移记录中。

| 顺序 | 检查内容 | 应满足的条件 |
|---|---|---|
| 1 <!-- REQ-DIR-01 --> | Java 入口 | `ruoyi-backend/pom.xml` 管理平台及四业务模块，定向构建使用该入口；无第二套活跃 Java 聚合工程 |
| 2 <!-- REQ-DIR-02 --> | 网页和桌面 | 管理端、门户、桌面及共享前端包保留独立构建入口，代理和依赖解析正确 |

| 5 <!-- REQ-DIR-05 --> | 上游基线 | 原文和许可完整保留在 `_reference`，不进入活跃构建 |

检查结果分别记录源码与路径、构建、实际联机；文件存在或编译通过不能代替业务验收。原迁移不改数据库结构，新增数据库或公共接口变化须另行设计。
