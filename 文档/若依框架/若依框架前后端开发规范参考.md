## 3. 管理端路由、后台菜单与权限

### 3.1 授权菜单从哪里来

基线与当前主链路为：登录取得 token → `user.getInfo()` 获取角色与权限 → `getRouters()` 获取该用户菜单树 → permission store 将后台组件名转换为页面组件 → 路由守卫注册可访问路由 → Sidebar/TopNav/TopBar 渲染授权树。

实际入口：

- [路由守卫](../../frontend/admin-web/src/permission.js)处理登录、锁屏、角色信息加载和动态注册；[user store](../../frontend/admin-web/src/store/modules/user.js)持有 token、roles、permissions 等用户状态。
- [菜单 API](../../frontend/admin-web/src/api/menu.js)调用 `/getRouters`；[permission store](../../frontend/admin-web/src/store/modules/permission.js)生成 `routes`、`defaultRoutes`、`topbarRouters`、`sidebarRouters`。
- 后端 [SysLoginController](../../ruoyi-backend/ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysLoginController.java)从 `SecurityUtils.getUserId()` 查询菜单；[SysMenuServiceImpl](../../ruoyi-backend/ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysMenuServiceImpl.java)构造 RouterVo；[SysMenuMapper.xml](../../ruoyi-backend/ruoyi-system/src/main/resources/mapper/system/SysMenuMapper.xml)对普通用户关联 `sys_role_menu`、`sys_user_role`、角色状态和菜单状态。超级管理员有单独的全量菜单分支。

菜单类型 `M`（目录）、`C`（页面菜单）生成导航树；`F`（按钮）提供操作权限标识，不是可见页面路由。后台 `path`、`component`、`routeName`、`query`、`visible`、`isCache`、`isFrame`、`orderNum` 参与生成路由或显示；实际值由后台菜单与所属迁移/设计决定，本轮没有查询数据库中的现行菜单值。

**实施建议：**业务主页面通过后台菜单接入；`component` 应对应 `src/views` 下的实际文件，如 `fashion/product/index`，由 `import.meta.glob` 和 `loadView` 匹配，不包含 `src/views/` 前缀及 `.vue` 后缀。目录使用既有 `Layout`、`ParentView`，内链使用 `InnerLink`。菜单/角色写入仍需要明确数据操作授权，不能因新增页面就直接修改真实权限。

### 3.2 公共路由和隐藏业务路由

[router/index.js](../../frontend/admin-web/src/router/index.js)保留 `constantRoutes`（登录、错误页、首页等）与 `dynamicRoutes`（按 permissions/roles 过滤的隐藏详情和操作页）。`filterDynamicRoutes` 调用现有 `auth` 插件；permissions 数组为任一匹配，roles 为其后备分支，不能理解为两者自动同时满足。

路由字段应保留现有语义：`hidden` 控制菜单显示，`alwaysShow` 控制父项显示，`name` 必须与缓存/页签身份一致且唯一，`meta.title/icon` 控制标题图标，`noCache` 控制缓存，`activeMenu` 控制详情页菜单高亮，`breadcrumb` 控制面包屑，`affix` 控制固定页签。`hidden` 本身不构成后端授权。

当前已有面试管理入口写入 constantRoutes，选品工作区有 `/_fashion-workspace-*` 隐藏父路由和绝对 `/fashion/*` 子路径；这些是项目现状，不代表新业务都可照抄静态主菜单。本轮没有核对其全部批准历史，也没有验证与服务器下发路由的实际冲突。新页面先检查后台生成路由和现有名字/路径，避免两处注册同一业务主入口。

### 3.3 按钮与数据权限

管理端使用 [v-hasPermi](../../frontend/admin-web/src/directive/permission/hasPermi.js)、[v-hasRole](../../frontend/admin-web/src/directive/permission/hasRole.js)和 [auth 插件](../../frontend/admin-web/src/plugins/auth.js)。已有通配权限 `*:*:*` 和管理员角色语义；条件渲染可使用现有 `hasPermi/hasPermiOr/hasPermiAnd`，不能另维护权限状态副本。

前端隐藏/禁用只负责界面表现，后端仍必须使用对应 `@PreAuthorize("@ss.hasPermi('模块:资源:动作')")` 或已批准业务权限适配器。权限点应在菜单按钮、前端和 Controller 保持一致。平台 [SysUserController](../../ruoyi-backend/ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysUserController.java)还会调用数据范围校验；[SysUserServiceImpl](../../ruoyi-backend/ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysUserServiceImpl.java)采用 `@DataScope`。功能权限不能代替资源归属/租户/部门数据权限；不能把平台部门过滤原封不动套到业务自有租户模型。

## 5. 前端状态、组件、请求与字段

### 5.1 状态和公共能力

[store/index.js](../../frontend/admin-web/src/store/index.js)创建 Pinia。用户身份沿用 user；路由权限沿用 permission；设备/侧栏沿用 app；布局偏好沿用 settings；页签缓存沿用 tagsView；字典缓存沿用 dict；锁屏沿用 lock。业务临时编辑状态可留在页面或所属业务 store，不能复制用户权限、全局导航或服务端正式业务状态成为第二套真相。

[main.js](../../frontend/admin-web/src/main.js)已注册 Pagination、RightToolbar、DictTag、Editor、FileUpload、ImageUpload、ImagePreview、SvgIcon，挂载 useDict、download、parseTime、resetForm、handleTree、addDateRange 等工具；[plugins/index.js](../../frontend/admin-web/src/plugins/index.js)提供 auth、cache、modal、tab 等入口。开发先看这些组件的 props/events，而不是只凭名称另造一套。

[Vite 配置](../../frontend/admin-web/vite.config.js)设置 `@` 到 src，支持 js/ts/vue 扩展，代理 `/dev-api` 与 `/api/v1`；[自动导入](../../frontend/admin-web/vite/plugins/auto-import.js)导入 Vue、Router、Pinia 和部分工具，但 `dts: false`。局部 TypeScript 应按实际声明文件和 tsconfig 处理类型，不能假定整个管理端自动类型完备。

### 5.2 API 与错误

[utils/request.js](../../frontend/admin-web/src/utils/request.js)是管理端已有 Axios 实例：采用 `VITE_APP_BASE_API`、10 秒默认超时、Bearer token、GET 查询序列化、POST/PUT 重复提交检查、code 错误分支、过期会话处理及二进制下载。它成功时返回 `res.data`（完整业务信封），不是 AxiosResponse；常规 API 模块只传 url/method/params/data。

重复提交防护是短时浏览器防护，不能代替服务端幂等；`isToken:false`、`repeatSubmit:false` 或自定义 timeout 是现有可选控制，不应当作绕过安全的默认选项。当前托管密钥请求跳过 sessionStorage 正文缓存，是项目对敏感请求的适配，不授权普通业务关闭所有防重复提交。

本项目已有 [fashion/client.ts](../../frontend/admin-web/src/api/fashion/client.ts)：仍调用共享 request，补充 `/fashion` 路径校验、业务错误信息、`X-Correlation-ID`、`Idempotency-Key`、`If-Match`、取消信号等。它是业务协议适配，不是独立 token/网络基础设施。[structuredBusinessError.ts](../../frontend/admin-web/src/utils/structuredBusinessError.ts)在显式 `preserveBusinessError` 时保留 HTTP 200 业务失败的原始响应；未选择的调用保持旧 fallback。不能因禁止平行实现而直接删掉这些已被消费者使用的适配，也不能重新 new Axios 绕过共享登录/错误处理。

处理接口应分清 HTTP 状态、若依数字 code、业务 errorCode、response.data 与业务 data；列表和详情不能按名称猜返回结构。现有拦截器会统一提示错误，页面额外提示应避免重复；结构化错误改动要核对所有消费者和原有兼容行为。

### 5.3 字典、分页、表格和字段

| 字典 | [useDict](../../frontend/admin-web/src/utils/dict.js) → `/system/dict/data/type/<type>` → dict store；[DictTag](../../frontend/admin-web/src/components/DictTag/index.vue)显示标签 | 平台动态字典沿用该链路；业务已有版本化枚举按契约，不把全部枚举强改为 sys_dict，也不硬编码平台字典副本 |
| 分页 | [Pagination](../../frontend/admin-web/src/components/Pagination/index.vue)接 total、page、limit，发 update:page、update:limit、pagination | 若依标准列表用 pageNum/pageSize 与顶层 rows/total；改变检索条件回到第一页。选品已存在 page/pageSize 与 AjaxResult.data 内业务页对象，应按端点契约做适配 |
| 搜索/列工具 | [RightToolbar](../../frontend/admin-web/src/components/RightToolbar/index.vue)提供 showSearch、queryTable、columns、storageKey | 复用搜索、刷新与列显隐；持久化 key 应按页面隔离，不能照抄示例 `xxxxxxxx` 造成冲突。没有列显隐需求时无需为了形式添加 |
| 表格/表单 | [用户页面实例](../../frontend/admin-web/src/views/system/user/index.vue)采用 el-form、el-table、加载状态、选择项、规则校验、DictTag 和操作权限 | 常规后台 CRUD 优先沿用这一模式；字段、列顺序、必填和业务动作仍来自所属业务设计，不照抄平台用户字段 |
| 时间/树/范围 | [ruoyi 工具](../../frontend/admin-web/src/utils/ruoyi.js)提供 parseTime、handleTree、addDateRange、resetForm | 核对字段类型和时区；不能把所有服务返回时间当成本地 Date 或自行推算业务日期 |
| 字段边界 | DTO、后端校验、数据库约束和 [选品类型](../../frontend/admin-web/src/api/fashion/types.ts)共同定义实际映射 | 64 位业务 ID 的前端字符串、金额/币种、版本并发、枚举与空值按已有协议；不把 long 盲转 JavaScript number，不由页面自定数据含义 |

共享组件样式修改应收敛影响范围；普通业务页优先用自身组件和局部样式。设计确需改变共享表格或布局行为时，须核对其他项目消费者并按第 9 节判断冲突。

## 6. 后端分层、响应、校验与审计

### 6.1 平台已有分层

平台示例为 [SysUserController](../../ruoyi-backend/ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysUserController.java) → [ISysUserService](../../ruoyi-backend/ruoyi-system/src/main/java/com/ruoyi/system/service/ISysUserService.java) / [SysUserServiceImpl](../../ruoyi-backend/ruoyi-system/src/main/java/com/ruoyi/system/service/impl/SysUserServiceImpl.java) → [SysUserMapper](../../ruoyi-backend/ruoyi-system/src/main/java/com/ruoyi/system/mapper/SysUserMapper.java) / [Mapper XML](../../ruoyi-backend/ruoyi-system/src/main/resources/mapper/system/SysUserMapper.xml)。Controller 处理 HTTP、权限、输入和输出，Service 维护规则/事务，Mapper 承载 SQL。平台实体沿用 [BaseEntity](../../ruoyi-backend/ruoyi-common/src/main/java/com/ruoyi/common/core/domain/BaseEntity.java)的审计字段与 params。

[生成模板](../../ruoyi-backend/ruoyi-generator/src/main/resources/vm/)提供 Controller、Service、Mapper、SQL、Vue 3 和 API 的常规 CRUD 示例。它们是复用入口，不等于业务模块必须生成整套 Service 接口或把全部领域对象继承 BaseEntity。当前四业务模块已有 application/domain/infrastructure 分层；保留其设计边界，不为“像若依”把逻辑挪入 Controller 或重造平台模块。

### 6.2 响应与分页

- [AjaxResult](../../ruoyi-backend/ruoyi-common/src/main/java/com/ruoyi/common/core/domain/AjaxResult.java)使用 `code/msg/data`，success 为 200；也支持额外顶层字段，不能要求所有接口 data 都存在。
- [BaseController](../../ruoyi-backend/ruoyi-common/src/main/java/com/ruoyi/common/core/controller/BaseController.java)提供 success/error/toAjax、当前用户、分页和日期绑定；toAjax(int)将影响行数大于零判为成功，复杂业务不能照搬影响行数作为完成断言。
- [TableSupport](../../ruoyi-backend/ruoyi-common/src/main/java/com/ruoyi/common/core/page/TableSupport.java)读取 pageNum/pageSize/orderByColumn/isAsc；`startPage()` 在 MyBatis 查询前调用，`getDataTable` 返回 [TableDataInfo](../../ruoyi-backend/ruoyi-common/src/main/java/com/ruoyi/common/core/page/TableDataInfo.java)的顶层 rows/total/code/msg。排序沿用已有校验，不拼接未校验请求字段。
- [FashionProductController](../../ruoyi-backend/ruoyi-fashion/src/main/java/com/ruoyi/fashion/controller/rest/product/FashionProductController.java)沿用 BaseController、AjaxResult、@ss 和 @Log，但其列表返回 `success(service.search(...page,pageSize...))`；这是业务分页协议，不能让前端按平台顶层 rows 读取，也不能对 JDBC 查询机械调用 PageHelper。

### 6.3 权限、校验、异常、日志

[SecurityConfig](../../ruoyi-backend/ruoyi-framework/src/main/java/com/ruoyi/framework/config/SecurityConfig.java)开启方法权限、无状态认证、JWT 与 CORS 过滤器，未放行请求需要认证；[PermissionService](../../ruoyi-backend/ruoyi-framework/src/main/java/com/ruoyi/framework/web/service/PermissionService.java)以 Bean `ss` 实现权限和角色校验。扩展公开接口必须说明其认证及滥用边界，不能为了调用方便扩大 permitAll 或删除 @PreAuthorize。登录成功不能替代业务权限、数据范围或资源归属校验。

平台 Controller 使用 `@Validated @RequestBody`，实体使用 Jakarta 校验，Service 继续核查唯一性、操作合法性和数据范围；选品服务另有确定性业务校验。前端校验不能代替这些后端校验。

[GlobalExceptionHandler](../../ruoyi-backend/ruoyi-framework/src/main/java/com/ruoyi/framework/web/exception/GlobalExceptionHandler.java)把 ServiceException、参数/校验、权限和未知异常映射成 AjaxResult；其中未知异常分支当前会采用异常消息，这只是现状，不能据此批准对外泄露内部错误。已存在的专用协议不能一律改成 HTTP 200 + AjaxResult：

| 项目 | 已有边界与入口 | 开发注意 |
|---|---|---|
| 面试 | [ApiErrorHandler](../../ruoyi-backend/ruoyi-interview/src/main/java/com/ruoyi/interview/controller/rest/common/ApiErrorHandler.java)、[ApiErrorResponseWriter](../../ruoyi-backend/ruoyi-interview/src/main/java/com/ruoyi/interview/controller/rest/common/ApiErrorResponseWriter.java)；限定包 advice 与过滤阶段错误信封 | 与门户/语音协议关联；不能从管理端 Bearer 模式推定所有面试客户端认证相同 |
| Aden | [AdenApiExceptionHandler](../../ruoyi-backend/ruoyi-aden/src/main/java/com/ruoyi/aden/api/common/AdenApiExceptionHandler.java)使用状态、errorCode、correlationId 等信息 | 保留桌面、Runner 消费者和并发恢复语义 |
| 排产 | [ApsApiExceptionHandler](../../ruoyi-backend/aps/aps-api/src/main/java/com/ruoyi/aps/api/error/ApsApiExceptionHandler.java)使用 ApsProblem 与 HTTP 状态 | 这是该项目已存在的协议适配，不把它扩成共享平台第二套全局错误机制 |

[Log 注解](../../ruoyi-backend/ruoyi-common/src/main/java/com/ruoyi/common/annotation/Log.java)及 [LogAspect](../../ruoyi-backend/ruoyi-framework/src/main/java/com/ruoyi/framework/aspectj/LogAspect.java)记录操作人、业务类型、请求/结果和异常，并异步持久化平台操作日志。框架已有默认排除密码字段，但不等于覆盖所有业务秘密；敏感正文需使用已有不记录/排除字段设置。平台操作日志与业务必须落库的审计事件职责不同；既有业务审计不因加了 @Log 就可删除。

## 7. 模块装配、数据源、迁移与事务

### 7.1 装配与配置

父 POM 的 `<modules>` 和 dependencyManagement 不会独自完成 Spring 注册；admin 的依赖、组件扫描、业务开关、Mapper/Bean 装配及数据配置都需匹配。[ApplicationConfig](../../ruoyi-backend/ruoyi-framework/src/main/java/com/ruoyi/framework/config/ApplicationConfig.java)当前只扫描平台 system/quartz/generator 的 Mapper，并绑定 `sqlSessionFactory`；它与基线的广域 Mapper 扫描不同。业务自有 Mapper 不应无依据塞进平台扫描。

[MyBatisConfig](../../ruoyi-backend/ruoyi-framework/src/main/java/com/ruoyi/framework/config/MyBatisConfig.java)构造平台 SqlSessionFactory；[DruidConfig](../../ruoyi-backend/ruoyi-framework/src/main/java/com/ruoyi/framework/config/DruidConfig.java)维护 dynamicDataSource。业务模块沿用自己的条件装配和显式 Qualifier，防止新增 Bean 改变其他模块注入。

[application.yml](../../ruoyi-backend/ruoyi-admin/src/main/resources/application.yml)及 local/test/aps/druid profile 分开维护配置。`interview/fashion/aden/aps.enabled` 总开关与 Flyway、Provider、Worker 等副作用开关不能混同。部分 Worker 已有不同默认值，必须按实际配置与启动指南核实，不能把“开启模块”理解成所有外部能力已授权运行。

当前 [RuoYiApplication](../../ruoyi-backend/ruoyi-admin/src/main/java/com/ruoyi/RuoYiApplication.java)还集成托管密钥安装及专用 CLI/Runtime 分支，这是项目定制，不是普通若依的自动保证。凭据用途和真实环境不能写入页面状态或复制到新配置；运维只沿用 [run-local.ps1](../../ruoyi-backend/bin/run-local.ps1)及项目启动入口的已批准范围，本轮未运行启动/初始化参数。

### 7.2 数据与迁移分工

| 范围 | 实际持久化入口 | 迁移与恢复边界 |
|---|---|---|

| 选品 | [FashionPersistenceConfiguration](../../ruoyi-backend/ruoyi-fashion/src/main/java/com/ruoyi/fashion/configuration/persistence/FashionPersistenceConfiguration.java)显式把 JDBC、fashionTransactionManager/Template 绑定 dynamicDataSource | [FashionMigrationConfiguration](../../ruoyi-backend/ruoyi-fashion/src/main/java/com/ruoyi/fashion/configuration/persistence/FashionMigrationConfiguration.java)须显式启用；首次 history baseline 另需批准开关。[FashionFlywayFactory](../../ruoyi-backend/ruoyi-fashion/src/main/java/com/ruoyi/fashion/configuration/persistence/FashionFlywayFactory.java)固定 `db/fashion-migration` 和独立 history，禁止 clean、禁止自动猜 baseline |
| 面试 | [InterviewInfrastructureConfiguration](../../ruoyi-backend/ruoyi-interview/src/main/java/com/ruoyi/interview/configuration/InterviewInfrastructureConfiguration.java)绑定 PostgreSQL interviewDataSource、interviewTransactionManager/JDBC | [InterviewFlywayConfiguration](../../ruoyi-backend/ruoyi-interview/src/main/java/com/ruoyi/interview/configuration/InterviewFlywayConfiguration.java)仅在显式启用时使用 platform schema 与 db/migration；其 baselineOnMigrate/version 是已有面试设置，不推广到别的项目 |

上述是代码装配边界，不是本轮数据库实际连接核验。当前各通道仍必须沿用所属项目原库、账号、托管密钥和业务数据；具体连接以启动指南及对应项目核实记录为准。面试 PostgreSQL 与平台 MySQL 以稳定用户标识关联，不做跨库 JOIN、外键或事务；选品 Java/MySQL 持有正式商品、库存、价格、报价和写入，Python 不成为第二业务库 owner。

### 7.3 事务和并发

平台服务已有 `@Transactional`；多数据源业务需沿用明确的事务管理器。[FashionProductService](../../ruoyi-backend/ruoyi-fashion/src/main/java/com/ruoyi/fashion/application/product/FashionProductService.java)使用 fashionTransactionTemplate 和已有目录写锁、rowVersion；[AdenTaskTransactionService](../../ruoyi-backend/ruoyi-aden/src/main/java/com/ruoyi/aden/application/task/AdenTaskTransactionService.java)显式指定 adenTransactionManager；APS 在数据源配置中创建专有事务适配。不能因为都在同一 JVM 就使用未限定默认事务、宣称跨模块/跨库原子提交。

迁移前应核对原库、schema、history 表、已执行版本、消费者兼容、备份与恢复以及明确写入授权；不得通过重写已应用脚本、clean、换空库或降低守卫掩盖失败。当前选品目录有 V4 脚本，而 Factory 的 EXPECTED_VERSION 仍为 3，这是源码版本需要在原任务中核对的点；脚本存在不能证明已迁移，也不能由本轮文档任务执行或改写迁移配置。
