**端口含义：**旧项目列的是已有启动定义；React 开发端口列的是源码配置，不表示进程已运行、已登录或代理已连接正确后端。未登记项目首次启动先查所属实施记录、原配置和现有进程，已有通道则沿用；确无通道时选未占用端口并登记，不能把前端默认代理 `8081` 当作已经核实的项目后端。

**共享什么、分别运行什么：**

- 每个正在调试的项目有自己的 Java／内置 Tomcat 和前端或客户端。若依登录、权限、菜单和公共基础保留，只开启当前业务及其必要依赖；不直接运行业务库模块代替 `ruoyi-admin`。
- MySQL、PostgreSQL、Redis、对象服务、第三方连接、账号、密钥及已准备的依赖环境直接复用。不得按项目或对话创建、克隆、初始化数据库，另起 Redis，复制凭据或重装依赖。数据库仍遵循各业务原有所有权，共享服务不等于合并业务数据。
- Redis 使用同一个已核实的现有连接，保留原认证及必要的业务键规则。旧 `16391～16394` 不再作为“每项目必须启动一个 Redis”的要求；本轮未指定新连接，也未停止、删除这些旧进程或数据。共享地址尚未核实时，只阻塞依赖该连接的启动，不猜测 `6379`。
- 必要 Worker、Runner、Python 业务进程按功能运行，已有正确实例先复用；这不授权复制底层运行环境。原私有上传、语音、索引和产物目录沿用，不因端口改变而改到空目录。
- 后端启动参数按进程传入，不反复改公共 `.env` 来切换项目。关闭总开关时还须核对后台任务、专用数据源及子功能；当前 `aden.collection.enabled` 等独立子开关不能只凭总开关推断已关闭。菜单按既有若依权限生成，后台关闭不保证菜单自动隐藏。

## 2. 各项目怎样启动

### 2.1 所有项目共用的启动步骤

1. **找项目。**在第 1 章找到对应项目，进入所属控制页或实施记录，核实原配置文件、正确运行包和当前进程。配置只读取本项目需要的项，不打印数据库口令、服务 Token 或供应商 Key。
2. **检查已有环境。**核对原库及必要表、共享 Redis、密钥用途、原存储目录和本机依赖。已有且地址、版本、身份正确的业务进程复用；缺项明确说明，不自动建表、初始化账号或创建替代配置。
3. **准备运行包。**日常恢复优先用本项目已登记的固定包；源码更新则按第 3 章构建，核对包内包含当前模块，保存为本项目固定版本并登记哈希。当前 POM 仍包含多个业务，不存在已实现的按项目 Maven Profile。
4. **启动自己的后端。**监听本项目端口，沿用原数据、托管密钥及共享 Redis 配置；显式关闭九个业务，再只开启当前一个，并核对该业务必要子开关。不把其他对话进程中的配置默认视为自己的原配置。
5. **启动配套和前端。**完整开发环境运行当前业务所需服务，前端明确代理到本项目后端；只开发普通页面等缩小范围时，应由本次任务明确，不能擅自关闭语音、AI 或求解后仍称完整环境。
6. **核对并打开。**检查实际监听进程、固定运行包、业务接口、前端代理和配套心跳／健康状态，再打开浏览器或安装版。只说明启动范围与缺项，不把验证码 HTTP 200、构建成功当作业务通过。

**脚本现状：**[旧四项目启动脚本](../../scripts/dev/start-four-projects.ps1)会新启动各通道 Redis，且只显式切换旧四个业务；[旧停止脚本](../../scripts/dev/stop-four-projects.ps1)也会停止项目名下 Redis。二者当前不符合本指南，不能作为新的默认启动／停止命令。尚无通用九项目脚本；本次仅修改文档，执行者应依下述参数和原配置核实后启动，不能假称 `start-projects.ps1` 已存在。

后端选择示例（排产；**参数示意，不是无需准备即可复制执行的脚本**）：先由执行者核实固定包、共享 Redis 连接、原配置的注入方法和必要子开关，再把参数交给既有 Java 启动方式。仅打开一个总开关不保证原配置已经齐备。

```powershell
$project = 'aps'
$backendPort = 18094
$backendJar = '<本项目已核实的固定运行包绝对路径>'
$businesses = @('interview','fashion','aipicture','aden','aippt','paismart','paiflow','paicli','aps')
$moduleArgs = foreach ($business in $businesses) {
    '--{0}.enabled={1}' -f $business, ($business -eq $project).ToString().ToLowerInvariant()
}
$javaArgs = @('-Xms128m','-Xmx768m','-jar',$backendJar,
    '--server.address=127.0.0.1',"--server.port=$backendPort",
    '--spring.profiles.active=druid,local') + $moduleArgs
# 在本项目启动进程中补入已核实的共享 Redis 连接、日志和必要子开关参数。
# 后台派发用 Start-Process -WindowStyle Hidden，并登记 PID、创建时间、包哈希和日志。
# 本段不加载秘密、不创建配置、不启动数据库或 Redis。
```

普通若依管理端前端使用下面的现有入口，变量必须先按第 1 章填入实际值。共享 `admin-web` 的多个前端实例设置各自 Vite 缓存路径；缓存、日志和固定包分别记录，不是复制一套基础服务。

```powershell
# 在工作区根目录执行；$backendPort、$frontendPort、$project 已核实并填写。
$env:ADMIN_DEV_BACKEND_URL = "http://127.0.0.1:$backendPort"
$env:PROJECT_VITE_CACHE_DIR = Join-Path (Get-Location) ".runtime/$project/vite-cache"
npm --prefix frontend/admin-web run dev -- --host 127.0.0.1 --port $frontendPort --strictPort
```

## 3. 并行开发、更新和停止

**排产与选品同时开发的顺序：**先核实并复用共享数据库、Redis及原配置；排产对话运行 `18094＋15175＋必要 Worker`，选品对话运行 `18092＋15174＋必要 Runtime`。各后端只开启自己业务，前端只连接自己后端。二者共享基础服务，但不互相改变对方的业务配置或数据规则。

| 改了什么 | 怎样生效；怎样避免影响其他项目 |
|---|---|
| Java 业务代码 | 执行对应模块的必要测试，排队构建共享 `ruoyi-admin`，固定新包路径和哈希；只更新、重启自己的 Java。当前可用构建入口为 `mvn -f ruoyi-backend/pom.xml -pl ruoyi-admin -am package`，不是按单业务裁剪；先确认检查范围，不用另一对话的新包自动替换当前实例 |
| 排产 Worker | 对应检查与构建入口 `mvn -f ruoyi-backend/pom.xml -pl aps/aps-worker -am package`；固定 Worker 包，只重启本项目 Worker，保留其他业务进程 |
| Vue／React 页面 | 查看自己的入口；代理或环境变量变化则重启自己的前端。图片／演示文稿嵌入产物按第 2 章同步；共享管理端的公共修改核对受影响项目 |
| Python／Runner／其他 Worker | 使用原解释器和配置完成对应检查，只重启归属明确的业务进程；原模型进程正确且已预热时复用，不重新复制环境 |
| Aden 桌面 | 退出属于目标安装目录的窗口，在 `frontend/desktop/aden-desktop` 执行 `npm run sync:local`，完成构建、备份、同步及哈希核对，再打开安装版；扩展、Native Host、安装器按各自分发范围处理 |
| 公共若依设施或数据库结构 | 协调受影响项目和必要检查；不由不同对话同时覆盖公共文件，不在共享目录切换分支。启动环境不自动扩大为表迁移、发布或 Git 写操作 |

**停止方法：**先依据本项目运行清单核对 PID、创建时间、完整命令和包／解释器路径，确认属于本项目后才定向停止；不能按端口、进程名扫杀所有 Java、Node、Python。共享数据库、Redis和第三方基础服务保留；旧四项目停止脚本在排除 Redis 之前不得直接使用。图片专用停止入口见[脚本](../../scripts/aipicture/停止图片本地通道.ps1)，同样须核对其当前身份范围；安装版窗口按其实际目录归属关闭。

**每次启动后只需简短汇报：**项目和实际分支；已复用／新启动的业务进程与包版本；开启业务和关闭业务；共享基础连接的非秘密地址；可打开的页面／客户端；未就绪配套及影响。把新的配置位置、通道端口、包哈希和进程身份登记到项目已有运行清单或唯一实施记录，不另建按对话划分的长期状态文档。

**新增项目：**在第 1 章增加项目与入口，在第 2 章增加真实目录、原配置、命令、配套和检查；复用既有基础环境。已有记录缺失就地说明，首次启动核实后更新同一入口；不把示例端口、离线夹具或尚未存在的启动脚本写成已就绪环境。
