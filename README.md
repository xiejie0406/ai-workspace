> 文档类型：工作区入口
> 文档状态：Draft
> 更新时间：2026-10-03

## 当前工程

| 目录 | 职责 |
|---|---|
| `ruoyi-backend/` | 活跃的若依 Java / Maven 主工程；聚合九个业务项目的 Java 模块，装配方式见[统一启动说明](文档/若依框架/Java业务模块统一装配.md) |
| `frontend/` | Web 与桌面前端：`admin-web/`、`portal-web/`、`desktop/aden-desktop/`，以及前端共享包 |
| `miniapp/` | 面试小程序 `interview-mobile/` |
| `python/` | 智能选品 AI Runtime、Aden Agent Runtime 和 Runner，各自独立运行 |
| `contracts/` | 共享机器契约；具体所有权由子目录和项目文档说明 |
| `prototype/` | 各项目可运行原型；它是工程资产，不是当前需求或验证的默认事实源 |
| 各工程内的 `_reference/` | 若依上游基线，供对照使用，不参与活跃工程构建和部署 |
| `文档/` | 共享规范、项目导航、项目事实、迁移记录和历史归档 |

本次按技术类型整理的[目录映射与恢复说明](文档/若依框架/工程按技术类型归档架构.md#3-旧新路径与恢复)记录旧新路径与恢复方式。迁移过渡期仍可能保留旧根目录供运行中的进程使用；新开发以表中目录为入口，不将这些旧副本作为第二套活跃工程。

## 当前边界

- 面试项目以若依账号、JWT、菜单和权限为平台事实，以 PostgreSQL 保存面试业务事实。
- 智能选品项目以 Java / MySQL 保存正式业务事实，Python 只返回结构化智能候选；当前生产 Feature 仍在开发和验证阶段。
- 智能体桌面端项目以若依作为唯一中心控制面，桌面端和 Runner 不形成第二套业务真相；真实账号、采集和外部发送仍未授权。
- 生产排产 API 由共享若依装配，求解 Worker 在同一 Maven 工程中独立运行；具体实现、验证与 UAT 状态以[项目控制页](文档/项目/生产排产项目/README.md)为准。

各项目更细的状态只从项目控制页、Feature 控制页和验证记录读取，不能根据文件或代码存在推断。

## 面试项目本地入口

- 多项目开发按[启动指南](文档/若依框架/多项目并行开发启动指南.md)选择当前业务，复用已有数据库和 Redis；业务开关按实例传入，不反复修改公共 `.env` 或在启动时初始化 schema。
- 后端：`ruoyi-backend/bin/run-local.ps1`，默认端口 `8081`
- 管理端：在 `frontend/admin-web/` 执行 `npm run dev -- --host 127.0.0.1`，默认端口 `5173`
- 用户端：在 `frontend/portal-web/` 执行 `npm run dev -- --host 127.0.0.1`，默认端口 `5174`

这些命令只说明现有本地入口，不代表当前环境、数据库、Provider 或完整业务链路已经验证通过。
